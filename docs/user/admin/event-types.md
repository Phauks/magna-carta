# Event types

Every setting on a calendar is classified under an **event type**: Hearing, Deposition, Filing,
Mediation, and so on. The type is what the firm-wide calendar shows for a setting, because a
calendar that spans every matter shows what kind of thing is happening and not what the case is
about. Under **Settings › Practice › Event Types** an administrator keeps that vocabulary.

## Two kinds of type

**The platform's own.** A set of types ships with the platform and is shared by every firm. Their
names and codes are the shared vocabulary and stay as they are: a firm can **recategorize** one
(litigation, transaction, firm, other) and can **retire** one it does not use, but never rename it.

**The firm's own.** A practice with a proceeding nobody thought of adds a type of its own: a name,
an optional short code in capitals that the firm-wide calendar paints from, and a category. A
firm's own type can be renamed or recategorized later.

## Retiring is one way

Retire asks first, because it is one way. A retired type keeps its meaning on every event already classified under it and simply stops
being offered for new ones. Nothing brings a retired type back; a word the firm wants again is
added again as the firm's own. That is deliberate: a type that could flicker on and off would make
the calendar's vocabulary a moving target.

## Who can change it

A member who can manage the calendar. Everyone else reads the catalog as a plain table.
