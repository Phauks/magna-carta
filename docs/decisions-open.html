ShippedBuilt · no screen yetdocuments.pdf.scrub

PDF document scrub

Whether the scrub should also strip a PDF's executable content, which today it leaves entirely intact — the document-level JavaScript name tree, the action that fires when the file is opened, the catalog actions that fire on save, print and close, the additional-actions on pages and on form fields, and the action attached to any annotation. A document produced to an opposing party can therefore still carry code, from the step whose whole purpose is that it does not. This is not a hypothetical path: prepareFormTemplateVersion in apps/worker/src/assemblies/pdf-form-engine.ts runs the scrub on every PDF form template a firm registers, so whichever way this is answered changes something already running. What stands in the way today is the malware scan every uploaded byte crosses, which is a different guarantee: it catches what is known to be hostile, not what is merely executable. Stripping is not free, and the cost falls on fillable forms a FIRM uploaded — a court form still uses field actions for validation and formatting, so a scrub that removes them hands back a form that looks right and computes nothing. Three ways to answer. Strip always, and accept that. Strip with an exception a firm marks at upload for forms it needs to keep working, which puts the choice on the person who knows what the form is for and has to be recorded so a recipient cannot forge it. Or report the active content without removing it, and let whoever is producing the document decide per file. Note that an exception keyed on "templates the platform authored" would exempt nothing today: every fillable template in the tree is a firm upload, and whether the platform ever authors its own is itself unanswered on document-automation.filing-grade-generation. The page-split path in crates/pdf-core/src/generate.rs removes some of the same entries, and does so for safety — but a different safety, that no byte of an excluded page survives into the output: it drops the catalog OpenAction, AA and Names because they reference pages across the whole document, and strips an action from an annotation on a kept page only when that action points at an excluded one, with a fail-closed gate behind both. An action pointing inside the kept range survives. A split is not a scrub, and neither path settles what the other should do.

The capability works. Nobody can reach it, because its interface is not built.

Removes hidden content and metadata from PDFs.

Corrections after finalization

What becomes of money a client over-pays, which the built mechanism cannot express — client_credit.credit_note_id is NOT NULL and the schema policy forbids the destructive rebuild that would relax it, so a payment larger than the bill cannot open a credit. Three ways out: leave the excess as received-and-unapplied cash and report it, which is safe and leaves the firm holding an unexplained figure; add a nullable payment source beside the credit note with a shape check requiring exactly one; or refuse over-payment at the application boundary and make the firm issue a refund. DeferredParkedtranslation.certification

Human-attested certification

Whether the platform offers human-attested certification at all. It is the difference between a reading aid and something a firm can file — under the governing federal standard a competent person may run an engine, review the output line by line and then sign, at which point the certificate is true — and it is also the part with the most ways to go wrong, so the recommendation is yes but only once the artifacts it would certify exist. A no means the product ships permanently as an explicitly non-certifying reading aid, which changes nothing else in this area. Translation design flag T3.

Set aside by an earlier decision. The answer decides whether it comes back.

A named person reviews the aligned translation, edits it, and signs a certificate of accuracy declaring their own competence in the language pair and the completeness of the rendering.

Sending the answers back

This page has no network of any kind — that is what lets it be read from a repository, from a published link, or from a laptop with no connection, and be the same page. So it hands the answers over two ways instead. Copy puts them on the clipboard for you to paste into the conversation. Open an issue writes them into a new repository issue for you, which lands them without a conversation being open at all — the browser does the sending, not this page. Either way the block names each decision by its own identifier, which is what lets every answer reach the right capability without anybody matching them up by hand.
