# claude/evidence-absence-rule

**Scope:** Evaluate — and measure — a ninth ledger-staleness rule that would refuse an unfalsifiable
absence claim ("no conflicts check exists to trigger") by requiring it to name a repository path.
**Measured and rejected**: 96 raw hits over 708 nodes for the path-requirement form, 8 hits at 5
true / 3 false for the better ledger-against-itself form found while measuring. Neither reaches the
zero-false-positive bar this scan holds itself to, so no rule ships. The rejection and both
measurements are recorded in the design's rejection register, and the matcher is kept as a hand-run
search tool — which is where it earned its keep, finding the stale nodes below.

**Then the sweep the measurement paid for:** correct every node in `roadmap.d/conflicts.md` that
still reads as though slices 1 and 2 had not shipped, plus the stale absence claims the matcher found
in five other areas.

**Files expected to touch:**

- `roadmap.d/conflicts.md` (six nodes: matching-engine, matching-engine.strictness, search-depth,
  firm-wide-scope, clearance, log)
- `roadmap.d/financial.md` (invoice-composition, wip-to-ar, and four notes lines calling the billing
  slice unbuilt), `roadmap.d/core-domain.md`, `roadmap.d/communications.md`,
  `roadmap.d/observability.md`, `roadmap.d/settings.md` (one prose line each)
- `roadmap.d/README.md` (one paragraph: an absence claim is not required to name a path)
- `docs/specs/2026-08-14-feature-ledger-staleness-detection.md` (a fourth and fifth rejection, with
  their measurements)
- `docs/now.md`, `docs/register-history.json` (regenerated by `vp run register-build`)
- `changelog.d/`, `docs/active-work/claude/`

**Not touching:** `tooling/lint-ledger-staleness/` (no rule is added, so its rules, fixtures and
tests are unchanged), any application code, `STATUS.md`/`status.d/`, `CHANGELOG.md`, the Decision-Log
register.
