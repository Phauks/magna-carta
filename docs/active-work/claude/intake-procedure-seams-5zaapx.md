A new package, `@magna-carta/intake`, and the first slice of the intake procedure: a firm-authored, per-matter-type list of steps a consultation must clear before it opens, each step answered by the subsystem that owns the fact (conflicts, billing, document assembly, trust, custom fields) or by a member's record, with a reader seam per kind so a kind can exist ahead of its subsystem. The matter shell gains an `openPreconditions` hook mirroring `closePreconditions`, threaded through `openMatter`; that touches `packages/matters/src/matter-service.ts` and the open route in `apps/api-worker/src/routes/matters.ts`, plus a new `GET /api/v1/matters/{id}/open-readiness`, so a concurrent stream regenerating the OpenAPI snapshot or the API client will collide — coordinate before touching them.

The per-firm lineage gains migration `20260903T150000_intake-procedure` (three tables and four permission seeds) and snapshot `0094`; a stream adding its own per-firm migration will need to re-sequence the journal. The matter section strip gains an eighth top-level entry, Intake, after Overview (`apps/web/src/lib/matters/sections.ts`), which the owner should walk on the deployed site at 1440 to confirm the row still fits before the fold backstop. The status window (`matter-status-dialog.svelte`) gains Requirements To Open on a consultation.
