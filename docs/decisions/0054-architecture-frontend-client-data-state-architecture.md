**Client data & state architecture — a three-way state split (URL / server-cache / local) with TanStack Svelte Query for server state, cross-tab BroadcastChannel sync, deliberately-minimal per-feature realtime on the DO-per-job primitive, and Tauri-only offline persistence; a local-first sync engine rejected as the default.** **Context:** the SPA (ADR-0001) committed to deep-linkable routes, multi-tab/pop-out with BroadcastChannel sync, and Tauri offline+sync parity, but the client data/state layer itself was unspecified. **Decision:** split client state **three ways, one owner each** — **URL state** (router, ADR-0052), **server state** (cached API responses) in **TanStack Query (`@tanstack/svelte-query` v6**, verified Svelte-5-runes-native; caching, dedup, refetch-on-focus, **optimistic mutations + rollback** surfacing the Observability Error ID, structured invalidation; query keys/hooks derived from the code-as-contract client, ADR-0022), and **local/UI state** in **Svelte 5 runes**. Cross-tab + pop-out coherence via **BroadcastChannel** cache-invalidation messages. **Realtime is deliberately minimal** — Magna Carta is not live-collaborative at the data layer (document co-editing is Collabora's own channel, ADR-0010); freshness = refetch-on-focus + cross-tab broadcast + **per-feature live channels on the Durable-Object-per-job primitive** (ADR-0039) only where genuinely needed (long-running job progress; the cross-device live timer, ADR-0033). **Offline follows parity** (ADR-0023): the web cache is **in-memory only, cleared on logout** (ADR-0025 app-shell-only service worker), while **Tauri** adds a cache **persister + an outbound mutation queue** behind the same call sites. **Considered & rejected:** a **global server-push / presence layer** for v1 (significant infra + cost before a feature needs it — kept as a seam: extend the DO-channel primitive to a per-matter/per-firm channel later); a **full local-first sync engine** (TanStack DB / Zero / Triplit — heavier, opinionated, and at odds with the server-authoritative ledger + per-firm-D1 model — seam only); a **bespoke runes data layer** (reinvents caching/dedup/invalidation against reuse-first). **Consequences:** a mainstream, typed, reuse-first client data layer meeting the multi-tab/offline/freshness needs without premature realtime infrastructure; cost is the TanStack Query dependency and the Tauri offline adapter. Builds on **ADR-0001** (SPA), **ADR-0022** (typed client + the open OpenAPI-library spike), **ADR-0052** (URL state), **ADR-0023** / **ADR-0025** (parity / caching), **ADR-0039** (DO-per-job realtime primitive), and **ADR-0033** (timer). Recorded in _Delivery model and application architecture_ (Client data & state architecture).
