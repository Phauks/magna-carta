**The `inline_playable` verdict seam (slice 2·3).** The white paper homes the inline-playability verdict "at ingest" (a cheap container+codec sniff, no FFmpeg, with a Reports "X% inline-playable" roll-up). The question for 2·3 (which needs the verdict to gate safe delivery) was where to compute it, given that the verdict's natural home — the `runIngest` pipeline — is being actively rewritten by the live, built-but-unmerged slice-2·1 worktree, and that no consumer of a playable-vs-download-only distinction exists in the repo yet. The decision: **compute at ingest, but in 2·3 land only the seam.**

**(1) Column only, on `main`, ahead of the worktrees.** 2·3 adds a single additive, nullable column to `file_version` — `inline_playable text` with `enum('playable','download-only','indeterminate')`, **NULL = never-sniffed** — matching the `storage_encoding`/`artifact_role`/`pinned`/`storage_class` seam columns that were all added before their consumer existed (ADR-0078, build-when-in-the-area). The verdict is **two-axis**: a render-disposition (`playable`|`download-only`) plus an honest `indeterminate` ("sniffed but undecidable"), with NULL distinct from `indeterminate` so the Reports roll-up can name a "not-yet-assessed" bucket rather than bias its denominator. The fail-safe direction is load-bearing: **only a positive `playable` can ever unlock inline-media**; a never-sniffed or undecidable row is always download-only.

**(2) Parser, compute hook, and backfill are ALL deferred to the first reader.** Verified: no inline-playable reader code exists in the repo (the player UI is deferred to 0·7a/0·7b; the Reports roll-up is uncoded); and the `file-type` library is codec-blind (it yields a container MIME only), so a real verdict needs a net-new MP4-`stsd`-FourCC / WebM-EBML codec probe that is neither cheap-now-needed nor expensive-to-retrofit (a pure function addable in one commit). So 2·3 ships **only** the column; the codec-sniff parser, the one-line `runIngest` compute hook that writes the verdict on commit, and the corpus backfill of already-committed versions all land with whichever slice first **reads** the value (the 2·1 ingest rebuild, the player, or Reports). Until then the column reads NULL and every preview correctly renders download-only — the identical UX to an `indeterminate` verdict.

**(3) `ingest-core.ts` is off-limits in 2·3.** The slice-2·1 worktree (built but unmerged) rewrites `packages/file-manager/src/ingest-core.ts` (the `IngestInput`/`IngestOutcome` shapes and every commit/quarantine return arm) and owns `file_version` scan-detail migrations — a hard-conflict surface. 2·3 therefore never edits `ingest-core.ts`; it lands all file-manager changes additively (a new exported `getCurrentCleanVersionForPreview` read, a new `preview-policy.ts`, a new `safe-rendition-port.ts`). The compute hook is the natural work of the 2·1 rebuild owner, whose pipeline already reads the head bytes.

**(4) The migration number is not pre-reserved.** The stable, reservable fact is the column name + two-axis semantics, not a number: `0013` is taken (slice 1·4), the next free is `0014` but a parallel stream may claim it. The migration is numbered at land time, gated on `vp run worktrees`. The column is nullable/additive/reader-free, so it lands ahead of 2·1's merge without ordering risk.

**Context.** 2·3's safe-delivery gate must read a per-version playability verdict; the verdict's white-paper home is ingest; ingest is mid-rewrite in a parallel worktree; and no consumer of the distinction exists yet. The seam-only decision honors the "at ingest" home and one-home-per-fact (the column is the single irreducible cheap-now/expensive-to-retrofit artifact — adding a column to a populated table later is the costly retrofit; a pure parser with no caller is not) while keeping 2·3 decoupled and collision-safe.

**Considered & rejected.** Computing the verdict now by extending `runIngest` from the 2·3 worktree (white-paper-canonical home, but a verified hard merge conflict with the 2·1 rewrite, and it breaks 2·3's "gate on nothing / stay decoupled" promise) — rejected. Deriving playability lazily at first preview (versions are immutable so an at-ingest verdict never goes stale, killing lazy's only advantage; lazy adds a byte-read to a request path that is byte-read-free today — a golden-rule-10 regression — and structurally breaks the Reports all-files denominator) — rejected. Shipping the codec parser eagerly in 2·3 (no reader exists; building machinery ahead of its load profile) — rejected; deferred to the first reader. Pre-reserving migration `0013`/`0014` (three worktrees carry divergent migration chains) — rejected; numbered at land time.

**Consequences.** The verdict column is present on `main` for the deferred readers to populate, 2·3 stays additive and collision-safe against the 2·1 worktree, and the parser+backfill (and the load-profile extension for the non-NULL distribution) are a named forward obligation on the first reader slice.
