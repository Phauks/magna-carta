**Amends ADR-0060. The OCR crate is `oar-ocr`; the model is the official first-party PP-OCRv6 ONNX export; and OCR determinism is server-canonical rather than cross-architecture.**

**Context:** ADR-0060 chose the engine class — PaddleOCR PP-OCR models consumed as ONNX through the Rust `ort` crate, never the PaddlePaddle framework, CPU-only, permissively licensed, one engine compiled native for both the server container and the Tauri desktop — and explicitly deferred three items to build time: the specific Rust crate, a head-to-head against docTR on structured layout output, and the model artifact. Two of those resolve on evidence rather than a spike, and one premise of the ADR does not survive contact with how ONNX Runtime actually behaves.

**Decision:** (1) **Crate = `oar-ocr`** (Apache-2.0, `ort` backend). It supplies detection, recognition, document-orientation classification, text-line orientation, and rectification in one crate, and can embed model bytes into the binary. Rectification and orientation are load-bearing for scanned legal exhibits, not extras. The alternatives fall on their merits: `retto` is a single-maintainer work in progress, `ocrs` recognizes Latin script only, and the MNN-backed crates (`rust-paddle-ocr` and relatives) would introduce a second C++ inference runtime with weaker provenance. The docTR head-to-head is dropped rather than run: docTR has no Rust crate, so winning on layout output would forfeit the one-engine-two-locations property that ADR-0060 exists to protect, and layout extraction is not a requirement of this slice. (2) **Model = the official `PaddlePaddle/PP-OCRv6_{det,rec}_onnx` artifacts** (Apache-2.0), pinned to an exact revision, SHA-256 verified, fetched at Docker build time and baked into the image — the build stage has network, the runtime stage has none, mirroring the scan container's YARA Forge and `freshclam` build-time fetch. PP-OCRv6 shipped 2026-06-11 with ONNX exports published by the PaddlePaddle organization itself; PP-OCRv5's ONNX artifacts were community conversions whose license text varied by republisher. This is an accuracy gain and a provenance gain. The artifact is **two files per model** — `inference.onnx` plus an `inference.yml` holding the pre/post-processing transforms and, for recognition, the character dictionary that maps class indices to glyphs; both are pinned and hashed. Compatibility is **verified rather than assumed**: read directly from the published protobufs, detection is opset 14 (IR 10) and recognition opset 11 (IR 6), every operator is a standard ONNX core operator with no custom domain and none of the `deformable_conv` / `fake_quantize_*` operators that are the documented failure mode for Paddle exports on ONNX Runtime — so the models load on the bundled ONNX Runtime 1.24 with wide headroom, and no self-export fallback is required. **The tier was pinned by measurement, not assertion — and the measurement picked small over medium.** v6 publishes three tiers — tiny (6.2 MB), small (31.0 MB), medium (138.6 MB) — and the vendor publishes no clean CPU benchmark separating them on documents shaped like ours, so the engine takes the model path as configuration, all three tiers are pinned by revision and content hash in a manifest, and a benchmark decided which pair the image bakes. Ground truth is manufactured rather than labelled: born-digital documents already carrying real text layers are rendered to raster at 300 DPI, degraded as a scanner degrades them, OCR'd, and compared against the text and glyph boxes the PDF engine's observer path extracts from the original — exact per-glyph ground truth on our own document shapes, at no labelling cost, though it understates absolute accuracy since that glyph text carries no word-spaces and follows PDF paint order rather than visual reading order, so the benchmark is a relative-ranking instrument between tiers rather than an absolute accuracy claim. Swept over 13 documents, the three tiers landed within one character-error-rate point of each other — noise, not a real ranking — while small led on word-box overlap at a quarter of medium's size and a comparable cold-load time, so **small is the tier baked into the image**, amending the medium lean this decision originally carried. The benchmark reports character error rate, word-box overlap, pages per second, cold-start model-load time, and image size; it then serves as the regression baseline for every later model upgrade, which is what makes the re-OCR discipline enforceable rather than aspirational. **Recognition covers Latin, CJK, and Greek only:** the v6 dictionary holds 18,707 entries, 15,565 of them CJK ideographs, with Cyrillic, Arabic, Hebrew, Devanagari, Hangul, and Thai absent entirely — "50 languages" means fifty Latin-script and CJK languages. Detection is script-agnostic, so the **recognizer is a swappable unit selected per text line**, with exactly one registered today; PaddlePaddle's per-script recognizers exist only for v5 (`korean_`, `cyrillic_`, `arabic_`, `devanagari_`, `th_`, `latin_`, `el_`, Tamil, Telugu) and are registered behind the same seam when a matter demands one, each stamping its own `modelVersion`, so a document is never silently read by a model that cannot represent its script. The scripts the v6 dictionary lacks (Cyrillic, Arabic, Hebrew, Devanagari, Hangul, Thai) are accepted as out of scope for now — the per-script seam stays dormant until a matter needs one of them. (3) **Determinism is server-canonical.** ADR-0060 asserted that the same input yields the same output regardless of where it ran. ONNX Runtime offers no cross-architecture bit-exactness guarantee and cannot: floating-point addition is not associative, and SIMD reduction order differs between x86-64 and ARM64. Argmax and CTC decoding quantize small logit differences away, so decoded text matches on virtually every real page — but "virtually every" is not a claim to make to a court. The corrected position: the x86-64 container is the single evidentiary source of truth, configured with one intra-op thread, one inter-op thread, sequential execution mode, and a fixed graph-optimization level, so it is reproducible against itself, which is the property that matters for re-running a production. A future desktop path is a speed and privacy accelerator whose output is marked provisional and never enters a production or a privilege log without a server run confirming it. (4) **Three separable version fields** on every result — `engineVersion` (the engine code), `modelVersion` (the pinned artifact), `platform` (the architecture that ran it) — never collapsed into one, which is a mistake the scan engine already made. A model upgrade triggers re-OCR rather than a silent divergence between documents processed before and after.

**Golden rule 14 — C++ consent, granted.** The only memory-unsafe code is ONNX Runtime, reached through the Rust `ort` crate. It adds no new C++ surface: `containers/scan` already pins `ort` to run Magika, under an existing consent — same library, same version line, same statically-linked build, same base image. There is no Rust alternative at the required breadth: `ocrs`, on the pure-Rust RTen runtime, is the one credible memory-safe engine and is Latin-script only, while discovery will meet Chinese, Japanese, and Greek documents that the chosen engine reads and `ocrs` cannot; it remains the named escape hatch if a C++-free build ever becomes a hard requirement. Decisively, the unsafe code never parses untrusted bytes — ONNX Runtime reads only our own pinned model file and a decoded pixel buffer, while the untrusted document is parsed by pure Rust (`hayro` inside the PDF engine's page rasterizer, or the `image` crate), so what crosses into C++ is a flat array of pixel values with no structure left to exploit. This inverts the exposure golden rule 14 exists to prevent; Tesseract fails the same test, since its C++ reaches image decoding through Leptonica. Consenting to the ONNX Runtime already in the tree is what permits refusing MNN without surrendering accuracy or language coverage. **Disclosed residual:** a future Tauri desktop build ships ONNX Runtime's C++ onto user machines — new surface relative to server-side inference, and a decision for the desktop slice. Today the code runs only in a container with `enableInternet = false`, behind the engine host's panic net, scaling to zero.

**Fitness tests:** the pinned model files match their recorded SHA-256 at build time, and the build fails rather than proceeding on a mismatch; the engine's session is constructed with single-threaded, sequential, fixed-optimization-level options, asserted at construction; the same document OCR'd twice in the same container yields byte-identical text; every result carries all three version fields and no field is derived from another; a page that already has a visible text layer is reported as skipped with a reason rather than re-OCR'd or returned as empty; an inference fault surfaces as a retryable 503 and never as an empty text result; the container image builds on trixie and boots in CI, since the ONNX Runtime linkage failure against bookworm's glibc appears only in the cloud build; no privileged content reaches a log, an error label, or a `Problem` response.

**Amends ADR-0060** (OCR engine class, ONNX-not-PaddlePaddle, CPU-only, permissive license, one engine two locations — all of which stand). **Reuses ADR-0024** (Rust scope and shared core), **ADR-0023** (web/desktop parity), **ADR-0030** (the conversion orchestrator dispatches scanned-PDF-to-searchable-PDF to this engine), **ADR-0039** (containers and queues for heavy compute), **ADR-0057** (idempotent retry). Bounded by **ADR-0003** (per-firm isolation — the container is firm-agnostic; the worker owns firm scoping) and the confidentiality discipline of **ADR-0038**.
