**Distribution & IP-protection posture: treat everything distributed to a client as readable by an adversary; the moat is the server and the legal perimeter, not the bytes. Client hardening is minification only (no obfuscation as a primary defense; no production source maps); the open/closed line is drawn explicitly; entitlement enforcement is server-side and deferred.** **Context:** asked ahead of distribution (web MVP first, Tauri desktop after — ADR-0002) how the program's internals are protected from actors who might extract the code or recreate the product. Four threats named (all in scope): competitor cloning, code/IP theft from the shipped artifacts, license/entitlement circumvention, tenant-data exfiltration. This records the _posture_ only — nothing is built now; every mechanism below is a named future seam (owner, 2026-06-15: posture ADR only). **Decision, seven points.** **(1) The moat is the server, not the bytes.** Anything embodying competitive value or correctness secret-sauce runs server-side (Workers / Containers / Durable Objects), never in the distributed client. The distributed surfaces — the Svelte SPA JS bundle, the Rust→WASM shared core, and the Tauri native binary + webview — are **treated as public** in the threat model: assume an adversary reads them. This is largely descriptive of where value already lives — the trust/ledger engine (ADR-0008/0009), conflicts (ADR-0013), billing/costs, and document-automation workflows are database-bound through the firm-scoped data-access layer (ADR-0003) and were never client candidates; it sharpens, not reverses, the ADR-0088 client-first-by-default placement (privileged bytes stay on the user's device, but the engine logic shipped there is the _generic_ PDFium engine, not proprietary product logic). **(2) Client hardening = minification only.** No heavy obfuscation / anti-tamper as a primary defense — rejected: it buys little against a determined actor while costing debuggability, performance, and clean observability/CSP (ADR-0017). **No production source maps are shipped to clients** (binds now — cheap, expensive to walk back; also trims shipped bytes). Seam: per-hotspot obfuscation may be revisited at distribution time _only_ if a concrete sensitive client-side routine appears; the default is no. **(3) Legal perimeter (named; owned outside engineering).** Proprietary closed-source SaaS license (already the platform's stance — ADR-0088); EULA / Terms of Service prohibiting reverse-engineering, decompilation, and scraping; trade-secret hygiene — the white paper, specs, ADRs, and research are internal trade secrets and are **not** published; trademark the brand (`magnacarta.esq`); register copyright; patents case-by-case and disfavored (a patent publishes the method). This is a business/legal owner track — engineering names it as a dependency and does not design it; its only real cost is legal/one-time (registration + drafting). **(4) The open/closed line is explicit** (reconciles ADR-0088 §J). Generic engine primitives are _deliberately_ open — upstreamed under MIT (the PDFium sanitization/signing contributions) — which is intentional, not a leak. What is protected is the **proprietary product layer** (trust/ledger correctness, the conflicts engine, document-automation workflows, the RBAC + ethical-walls model, the redaction verification gate), the **firm data**, and the **brand**. Rule: open the generic primitive; protect the product layer + data + brand. **(5) License/entitlement circumvention → server-side enforcement only (deferred seam).** When distribution arrives, entitlements/licensing are checked server-side in a Worker; the client is never trusted to enforce its own license, and the Tauri desktop app is a thin client to the same server entitlements — no offline crack surface for paid features (the ADR-0023 parity model: desktop adds optional local accelerations with a server fallback, never platform-exclusive entitlement logic). Nothing is built now; named as a distribution-time slice. **(6) Tenant-data exfiltration is already governed** by the tenancy/security posture — the firm-scoped data-access layer (ADR-0003), ADR-0052 absence-not-existence responses, sandbox-hardened Containers, and the separate cookieless preview origin (security conventions). This ADR adds nothing there; it references those as the answer to that threat. **(7) Honest non-goal.** Clean-room reimplementation of the product _concept and UX_ is not technically preventable and is explicitly out of scope for technical defense — it is countered only by the legal perimeter (point 3) and the operational moat (trust-accounting/regulatory correctness, data gravity and switching cost, integrations, reputation, feature velocity). **Considered & rejected:** a hardened/obfuscated-client posture (cost > value; the server is the real lever); building license/entitlement enforcement now (YAGNI — distribution is far off; recorded as a seam); treating _all_ internals as secret (contradicts the deliberate ADR-0088 §J openness — the open/closed line is drawn instead). **Consequences.** _Binds now:_ no production source maps; "does this value belong server-side?" becomes a design check on new client-shipped logic; internal process docs are treated as trade secrets. The now-binding rules are recorded in [`docs/conventions/security.md`](conventions/security.md) (_Distribution & IP-protection posture_); everything else is a named future seam surfaced in [`../ROADMAP.md`](../ROADMAP.md) at distribution time. _Cost:_ no material infrastructure cost — value placement is mostly descriptive of existing server-side logic (DB-bound, low-CPU; Workers bill CPU time, not I/O wait), and the ADR-0088 client-first default is preserved; "protected" never means relocating heavy _client-feasible_ compute onto an inline Worker — heavy + protected work goes to a Container/Queue (golden rule 10, ADR-0039, ADR-0083). Real costs are legal/one-time (trademark, copyright, EULA/ToS); the deferred entitlement check is a session-cached per-request lookup. **Status Accepted** (posture only — no implementation). Builds on **ADR-0003** (tenancy isolation), **ADR-0023** (web/desktop parity), **ADR-0052** (absence-not-existence), **ADR-0088** (proprietary-SaaS stance + §J open/closed line); composes with golden rules 3 and 10.
