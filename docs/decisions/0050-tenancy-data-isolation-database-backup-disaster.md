**Database backup & disaster recovery — two layers (Time Travel + export snapshots), on-Cloudflare, bucket-lock-immutable, GFS 7+yr; separate backup account declined, off-Cloudflare seam deferred.** **Context:** the tenancy model (control-plane D1 + per-firm D1 + per-firm R2, ADR-0003) had no documented backup/DR strategy; D1's **Time Travel** gives free always-on 30-day point-in-time recovery but nothing longer, no protection against database/account loss, and no multi-year legal archive of DB state. **Decision:** two layers — (1) **Time Travel** is line-of-defense #1 for operational recovery (bad migration, fat-finger write, accidental delete) within 30 days, free, no setup; (2) **export snapshots** are line-of-defense #2 — a **Cron-triggered Workflow** fans out across firms, calls the **D1 export REST API** per database, and streams each SQL dump into **that firm's own R2 bucket** (`backups/` prefix), preserving per-firm isolation; **control-plane D1 backed up the same way** as a first-class target; restore = SQL import into a fresh D1, validated by **periodic restore drills**. Backups land in the same at-rest-encrypted per-firm store; `protected()` field ciphertext stays encrypted inside the dump, so **crypto-shred** (ADR-0026) still covers backed-up secrets. **Retention: GFS ~7+ yr** (daily→30d, weekly→1yr, monthly/yearly→7+yr, aligned to matter-retention windows), aged snapshots **tiered to IA** via the same lifecycle as versions/deleted files (ADR-0035/ADR-0049). **Immutability via R2 bucket locks** (prefix-scoped retention per GFS tier) blocks accidental/malicious deletion before age-out — the primary defense against keeping primary + backup in **one Cloudflare account**. **Considered & rejected / deferred:** **Time Travel only** (no DR past 30 days, no account-loss protection — kept only as layer 1); **separate Cloudflare backup account** (cleanest blast-radius isolation, but **declined** for operational simplicity — bucket locks carry the deletion-defense instead); **off-Cloudflare cold copy** (true provider-independent DR + certified-WORM path — **designed-but-deferred** as a seam for the residual tail: Cloudflare-wide catastrophe, account loss, or a firm's SEC-17a-4-grade compliance need). **Honest limits:** R2 bucket locks are retention policies, not certified WORM, and lock rules are account-managed — hence the retained off-Cloudflare seam. Extends **ADR-0003** (tenancy); reuses **ADR-0035**/**ADR-0049** (IA tiering lifecycle) and **ADR-0026** (envelope encryption / crypto-shred); uses **Workflows + Cron + R2** from the _Cloudflare primitive mapping_.
