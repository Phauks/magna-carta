**`protected()` concretization — envelope, context binding & blind-index policy: every protected value is stored as the versioned binary frame `[algo_version | key_version | iv(12) | AES-256-GCM ciphertext+tag]` (base64 TEXT); every encrypt/decrypt is context-bound via AAD = the canonical string `mc:aad:v1|firm|table|field|row_pk|algo_version|key_version` so a ciphertext moved between rows/fields/firms fails authentication; HKDF-SHA-384 purpose keys derive under frozen versioned info constants (`mc:v1:pii`, `mc:v1:secrets`, per-field index subkeys `mc:v1:index:<table>:<field>:<index_name>`) with all keys non-extractable end to end; blind indexes are version-prefixed truncated HMAC-SHA-384 over frozen normalization transforms, with low-entropy fields (DOB, SSN last-four) never standalone-indexed — matched by decrypt-and-compare on a higher-entropy candidate set; TOTP seeds stay under Better Auth's own at-rest encryption (verified + rotation-configured), closing ADR-0026's open line.** **Context:** ADR-0026 fixed the architecture (envelope encryption, per-firm keys, the data-access chokepoint, HMAC blind index for Conflicts) and ADR-0046 the agility mandate, but neither specified the bytes, parameters, or per-field policy — the cheap-now/corpus-rewrite-later layer; research ([`docs/research/protected-crypto-module.md`](research/protected-crypto-module.md)) verified the primitive set on the Workers runtime and surfaced the policy math (CipherSweet's coincidence formula `C = R/2^min(L,K)`, target `2 ≤ C < √R`). **Decision (additional):** module = pure `@magna-carta/encryption` + enforcement in `data-access` (`protectedField` declarations carrying the ADR-0068 permission required to decrypt; `readProtected` = permission check → per-firm `audit_log` row → AAD decrypt, inseparable; `blindIndexValue` matching needs no permission and writes no audit — nothing is revealed); per-field policy table: SSN standalone-indexed at L=16 over digit-stripping, account numbers L=24, driver's license L=16 state-prefixed, DOB/last-four never standalone, plugin credentials + incident descriptions encrypted unindexed; normalization transforms are frozen contracts (a change = full decrypt-reindex, documented as a deliberate maintenance job); firm keys minted at provisioning (idempotent `FirmProvisioner` step + a one-off mint sweep for existing firms); `firm_secret` table + `getSecret`/`putSecret` under `firm:manageSecrets`; `incident.description` upgraded by expand-contract with a code backfill sweep (SQL migrations cannot encrypt); crypto-shred ships as the audited `shredFirmKey` registry function, offboarding route a named seam. **Considered & rejected:** routing TOTP seeds through the module via Better Auth hooks (permanent coupling to library internals, zero gain against the actual database-exfiltration threat — owner decision 2026-06-12, option 1 of the research's three); per-firm keys for TOTP (layering inversion — login precedes firm context; shredding a firm must not break a user's login); standalone DOB/last-four blind indexes (~15/~13 bits — fingerprintable by frequency analysis at any truncation); `deriveBits` (raw bytes in the JS heap; `deriveKey` keeps everything non-extractable); a separate crypto Worker (re-rejected per ADR-0026); wide-nonce ciphers for IV safety (outside the FIPS-friendly set — IV uniqueness is enforced in code with a fitness test instead). **Consequences:** Conflicts gains its exact-identifier channel with quantified leakage (equality + frequency only, accepted knowingly); rotation seams are one byte each instead of corpus rewrites; the module ships exercised (secrets store, incident upgrade, fixtures) before Directory declares its fields in 1·3. Extends **ADR-0026** (amended: TOTP line closed) and **ADR-0046** (the version bytes realize the agility mandate); builds on **ADR-0068** (decrypt permissions), **ADR-0073** (provisioning step), **ADR-0071** (package seam); slice 1·1's `audit_log` is the decrypt-audit home. Spec: [`docs/specs/2026-06-12-slice-1-2-protected-crypto-module-design.md`](specs/2026-06-12-slice-1-2-protected-crypto-module-design.md). _Amended 2026-06-16 (slice 1·2 build): two build-time verifications. **(a)** The `firm_secret` row-id prefix is the full-name form **`firmSecret`** (not `fse`), per the slice-1·1 ADR-0062 amendment full-name convention — the scaffold commit's `fse` placeholder was reconciled to the registry's full-name scheme. **(b)** The Better Auth at-rest 2FA-secret encryption keyset is verified and used, but in the pinned **better-auth 1.6.16 the option is named `secrets`** (an array of `{ version, value }`), **not `encryptionKeys`** — wired as a single-element rotation array with version 0 = the existing `AUTH_SECRET` (so already-stored TOTP seeds still decrypt; a future rotation prepends a version). All else built as designed._
