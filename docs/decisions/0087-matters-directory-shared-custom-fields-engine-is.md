**The shared custom-fields engine is promoted to its own slice 1·4 (after Directory, before Phase 2·6 document automation) — not built in slice 1·3 and not deferred to LEAP. Slice 1·3 ships fixed standard fields only (a category is a classification label, ADR-0085); the shared typed-EAV design is settled in the 1·3 spec as 1·4's seed: per-firm `custom_field` definitions (the Clio-12 kind catalog as a CHECK; target matter | entity; attachment to matter-type/entity-category) + picklist-option child rows + `custom_field_value` with typed value columns (text/number-minor/date/option-FK/reference) exactly one non-null, reference kinds getting real indexed columns. 1·4 extends slice 1·3's merge relink set to repoint reference-kind values (build-when-in-the-area).** **Context:** ADR-0080 deferred the custom-fields engine "to a shared design with Directory"; the 1·3 design cycle found it is the largest single component, is a genuinely shared subsystem (matter types from 1·1 + entity categories from 1·3), and is built against known field _kinds_ (not a firm's unknown field inventory — so it need not wait for LEAP). Sequencing it after 1·3 (needs entity categories as an attach target) and before 2·6 (which consumes custom merge fields) puts it where its consumers are. **Considered & rejected:** building it inside 1·3 (unbalances the slice; the largest component bolted onto Directory); deferring to the LEAP slice (risks landing after 2·6; leaves the build unscheduled — and the kinds are knowable now); JSON-column storage (breaks merge relink + field-level audit/temporal history — the §A.3 platform invariants); descoping firm-defined fields entirely (a white-paper promise). **Consequences:** 1·3 stays lean with a fixed schema; 2·6 document automation has a custom-merge-field home; ROADMAP gains slice 1·4 and the Backlog custom-fields expectation points there. Amends **ADR-0080** (custom-fields-deferral line → slice 1·4); builds on **ADR-0085** (categories, merge relink).
