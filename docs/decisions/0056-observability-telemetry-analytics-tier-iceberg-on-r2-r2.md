**Telemetry analytics tier — Iceberg-on-R2 (R2 Data Catalog) evaluated and deferred; Analytics Engine is the MVP path; design the Logpush→R2→Iceberg seam now, adopt on named triggers.** **Context:** the observability pillar's always-on operational telemetry (ADR-0017, ADR-0038) ships to **Workers Logs/Logpush → R2** and **Analytics Engine**, but Analytics Engine has known ceilings — **~92-day retention**, **adaptive sampling** under high write volume, and a **limited SQL surface** (no rich joins / external engines) — that a long-horizon, exact-count, or BI-grade telemetry query workload would eventually hit. Cloudflare's **R2 Data Catalog** (managed **Apache Iceberg** REST catalog on R2, zero-egress, with managed **compaction** + **snapshot expiration** table maintenance) is a natural fit for the redacted logs **already landing in R2**. **Decision:** **evaluate and defer** — keep **Analytics Engine as the MVP telemetry-query path**, and record R2 Data Catalog as the **designed-but-unbuilt analytics tier** with its insertion point fixed: register the Logpush-in-R2 logs as **Iceberg tables** → query via DuckDB/Spark/external BI at zero egress. It sits on data already written, so adoption is configuration, not re-architecture. **Scope is narrow by construction** — only **redacted, cross-firm aggregate operational telemetry** (the class the pillar already rolls up globally), so it **never touches per-firm privileged data** and stays clear of the ADR-0003 isolation boundary; any future per-firm Iceberg use would require strict per-firm table scoping and is **out of scope**. **Adopt-when triggers:** (1) **retention** beyond ~92 days; (2) **sampling fidelity** — exact/unsampled counts; (3) **query power** — joins / external engines / BI; (4) **cost at scale** — cataloging existing Logpush-in-R2 beats scaling Analytics Engine writes. **On adoption,** enable **compaction** (small-file problem → sustained query performance) and **snapshot expiration**, and treat the open-beta limits (**Parquet-only**, **~2 GB/table/hour** compaction throughput, **orphan-file cleanup not yet automated**) as **verify-before-build** (same provisional posture as ADR-0045). Reuses the **Cron-triggered Workflow → per-firm R2** fan-out established in ADR-0050. **Considered & rejected:** **adopt now** (premature — Phase 0 unscaffolded, the custom report builder / live dashboards are themselves deferred, and Analytics Engine covers the MVP query workload); **reject outright** (forfeits a cheap, well-aligned seam on data already in R2 — re-litigating it later costs more than recording it now). **Consequences:** the telemetry analytics path is captured with explicit flip conditions so it is neither built prematurely nor re-debated; the cost is carrying the seam and re-verifying the beta limits at adoption. **Status Accepted (2026-06-18)** — a trigger bound: product-usage analytics (`ADR-0106`) needs full-fidelity retention/BI, so this tier is **adopted and realized** by that work, with the path fixed as **Logpush → Pipelines → R2 Data Catalog**. R2 Data Catalog now **automates compaction + snapshot expiration (incl. data-file cleanup)** — the open-beta "orphan-file cleanup not yet automated" caveat above no longer binds; Analytics Engine retention is **~90 days (verify current)**. The Logpush→Pipelines provisioning step itself is the remaining deferred build (that slice's sub-step). Extends **ADR-0017** / **ADR-0038** (observability); reuses **ADR-0050** (Cron-Workflow/R2 fan-out) and the _Cloudflare primitive mapping_; bounded by **ADR-0003** (tenancy/isolation).
