**Bulk-download implementation: adopt `client-zip` (MIT, pinned) as the streaming store-mode ZIP64 writer — per-entry CRC-32 via streaming data descriptors, async/stream entries fed directly from R2 `get()` bodies, memory-flat at any archive size; version keys resolved at request time (consistent snapshot); only `clean` versions eligible; single-file selections download directly; v1 ships the live stream only, with the ADR-0027 async-job seam (build-to-R2-artifact → signed URL past a config threshold) documented and flagged for future research (job lifecycle, artifact TTL, identical-bundle dedup — no timeline home yet).** **Context:** ADR-0027 fixed the approach (Worker streams R2 → store mode → ZIP64, version-pinned, access-checked, audit-logged); research (slice 1·1 research doc, section B) confirmed `client-zip` implements exactly the required mechanics and that streaming store-mode zips are I/O-bound (CRC-32 the only CPU work) — fine on a Worker at multi-GB sizes. **Considered & rejected:** a ~200-line in-house ZIP64 writer (re-implements a small, focused, pinned library; control gain not worth the maintenance); compression (ADR-0027 — legal corpus already compressed); building the async-job path now (no measured need; the live path ships first and the seam is documented). **Consequences:** bulk download lands with the File Manager at near-zero marginal design cost; the dropped-connection-wastes-the-stream failure mode is accepted until the async seam is researched and built. Implements **ADR-0027**; builds on **ADR-0068** (open reading, audit-logged exports). **(4) Parked for research (resolve in the slice 1·1 design cycle):** a **derived-vs-original artifact class** — recomputable artifacts (OCR text, conversion outputs, preview/CDR renditions, indexes) are caches, not archives, and arguably should not inherit keep-forever tiering by default; owner flagged needs-more-research before committing. **Recorded constraint:** any future per-firm envelope encryption of R2 objects (extending ADR-0026 beyond D1 fields) must sit _below_ the delta/dedup layer — encrypting first destroys the redundancy ADR-0077/0078 exploit. Extends **ADR-0077** (delta seam), **ADR-0050** (backup snapshots), **ADR-0035/0049** (tiering lifecycle); touches **ADR-0026** (encryption ordering), **ADR-0074** (Analytics Engine path).
