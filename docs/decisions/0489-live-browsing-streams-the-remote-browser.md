**Live mode streams the remote browser and forwards the member's input to it. The owner ruled on 2026-09-24 that live websites should be streaming, not screenshots.** Supersedes points 4 and 5 of the per-member-session decision (`interactive-browsing-on-a-per-member-session`); everything else in it stands.

**Context.** The first Live build held one browser per member and walked it from page to page, answering each step with a screenshot and the inspector's facts. The owner's first real use of it found the gap straight away: "I was on live, but could not interact with the screen." A consent button, a cookie banner, a search box, a menu that opens on hover — the steps a suspect link hides behind are things you do, not addresses you enter, and a picture per navigation cannot do any of them. The earlier decision had recorded pixel streaming as possible on this platform (the session probe found CDP available) and deliberately not built, naming three reasons to wait: keystrokes invite credential entry, a streamed session bills for its whole duration, and the input path is new attack surface. The owner's ruling answers the first two as costs worth paying; the third is answered by the design below.

**Decision.**

1. **The stream is a WebSocket from the member's page to their session object.** `GET /api/v1/safe-browse/live/stream` passes the chokepoint on `tools:safeBrowse`, refuses an upgrade carrying another site's `Origin` (a socket is not protected by the same-origin policy, and this one would let a foreign page watch the member's screen and type into it), and hands the upgrade to the member's `SafeBrowseSession`. The object accepts it with the ordinary API rather than hibernation, because it now holds a live CDP connection to the browser that hibernation would drop.

2. **Frames are JPEG, paced by the member.** `Page.startScreencast` produces a frame when the remote screen repaints; the object forwards one and holds the next until the page has drawn the first and acknowledged it, superseding any older held frame. A slow connection sees a lower frame rate, never a backlog of stale screens, and the browser is never more than one frame ahead.

3. **Input is data, validated as hostile.** Pointer, wheel, key and pasted-text frames are parsed by one shared protocol (`@magna-carta/safe-browse/live-stream-protocol`): unknown types dropped, every number bounded, every string capped. Nothing the page sends is evaluated in the remote page; an address is guarded before the browser sees it.

4. **The guard covers every document for the whole session.** `Fetch.enable` scoped to the Document resource type pauses every main-frame and sub-frame navigation, and each redirect hop of one, until `assertPublicTarget` passes its address; images, scripts and fetches are not paused, the same line the static capture draws. A refused main-frame document is reported to the member; a refused sub-frame is blocked alone.

5. **Everything that would leave the screen is shut.** New tabs are folded into the visible one (and a tab that opens anyway is closed and its address followed through the guard), downloads are denied, the file chooser is intercepted, and dialogs are dismissed and reported so a page cannot freeze the stream.

6. **The credential risk is stated, not blocked.** The screen carries a standing warning never to type a real password or personal details into a page being checked. A technical block is not possible — the stream cannot tell a phishing page's password field from a search box — and refusing keystrokes would refuse the tool the owner asked for.

7. **One stream per member.** A second tab opening Live takes the stream over; the first is told why and releases the browser, and the second reconnects to it with its cookies. The idle alarm now counts input rather than navigations (three minutes with no pointer, key or scroll ends it), and the fifteen-minute ceiling is unchanged.

**Consequences.** A member can use a suspect page — click through its consent wall, scroll to what it hides, try its search box — without any of it executing on their device. A streamed session is billed for its whole open duration, which the idle alarm and the ceiling bound; the cost note in `docs/operating-costs.md` says so. The per-navigation POST route is retired, so there is one Live path, not two. The frames are pictures of whatever the page shows, so the member's screen can show anything the page renders — the same exposure a screenshot had, at a higher rate.
