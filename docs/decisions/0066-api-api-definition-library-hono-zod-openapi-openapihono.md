**API-definition library — `@hono/zod-openapi` (`OpenAPIHono` + `createRoute`, Zod 4, OpenAPI 3.1 via `doc31`) with a spec-first codegen client (Hey API → typed client + Svelte Query v6 hooks; `openapi-generator`/Speakeasy for non-TS SDKs), deliberately NOT Hono `hc` RPC inference; resolves the ADR-0022 Phase-0 spike.** **Context:** ADR-0022 fixed REST + OpenAPI 3.1 code-as-contract on Hono but left the implementing library to a Phase-0 spike (oRPC vs ts-rest vs @hono/zod-openapi vs chanfana). The contract layer underpins every subsystem, so the choice is high-leverage; June-2026 research drove it. **Decision:** (1) **Library = `@hono/zod-openapi`** — first-party Hono (Hono is Cloudflare's internal Workers framework; its creator is a CF Developer Advocate), `OpenAPIHono` extends `Hono` (zero adapter), first-class OpenAPI 3.1 (`doc31`/`getOpenAPI31Document`), Zod 4. (2) **Spec-first codegen for the client, not `hc` inference** — the emitted 3.1 spec is the single source of truth; **Hey API** generates the typed TS client + Svelte Query v6 hooks for the first-party app, `openapi-generator`/Speakeasy generate non-TS SDKs from the same spec. By **not** building an `hc<AppType>` client we avoid Hono RPC's documented `tsc`/IDE blow-up on large route unions entirely, while keeping per-route handler typing (cheap). (3) **CI spec gate** — the emitted spec is snapshotted/validated (Spectral, Prism, oasdiff) so code-as-contract stays honest regardless of library. **Considered & rejected:** **oRPC v1** (best single-library capability — spec + typed client + Svelte/TanStack from one definition — but single-maintainer **bus factor** and a ~6-month-old v1; the portable spec lets us adopt it later with no contract break if Hono disappoints); **ts-rest** (effectively **dormant** — no commits since Jun 2025, **OpenAPI 3.0 only**, no official Hono adapter, no Svelte Query); **chanfana** (Cloudflare-authored and 3.1-default, but **spec-only** — no typed client — and its headline **D1 auto-CRUD endpoints bypass the firm-scoped DAL** (ADR-0003), making its main advantage unusable here; `@hono/zod-openapi` is a superset that also keeps inference as an escape hatch). **Consequences:** native Hono, OpenAPI-3.1 code-as-contract, fast/flat type-checking (no RPC-union tax), one uniform client-generation mechanism for first-party + third parties; cost is `createRoute` verbosity (tamed by 1.3.0 `defineOpenAPIRoute`/`openapiRoutes` + per-subsystem modules), Zod-4 lock-in (current/correct), and a codegen build step. **Extends ADR-0022** (resolves the spike it named — does not supersede); reuses **ADR-0003** (DAL), **ADR-0017/0038** (Error ID), **ADR-0026** (`protected()`); binds the route-metadata model (**ADR-0067**). Detail in the _API contract & route conventions_ spec. **Build amendment (2026-06-13, slice 0·5b — tooling deviations forced by 3.1/codegen reality):** (a) the committed snapshot is emitted through a programmatic **Vite SSR pipeline** (`scripts/emit-openapi.mts`), not the plan's plain-Node assumption — the worker route graph is bundler-targeted (extensionless imports, `.sql` text modules, attribute-less `.json`) and never loads under plain Node ESM; (b) **Spectral 6.16/nimma crashes** traversing the document because the contract emits `null`-valued `x-mc-permission` extensions, so `.spectral.yaml` disables `duplicated-entry-in-enum` (our enums are trivial single-value literals — near-zero loss); (c) the generated Hey API client is **formatter- and lint-exempt** (its bytes are the generator's, its barrel/codegen idioms trip our rules), so its "compiles" gate is a dedicated `tsc -p` wired into the root `check`, not vp's lint-coupled typecheck; (d) the document's root `tags` are **auto-derived from the operations** (shared emit helper feeding both the snapshot and the live `/api/openapi.json` route) to satisfy Spectral's `operation-tag-defined` without per-module maintenance. Operational detail in [`docs/conventions/api.md`](conventions/api.md).
