**Shipping & postage subsystem: adopt EasyPost as the first credentialed shipping adapter, with the `ShippingPort` as the category port, because EasyPost offers a documented REST API (rate/buy/track/refund), supports certified mail (USPS Certified Mail with return receipt and signature), and the EasyPost Forge child-user model centralizes postage billing to our account — whereas Pirate Ship has neither a public API nor certified mail support. The subsystem lands as `@magna-carta/shipping` (canonical model + `ShippingPort` + EasyPost adapter + zod boundary), the `integration_connection` per-firm table + migration `0006`, and firm-scoped `ConnectionStore` and `CredentialStore` seams in `@magna-carta/data-access`. The UI, vertical-slice routes (connection-management, `POST /v1/shipments`, rates, purchase, label, tracking, refund), and the live `firm_secret` credential backing are Plan 2 (gated on slice 1·2).** **Context:** the white paper names postage/shipping as a Phase 7 integration; the integration port system (ADR-0091/0092) landed the framework. Legal practice produces three shipping use-cases — certified-mail service-of-process (deadline-critical, USPS Certified Mail only), deposition/subpoena/evidence transport (tracked), and general document delivery — all requiring a credentialed provider. **Provider evaluation:** Pirate Ship rejected on two hard blockers: no public API (web-only UI — no programmatic rate/buy/track), and no certified mail capability. EasyPost selected: a comprehensive REST API (`/shipments/rates/buy/track/refund`), USPS Certified Mail with return receipt and signature, the Forge child-user model (charge-to-parent) so every client firm's postage bills to our EasyPost account (no per-firm billing setup needed), multi-carrier support, a generous free tier. **Design decisions:** `ShippingPort` (`validateAddress` / `rateShipment` / `buyLabel` / `getTracking` / `refundLabel`); canonical types (`packages/shipping/src/canonical.ts`) — `CanonicalAddress`, `Parcel`, `Rate` with `amountMinor` money encoding, `RatedShipment` with `remoteId` (EasyPost shipment id, consumed by `buyLabel`), `Label`, `TrackingEvent`, `RefundResult`; request-input types `AddressInput`, `ParcelInput`, `ShipmentOptions`, `RateRequest`, `BuyLabelRequest`; capability descriptor gates certified-mail usage; `ShipmentOptions` models certified mail + return receipt + signature + insurance; EasyPost mapping in `packages/shipping/src/easypost/map.ts` — `mapRatedShipment`, `mapLabel`, `mapAddress`, `mapTrackingEvents`, `mapRefund`, `mapShipmentOptions`, `dollarsToMinor`; EasyPost HTTP errors mapped into the framework's `IntegrationProblem` taxonomy (`auth`/`rate_limit`/`validation`/`upstream`/`network`) via `classifyError(status, title)` — errors surface as the dispatch `adapter-error` outcome. **Connection and credential seam:** `integration_connection` (migration `0006`, `integrationConnection_…` handles from `@magna-carta/identifiers`) and firm-scoped `ConnectionStore` (`getConnection` over the `integration_connection` table) land in `@magna-carta/data-access` as the connection persistence layer; the `firm_secret`-backed `CredentialStore` seam (`createFirmSecretCredentialStore` over a `SecretStore` interface, tested with an in-memory fake) is the ADR-0092 seam — the live `firm_secret` backing is Plan 2, gated on slice 1·2. **Out of Plan 1 (seamed):** shipment/label/tracking tables, the shipping service, all worker routes, EasyPost webhook ingress, R2 label storage, and the live credential backing. **Considered & rejected:** Pirate Ship (no API, no certified mail); stamps.com / Endicia (legacy APIs, no certified mail at API level); a multi-provider abstraction built now (one provider first, the port generalizes by construction). **Consequences:** legal-grade postage (certified mail) joins the platform; the `ShippingPort` is a first-class integration port carrying all ADR-0091/0092 framework semantics; Forge child-user billing removes per-firm credential management for postage; Plan 2 wires the live routes and credential store. Builds on **ADR-0091** (port framework), **ADR-0092** (connection model, `CredentialStore` seam), **ADR-0095** (api-key credential kind).
