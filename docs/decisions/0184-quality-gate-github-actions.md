**GitHub Actions is the whole-repo gate of record; the pre-push hook is a fast local subset.**

**Context:** ADR-0144 retired GitHub Actions and put the entire quality gate in the `pre-push` hook — full `pnpm check`, full `vp test`, the OpenAPI contract toolchain, and the scan acceptance test all ran locally before every push. That was sound when development happened on one workstation, but two things changed it. First, the production branch moved to `release` (ADR-0171), so a push to `main` deploys nothing and no longer needs to be gated _as a deploy_ — the deploy is a separate, later fast-forward of already-landed commits. Second, development moved onto ephemeral Claude Code cloud sessions, where the full gate's tens-of-minutes wall-clock is paid on every push, single-threaded in the type-aware lint pass, with no cross-run cache. A hook that runs the whole repo made every cloud push slow enough to discourage pushing, while adding nothing that a merge-time check could not do — nothing between `main` and the deploy re-runs it.

**Decision:** split the gate by cost. The exhaustive whole-repo gate lives in **GitHub Actions** (`.github/workflows/gate.yml`), running on every pull request into `main` and every push to `main`: `pnpm audit`, the full `pnpm check` (fmt + lint + `tsc -b` + svelte-check + Rust), the governance lints, migration integrity, the full `vp test`, all four contract-drift checks (OpenAPI snapshot, generated client, Spectral, design-token), and the acceptance suite of any changed container (scan/recovery/bundle). The workflow reproduces the environment the checks need — pnpm install, the pinned-Docker WASM build (`vp run rust-wasm-build`, since `rust-wasm-build-dev` refuses under CI), and the specific Playwright browser the vitest browser runner resolves. Branch protection requires this check, so `main` only advances on a green whole-repo run and the `main:release` fast-forward always deploys CI-verified code. The **`pre-push` hook** is narrowed to a fast tripwire — `pnpm audit`, `pnpm check:scoped` (fmt + lint + `tsc -b` + svelte-check/Rust, scoped to the diff), the governance lints, and the migration-integrity test — the checks the current diff can actually break, finishing in seconds. `SKIP_PREPUSH=1` still bypasses the hook; the safety net is now CI, so a skipped or under-powered hook is caught at the merge rather than shipped.

**Shape (built for keeps, not a monolith):** the workflow is a fan-out DAG, not one serial job — the same build-performance rule that governs the rest of the repo (ADR-0078: fast CI is a foundation added up front) applies to the gate itself. A `changes` job path-filters the diff; a `wasm` job builds the Rust→WASM artefacts once, caches them across runs keyed on the crate sources (a push that touches no crate restores in seconds instead of the ~7-minute cold Docker build), and shares them to the consumer jobs as an artefact; and the check dimensions — format, lint, type-check, rust, tests, governance, contracts, containers — run as independent jobs in parallel, each skipped when the diff cannot affect it (a docs-only push runs only format + governance). Wall-clock is the tallest single dimension (the type-aware lint pass), not the sum of all of them. Shared setup (pnpm + Node + deps, optional Rust) is a local composite action (`.github/actions/setup`), and an aggregate `gate` job is the single required status so the branch-protection requirement stays stable as jobs are added or skipped. Third-party actions are avoided beyond pnpm's official setup — the path filter is a hand-rolled `git diff` — to keep the CI supply chain small.

**Scope:** the quality gate only. The deploy model is unchanged — Cloudflare Workers Builds off `release` remains the pipeline (ADR-0144, ADR-0171); this reintroduces GitHub Actions solely as a check runner, never as a deploy path. The rendered ADR-0144 register entry stays Accepted; its "gates run pre-push, no CI runner" consequence is superseded by this entry and should be cross-linked when this fragment lands on `main`.

**Rejected:** running the whole-repo gate as a Workers Builds _build step_ (gate at deploy). It would keep everything inside one vendor, but it gates only the deploy — a broken commit still lands on `main` and is only caught when someone tries to ship, by which point several changes have stacked on it. It also couples check latency to the deploy pipeline and cannot gate a pull request before merge, which is where a firm-controlled trunk wants the gate. Also rejected: keeping the full gate in the hook and merely parallelizing it, which does not remove the fixed whole-repo cost paid on every cloud push and still leaves nothing gating a merge that used `SKIP_PREPUSH`.

**Consequences:** cloud pushes are fast again (the hook does a seconds-long scoped subset) while `main` is gated more strongly than before, because CI runs the exhaustive sweep on a clean, reproducible environment rather than trusting whatever each developer's machine happened to run. Two costs. First, the gate now depends on GitHub Actions availability and minutes; a red workflow blocks a merge, which is the intended trade. Second, `gate.yml` reproduces a non-trivial environment — the pinned-Docker WASM images, the Playwright browser install, and the flaky `ort-sys` ONNX download — and has not run on a runner yet, so it needs a first-run validation plus a round or two of iteration before it is made a required check; until then the interim protection is the scoped hook plus a manual `pnpm check && vp test` before a merge. A known non-determinism to quarantine during shakeout: `apps/worker/test/live-timer-do.test.ts`'s concurrent `stopAndCommit` race, which flaps independently of the change under test.
