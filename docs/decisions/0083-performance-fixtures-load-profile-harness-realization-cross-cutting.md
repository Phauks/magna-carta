**Load-profile harness realization (cross-cutting slice) — the white paper's third fixtures entry point builds as harness machinery inside `@magna-carta/fixtures` (no new package; a separate export path keeps it off the scenario/demo import surface): declarative named+versioned volume profiles (counts and distributions as parameters, never generator constants; one scale multiplier spanning CI-smoke to stress scale), generation through the real domain write-paths at volume (valid by construction, one-seed deterministic), snapshot artifacts (SQLite file + JSON manifest of profile version/seed/schema state/package versions) in a gitignored content-keyed local cache — reproducible by construction, never committed, manifest mismatch regenerates — and a query-level measurement runner (warmup + timed iterations → median/p95 per named domain-service/data-access operation, plus `EXPLAIN QUERY PLAN` capture flagging full scans on measured paths) writing small committed JSON baselines for human diffing.** **Context:** golden rule 10 and `performance.md` name the load profile the standing performance/scaling harness, and the slice DoD ("perf-tested against the load-profile fixtures as built") was unfulfillable without it; slice 0·3 built the other two entry points and deferred this one (§5.5); a growing gate list (the 0·3 efficiency candidates first) had no measurer, and the owner's per-gate rule is that every gate needs a named measurer. V1 ships the machinery + the ledger volume profile (the only domain with schema today); the **accretion rule** (ADR-0078's build-when-in-the-area principle) binds every subsequent domain slice to extend the profile and the measured set while the slice is open — 1·1 adds matters/files + the R2 blob layer of the artifact, 1·3 the Directory graph, Phase 3 financial volume. **Honesty clause:** local `node:sqlite` is not production D1 — numbers are relative (regression deltas, growth curves, plan shapes), never absolute latencies; the `loadtest` environment (ADR-0075) running the same harness on real infrastructure is the named absolute-numbers seam. **Rejected:** a new `@magna-carta/load-profile` package (golden rule 1 — the fixtures engine already owns determinism, the node-sqlite database, and the production guard); committing snapshot artifacts (reproducible derived data; repo + OneDrive bloat); CI timing gates now (`performance.md` defers budgets until stable numbers exist — CI gets a tiny-scale smoke only, no timing assertions); request-path HTTP measurement in v1 (slice 0·5's chokepoint stack would be measured mid-change; named seam, builds after 0·5); fleet-scale simulation (per-firm D1 isolation makes per-firm volume the unit that scales). **Consequences:** the 0·3 efficiency candidates become decidable with evidence; the DoD perf-test binds from the next slice to land; UI work (0·7a catalog, 1·1 screens) gains real-density data per the white paper's UI multiplier; the build is phase-independent and parallel-safe (next free session).
