**Module-reference policy — no convenience barrel files; reference modules by their specific source path within a package, and import other packages only through their `package.json` `exports` map (a curated, side-effect-free public surface + explicit subpaths, `"sideEffects": false`); enforced structurally by the Oxlint no-barrel rule + dependency-cruiser boundary/no-cycle rules, not discipline.** **Context:** the import convention starts at the first package (slice 0·1) and is expensive to retrofit across a large monorepo. Barrel files (`index.ts` re-export hubs) are a verified perf/correctness sink on this exact stack: Vite's dev server crawls/transforms every module a barrel re-exports for a single import (Vite's own perf guide says avoid them), mixed inline+re-export barrels break tree-shaking (Rolldown can pull a whole barrel + its heavy deps into a shared chunk), and barrels breed circular deps and slow `tsc`/IDE. Rolldown 1.0's lazy-barrel optimization helps at _build_ time but does not fix the dev-server crawl or every tree-shaking edge case, so the guidance remains "avoid." A specific case of the _Architectural integrity & coherence_ boundary-rules category (ADR-0051), not new machinery. **Decision:** (1) **No convenience barrels in source** — intra-package imports reference the specific module (`./trust/rounding.ts`), never an intermediate `index.ts`. (2) **A package's public API = its `package.json` `exports` map** — one small, **curated, side-effect-free** entry and/or explicit subpaths (`@magna-carta/money`, `@magna-carta/money/rounding`), with **`"sideEffects": false`** so tree-shaking still drops unused re-exports; this curated boundary file is the _only_ acceptable barrel-like module, kept flat (no nested re-export chains). (3) **Cross-package imports touch only another package's declared `exports`**, never its internals. (4) **Enforced, not trusted** — the **Oxlint no-barrel rule** on source (already in `vp check`) + **dependency-cruiser / ts-arch** boundary + `no-cycle` rules in CI (the ADR-0051 fitness-function tier), so the wrong import fails CI rather than relying on memory. **Considered & rejected:** **convenience barrels relying on Rolldown's lazy-barrel optimization** (keeps the dev-server crawl, tree-shaking edge cases, and circular-dep risk — optimizes a problem better avoided); **zero barrels anywhere incl. package entries** (maximally safe but loses the curated, discoverable package surface and makes consumer imports more verbose for no real tree-shaking gain once `sideEffects:false` + `exports` are in place); **deep cross-package imports into internals** (defeats encapsulation and the boundary fitness functions). **Consequences:** clean package boundaries with no barrel perf/tree-shaking tax, circular deps caught structurally, and a fast dev server as the module graph grows; cost is slightly more explicit import paths and the per-package `exports`/`sideEffects` discipline (a scaffold makes it uniform). Practitioner detail in [`docs/conventions/typescript.md`](conventions/typescript.md); a one-line nod in the white-paper _Architectural integrity & coherence_ boundary-rules text; first applied in the _Phase 0 · walking skeleton_ spec. Reuses **ADR-0051** (boundary rules / fitness functions / coherence ordering) and the Vite+/Oxc toolchain; binds every future `packages/*` and `plugins/*` module.
