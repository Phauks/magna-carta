**Version-history delta storage — designed-but-deferred: superseded `vN` snapshots may later be stored as binary deltas instead of full bytes; slice 1·1 reserves the seam now (version metadata carries a `storage_encoding` discriminator — `full` today — and nothing outside the data-access layer may assume a version object is raw file bytes); the delta pipeline itself builds in Phase 2 after Collabora editing ships, gated on real version-churn numbers from the load-profile harness (golden rule 10).** **Context:** ADR-0035 already prevents the autosave-explosion failure mode (autosaves overwrite the churning `current`; versions are cut deliberately, never per-autosave), but deliberate versions still accumulate as full snapshots in Infrequent Access forever (tiering, never pruning — ADR-0035/0049), and successive versions of the same document are highly redundant. The catch: `.docx`/`.xlsx`/`.pptx` are deflated ZIP containers, so a one-word edit scrambles the compressed byte stream and defeats any naive binary delta — deltas require a normalization step first. **Decision (the deferred design, recorded so the seam is cheap):** when a version is superseded, an **async Queue/Container job** (never the Worker request path) re-packs the ZIP container with entries _stored_ rather than deflated (the ReZipDoc insight — ~30 lines against any zip library, not a dependency), computes a **zstd `--patch-from`** delta against a base version (one tool for every format: normalized OOXML, PDF — incremental-save PDFs are append-mostly — images, generic binaries; solid Rust bindings fit the planned shared Rust doc core), **verifies a roundtrip content hash**, then swaps the IA object. The **latest version always stays a full object** and a **full keyframe every K versions** bounds reconstruction chains — no corrupted base may strand unbounded descendants, and the recorded content hash keeps every version independently verifiable (the legal-hold/discovery defensibility bar). Recorded trade-off: a delta-encoded old version cannot be range-streamed for preview — history preview reconstructs first (acceptable at ~once-a-year read rates). ADR-0035's "no compression" stands for the active corpus (`current` + the latest version, preserving the inline-preview range-stream path); this ADR scopes it: superseded versions may delta-encode behind the seam. **Why deferred, not built:** IA is $0.01/GB-mo with no minimum object size — a firm's full snapshots must reach ~100 GB before costing $1/month, so the saving (real, compounding, multi-tenant) does not justify storage-layer complexity before measured churn exists. **Considered & rejected:** **building the pipeline now** (optimizing ahead of measurement — golden rule 10); **ReZipDoc itself** (a Java git clean/smudge filter — the normalization insight transfers, the tool does not); **content-defined chunking + chunk store** (FastCDC/restic-style: O(1) reconstruction and cross-document dedup are attractive for templated legal work, but it multiplies object counts and operational complexity — revisit at Phase 4/discovery scale if measurement justifies); **per-autosave delta versions** (already solved differently — ADR-0035's deliberate version-cutting is the first-order fix to save-churn). Extends **ADR-0035** (version tiering — the supersede-to-IA `CopyObject` hook is exactly where the delta job attaches) and **ADR-0049** (deleted files tier through the same path); touches **ADR-0010** (Collabora — the Phase 2 churn source) and the slice 1·1 File Manager spec (carries the seam).
