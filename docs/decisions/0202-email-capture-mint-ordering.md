**A capture address is minted per-firm-first through the transactional outbox and revoked control-plane-first, and the token it carries is disclosed exactly once.**

**Context:** A forward/CC capture address is one logical thing stored in two physically separate databases that share no transaction. The **control-plane** `email_capture_route` row maps an opaque token to a firm; it is the only thing the inbound Email Worker can read, because that worker holds no per-firm database handle and must answer "which firm?" from a single indexed lookup. The **per-firm** `email_capture_address` row maps the same token to a matter (or to nothing, for the firm catch-all) and records who minted it and when. The reader of each half is a different process. Until a writer existed, the control-plane index was empty and every forwarded message bounced, so the whole forward/CC entrance was dead code behind a working parser and a working consumer. Writing the two halves needs an order, and any order has a window where they disagree; the question is which disagreement is acceptable.

**Decision:** (1) **Mint writes per-firm first, through the outbox.** The `email_capture_address` row and an `emailCaptureAddress.minted` outbox row commit in ONE atomic per-firm batch (the existing `composeEffectBatch` / `runIdempotentEffect` chokepoint), and the per-firm outbox relay dispatches the control-plane insert. The intermediate state is an address that **exists but is not yet routable**: mail sent to it in that window is bounced by the Email Worker, which is a visible non-delivery, not a loss or a misfile. The opposite order would produce the intolerable state — a token routing to a firm that has no record of what it is for, so mail arrives somewhere nobody can see it. Convergence is the relay's at-least-once retry, and the mint response reports `routable: false` so the transient state is part of the contract rather than a surprise. (2) **Revoke and rotate write the control plane FIRST**, un-batched, and only then the per-firm row. Revocation is a security operation and must fail closed: the routing row flips before anything else runs, so the token has stopped delivering mail by the time any later step can fail, and the residue of a partial failure is a dead address rather than a live credential. Rotate is revoke-then-mint returning the new token, with the per-firm retirement and the replacement insert riding one batch so a matter is never briefly without an address or briefly holding two. (3) **Mint and rotate declare idempotency `required`.** Both create a bearer credential, so a double-submit must return the first token rather than strand a second live address or retire the token the caller was just shown. (4) **Tokens are server-minted, 20 characters of lowercase alphanumeric (~103 bits), never client-supplied.** Lowercase because the receiving worker lower-cases the local part before lookup; no `.`, `+`, `-`, or `_` because mail systems read or rewrite them. `email_capture_route.token` is a GLOBAL primary key, so the mint claims a candidate against that index with bounded retries (mirroring `generateUniqueIdentifier`'s UNIQUE-insert idiom), and the relay's insert is `ON CONFLICT DO NOTHING` reconciled against the winning row — a token already routing to another firm is refused loudly, never adopted. (5) **The token value is returned exactly once**, in the mint or rotate response. It IS the credential, so lists return a four-character prefix plus metadata, and audit entries carry the address handle and never the token. (6) **The firm catch-all binds `resource: "firm"`.** It has no matter by construction, so the conformance suite's namespace→resource map admits both `matter` and `firm` for `emails:*` rather than forcing a resource the object does not have.

**Considered & rejected:** **a two-phase commit or a distributed transaction across the two databases** (D1 has no interactive transactions and no cross-database transaction at all; the outbox is the platform's existing answer and is already the chokepoint every other cross-boundary effect rides); **writing the control plane first on mint** (creates the one genuinely dangerous window — a live token routing mail into a firm with no address record — in exchange for removing a window where mail merely bounces); **writing both halves best-effort with a reconciliation sweep** (a sweep that repairs a half-written address must guess which half is authoritative; the outbox makes the per-firm half authoritative by construction and needs no guessing); **routing revocation through the outbox for symmetry** (that would leave a revoked token still delivering mail for up to a sweep interval — the exact failure revocation exists to prevent); **client-supplied or human-readable tokens** (`acme-smith-v-jones@…` leaks a matter name to every recipient of a forwarded thread and is guessable); **encoding the firm in the address hostname** (Cloudflare Email Routing supports exactly one zone-level catch-all and no per-subdomain wildcards, which is why the firm lives in the token at all); **returning the token on reads** (multiplies the exposure of a bearer credential across every list render, log, and screenshot for no capability the mint response does not already provide).

**Consequences:** A minted address becomes routable on the next per-firm outbox sweep rather than instantly, which is why the shared per-firm job queue is now a declared consumer — the relay's publish had no consumer before, so this effect (and every other per-firm topic) would never have been applied in production. A dead-lettered `emailCaptureAddress.minted` row is a real operational signal: the address exists and will never route until the row is revived through the documented operator seam. The token's one-time disclosure means a lost token is not recoverable — the answer is rotation, which is why rotate ships in the same slice as mint rather than as a follow-up. The `emails:*` namespace becomes the first with a two-resource binding in the conformance map, a widening the original single-value rule anticipated and which stays a closed set rather than a suppression.
