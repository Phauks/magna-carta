**In-app conversion moves from in-house-only to a pluggable engine model with confidentiality as the default.** Amends **ADR-0030**.

**Context:** ADR-0030 framed the converter as **in-house only, by design**, justified by confidentiality — privileged bytes go R2 → our Container → R2 and never egress (CloudConvert/Zamzar rejected). The owner now wants the converter to also be able to use **external engines** (Microsoft 365, Adobe PDF Services, others) where a firm chooses them. That means privileged client files could leave the tenant, which contradicts ADR-0030's absolute in-house framing. A reconciliation is needed that honors the new intent without discarding the confidentiality guarantee.

**Decision:** (1) Conversion engines are **peer adapters behind one `ConversionPort`**, reusing the integration framework (typed port, per-adapter capability descriptor, the per-firm `integration_connection` + credential store). In-tenant Container/WASM engines (LibreOffice, libvips, FFmpeg) and external credentialed engines (Microsoft 365, Adobe) are the same shape. (2) Each adapter declares a **capability descriptor** carrying a **confidentiality posture: `in-tenant` | `egress`**, alongside the edges it serves, fidelity, and cost. (3) **In-tenant is the default and the only path for privileged content.** An `egress` engine is selectable only when the firm has **explicitly enabled** it **and** the content class permits egress; privileged content never selects an `egress` candidate. Egress is a deliberate, governed, consented exception — never the default. (4) The format **registry** becomes a multi-candidate graph (an edge may have several candidate engines); the orchestrator does policy-driven selection after pathfinding. Per-firm available conversions are the union of the enabled engines' descriptors.

**Consequences:** the confidentiality principle survives as the structural **default** (nothing egresses unless a firm chose a vendor and the content class allows it) while external engines become an additive adapter problem rather than a rewrite. The white paper's _In-app file conversion_ is amended to match (the published rationale no longer reads as an absolute in-house lock). Builds on **ADR-0091**/**ADR-0092** (integration port system, connection model) and **ADR-0067** (the route chokepoint, when wired). The pure core (`ConversionPort`, descriptors, registry, pathfinding, selection) and the libvips adapter are built substrate-independently ahead of the execution substrate; the orchestrator/Container/Durable-Object execution and the registry storage model remain deferred.
