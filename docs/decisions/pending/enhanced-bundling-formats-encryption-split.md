summary: The matter bulk-download ("bundle") path gains user-chosen output options — format (ZIP and 7z, via an extensible encoder registry), compression (store/normal/maximum), AES-256 encryption, and format-native multi-volume splitting — plus quality-of-life options (named output, wrapper folder, flatten, a CONTENTS manifest). This EXTENDS ADR-0027 (which kept bulk download as store-mode ZIP64) rather than replacing it: a two-lane build keeps the existing in-Worker client-zip path for plain ZIP (store, no encryption, no split) and routes everything heavier to a dedicated Rust Container (containers/bundle, mirroring containers/scan), per golden rule 10 and the "Container subsystems extract to dedicated workers" standing rule. The encryption password is user-supplied and NEVER persisted (in-memory only — not in the durable queue, not in logs, not in the cache key); encrypted bundles therefore bypass the durable queue and the content-addressed R2 cache and build single-flight. This is general-convenience download tooling, not a legal-production feature, and it is NOT a new Tool (the Tools area is matter-grade work done without a matter; bundling only acts on files already in a matter). "Bundle" is the deliberate term — "archive" means retired/retention items in this product.
---

**Enhanced Bundling.** The firm wanted a better matter-file download: pick the format, optionally compress, encrypt, and split. ADR-0027 established bulk download as version-pinned, access-checked, audit-logged store-mode ZIP64 streamed R2→client-zip→R2 (with an async-job→R2→signed-URL seam for large bundles); this decision adds the option surface on top without disturbing that fast path. **Boundary / two lanes:** plain ZIP (store, no encryption, no split) keeps streaming through the existing in-Worker `client-zip` path — cheap, already built; anything needing compression, encryption, 7z, or multi-volume splitting routes to a new dedicated **Rust Container** `containers/bundle` (an axum service streaming R2→encoder→R2, never buffering the whole archive), because that CPU work cannot run in a request handler (golden rule 10) and `client-zip` cannot produce 7z/AES/LZMA2/volumes. The container is a deploy-time activation that cannot run under the local test pool, exactly like `containers/scan`, with a CI image-build acceptance gate (build→re-open→verify, wrong-password rejection). Cost is negligible — Cloudflare Containers bill active-CPU only and scale to zero (~$0.001–0.008 per build; typical volume sits inside the included Workers-Standard allowance), and the Container platform is already committed by `containers/scan`, so this is a second image, not a new commitment. **Secret posture (load-bearing):** the encryption password is supplied per request and never persisted anywhere — it is not a field of the `BundleOptions` model, and `bundleCacheKey` is built from an explicit allow-list that excludes the `encryption` block (and the display `outputName`, which does not change bytes). Encrypted output is non-deterministic (random salt/IV) and its password must never enter a durable queue message or a persisted key, so **encrypted bundles bypass the durable queue and the R2 cache and build single-flight, with the password held in memory only** (redact-by-default, golden rule 4). The worker cache-lookup MUST branch on `encryption !== null` to bypass the cache — never rely on the cache key differing, or it could serve a plaintext artifact for an encrypted request. **Extensibility:** an encoder registry keyed by format (mirroring `@magna-carta/conversion`'s registry) makes a third format a new adapter row plus one capability entry, not a change spread across callers; the UI gates its option controls off that capability table. **Clean-only and isolation are unchanged from ADR-0027:** bundles build only from `status='clean'` current versions, manifest hash and coordinator DO stay firm-scoped, artifacts live in the firm's own bucket. **Considered & rejected:** self-extracting `.exe` (SFX) — antivirus-flagged malware vector, clashes with the untrusted-file posture; **RAR** output — proprietary/licensing; exposing compression **method / dictionary / thread count** as user knobs — performance internals the builder auto-tunes from the chosen level (LZMA2+solid for 7z, Deflate for ZIP); a **Worker/WASM** encoder instead of a container — CPU-bound work barred from the request path and impractical for large/split/encrypted jobs; **legal-production** features (Bates, production logs, delivery-to-portal) — out of scope, named as later seams. **Consequences:** the pure model lives in `@magna-carta/file-manager` (`bundle-options`, `bundle-formats`, `bundle-paths`, `bundle-layout`, `contents-manifest`, `bundleCacheKey`) and is built+merged; the container, the worker orchestration (extending `apps/worker/src/downloads/`), and the UI follow as separate plans.
