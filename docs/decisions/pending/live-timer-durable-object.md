summary: The single active live timer is a per-timekeeper Durable Object (the codebase's first DO), firm-namespaced via idFromName(`${firmId}:${userId}`). It holds only transient timer state ({startedAt, pausedIntervals, matterId?, label?, narrative?, lastActivityAt}) in DO storage — it is NOT a business-data store; committed entries flow through the data-access chokepoint into per-firm D1. It is idle-friendly (hibernates between interactions; elapsed is computed client-side from startedAt, so the DO never ticks), making cost negligible. Stop-commit is idempotent on a DO-minted live_run_id (compare-and-set) to close the cross-device double-commit race; abandoned-timer detection uses an Alarms-API alarm cancelled/rescheduled on commit/discard. Scratch/unbound timers are allowed; binding to a matter is required only at commit.

**Slice 3·1 live timer.** The requirement — one authoritative, single-active timer per person that survives a tab close, follows the user across devices, and self-detects abandonment — is the canonical Durable Object use case (single-threaded coordination + the Alarms API + durable per-entity state; the white paper specifies the timer "lives in DO durable storage, not memory"). **Boundary:** one DO per timekeeper, firm-namespaced so it never holds another firm's state (ADR-0003); it stores only transient live state and is **not** a business-data store — `stopAndCommit` is route-orchestrated (read DO → compose a `time_entry` EffectWrite → commit through the chokepoint into per-firm D1 → clear the DO), keeping all business writes on the audited path (golden rule 3). **Cost posture:** the DO hibernates seconds after idle and elapsed is computed client-side from `startedAt`, so it accrues no duration while a timer "runs" — a handful of brief wakes per session; order ~$10–15/month at platform scale, most firms inside the included tier. **Correctness:** the stop-commit is idempotent on a DO-minted `live_run_id` (a single-threaded compare-and-set to `committing`; the route derives the Idempotency-Key + `timeEntry_` handle from it) so two devices racing one stop collapse to one entry; the abandoned-alarm is cancelled on commit/discard so it only ever fires for a live timer. **Considered & rejected:** a plain **D1 row** (viable and near-zero new infra, but loses race-free coordination, the alarm, and the realtime-push seam — the white paper already specifies the DO); an **always-on / non-hibernating WebSocket** (rejected for cost — if realtime cross-device push is added later, use the WebSocket Hibernation API). **Consequences:** introduces the first DO (wrangler `durable_objects` config + a DO migration class) — which pays forward (bulk-download jobs in 2·1 and a per-firm rate-gate already want DOs).
