**The Pangram adapter speaks both async (task-poll) and sync (v3) endpoints, selectable by configuration; the pure package stays timer-free via injected sleep and now; provenance is accurate.**

**Context:** The Pangram vendor offers two detection surfaces: an async task-submission workflow (external-api subdomain, `POST /task` with async polling on `GET /task/{id}`) and a direct synchronous endpoint (v3 subdomain). The existing adapter was wired to one; reconciliation ensures both are available without code branches, letting configuration track which the provisioned platform key can reach.

**Decision:** (1) **Dual-mode endpoint support.** The adapter recognizes two modes via `PANGRAM_MODE` configuration (`async` or `sync`, defaulting to `async`): async routes to `text.external-api.pangram.com` with task submission and polling; sync routes to `text.api.pangram.com/v3` with a direct call. The base URL is also configurable (`PANGRAM_BASE_URL`), so the exact path is a configuration binding, not code. (2) **Poll delay injection.** The core `@magna-carta/ai-detection` package is timer-free by design (pure adapters, no Date.now() or setTimeout). The async poll delay (`PangramAdapterConfig.sleep`) is injected at construction time in the worker route, so the package remains composable and timer-free for all consumers. The poll loop uses this injected `sleep` function and a configured `pollIntervalMs` (default 750 ms) and `maxPollAttempts` (default 16) to yield ~12 seconds of total wait. (3) **Provenance correctness.** The Pangram response carries `version` (the detector version) and a `stage` lifecycle field. Provenance is the detector version (mapped to `vendorVersion` in `DetectionReport`); the `stage` field is a request-lifecycle artifact, never provenance. `toRawDetection` unpacks the Pangram response correctly: `version` → `vendorVersion`, never touching `stage`. (4) **Configuration selection.** Which surface the provisioned platform key is valid for (external-api vs v3) is confirmed at key provisioning time; once known, it is a configuration change (`PANGRAM_MODE` + `PANGRAM_BASE_URL`), not a code change.

**Fitness tests:** the adapter accepts both submit and poll responses, correctly discriminating `PangramTaskStatus` states (success, failed, pending, malformed); the sync endpoint returns a direct result, not a task, mapped identically to the async flow via `toRawDetection`; the poll loop respects `maxPollAttempts` and `pollIntervalMs`; the pure package has no new imports (all existing allowlist); no `setTimeout`, `Date.now()`, or network imports in `@magna-carta/ai-detection/src/` (the injected `sleep` and `now` live only in the worker route); provenance mapping is accurate (version → vendorVersion, stage never provenance).
