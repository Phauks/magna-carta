**Custom-field lifecycle & governance (slice 1·4): the rules that keep firm-controlled data input from degrading platform invariants. (1) Rename is label-only and free (handle identity, ADR-custom-fields-engine). (2) Retype is allowed but only as a non-destructive guided Convert — Preview classifies each value clean/needs-a-rule/parked, the admin confirms rules and disposes of parked values (park = clear-to-history + a parked-values report, or block), Apply appends coerced values while flipping originals to history under one `custom_field.kind_changed` event, and the operation is reversible because no value is destroyed; a bulk Convert offloads to a Queue behind a `converting` flag so no mixed-kind field is ever read. (3) Value history is full-temporal (ADR-custom-fields-engine). (4) Delete is archive-first — `archived=1` retires a field but keeps all data readable and automation-resolvable; a true hard-delete is allowed only when the field has zero values (current + historical) and zero bindings; compliance erasure is a _separate_ permission-gated, audited, irreversible Purge whose seam (`purge.ts` + the `customFields:purge` permission + a `PurgeNotYetEnabled` throw) ships now and whose execution is built on a real erasure obligation. (5) Anti-bloat caps (fields-per-scope, options-per-picklist, fields-per-firm) ship as mechanism + named codes, the numbers calibrated by the load profile. (6) Conformity templates ("fast pre-builds") are deferred out of 1·4 with a hard gate — addressed before the first real client — shipping only the reserved `template_field_key` alignment column now (cheap because no firm has forked fields yet).** **Context:** the owner (2026-06-18) flagged that the engine's power — firms shaping their own data model — is also how invariants rot, and wanted the governance settled before build: retype must not lose data (the owner rejected immutable-kind-without-migration), delete must not orphan automation, and the schema must not bloat. The Convert/temporal-history pair is what makes safe retype possible — keeping every value as history turns a kind-change into a previewable, reversible transformation. **Considered & rejected:** immutable kind after creation (cleanest, but the owner will not accept losing data or forcing a manual new-field migration); kind change with silent coercion (lossy — drops un-parseable values); hard-delete as the default remove (orphans automation references + destroys the audit trail); overloading "delete" to also mean compliance erasure (conflates a reversible retire with an irreversible purge — split into Archive vs the gated Purge); building Purge and templates now (Purge has no consumer and is destructive — seam only; the templates' stable key is the sole expensive-to-retrofit part and there are no production firms yet). **Consequences:** firms get real flexibility (rename, retype, retire) with a no-data-loss guarantee and a clean erasure path when needed; the handholding cost (the Convert preview/confirm + the parked-values queue) is accepted; the templates deferral is recorded with a tracked before-first-client gate. Builds on **ADR-custom-fields-engine** (the engine + handle identity + temporal history), **ADR-0085/0086** (soft-delete-never-hard-delete + non-destructive merge), **ADR-0078** (build-when-in-the-area for the template-key seam).
