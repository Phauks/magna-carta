**Legacy port-43 WHOIS text is retained verbatim and never normalised into the shared registration fields; a bootstrap-fetch failure is a transport failure, not a 'no RDAP for this TLD' signal.**

**Context:** The WHOIS lookup is being enriched so a result can become a printable exhibit a lawyer hands to someone else. Most TLDs answer over RDAP (structured JSON), but four ccTLDs still answer only on port 43 with unstructured, mutually incompatible text. The temptation is to parse that text into the same fields the RDAP path fills, so the page renders one uniform card. Measuring the actual responses (captured 2026-07-09) showed why that is unsafe.

**Decision:** (1) **Never parse legacy text into the shared fields.** The four port-43 formats share no grammar, key names, or semantics. DNS Belgium (`.be`) reports a *registered* domain as `Status: NOT AVAILABLE`; mapping that string into the shared status field would state the opposite of the truth in a document offered as evidence. Their dates carry no timezone (`.it` publishes `1997-08-27 00:00:00`; `.be` publishes `Wed Jun 13 2012`), so they cannot honestly be converted to the UTC the rest of the report uses — guessing a zone would put a wrong instant in an exhibit. The legacy result therefore carries the raw text verbatim, marked `timezoneUnspecified`, and the page shows it as the registry published it. A per-registry parser may come later, driven by captured fixtures with tests; if one is ever written, a parse miss must never render as "not provided by the registry" — a failure to read and a genuine absence are different facts. (2) **The four are `.de`, `.eu`, `.it`, `.be`.** `.nl` and `.fr` were removed from the port-43 table: both now appear in IANA's bootstrap with RDAP endpoints (`rdap.sidn.nl`, `rdap.nic.fr`), so their rows were dead. (3) **Absence is typed, not blank.** A report distinguishes three silences — not-provided (the field is absent), redacted (the registry says so in `remarks[]`, quoted verbatim, never inferred), and not-applicable (a registrar or nameservers on an IP allocation) — modelled in the type system so the page cannot render a blank that implies the wrong one. (4) **Bootstrap outage is a transport failure.** Resolving the RDAP base now returns a discriminated outcome (`found` / `noRdapForTld` / `transportFailure`) rather than `string | null`. A non-200 from the IANA bootstrap fetch is surfaced as a retryable transport failure (HTTP 503), not misread as "this TLD has no RDAP" — which previously fell through to port 43 and turned an IANA outage into a 500 for every `.com` lookup. (5) **The read is audited.** A lookup can surface a natural person's postal address (some ccTLDs publish a full registrant contact), so the route writes a `whois.looked_up` row to the per-firm audit log recording who looked up what target and when — metadata carries the target, object kind, and responding server, never any surfaced contact detail. (6) **Provenance is mandatory.** Every result carries the exact target queried, the UTC timestamp of the lookup, and which server answered (the RDAP base URL or the port-43 host), because the document may become an exhibit and the raw payload is the record.

**Fitness tests:** the extractors are unit-tested against realistic RDAP fixtures — a domain object, an IP network object, a redacted registrant carrying the registry's own remark, a response missing every optional field, and a malformed body — asserting that "redacted" and "absent" produce different typed values, that an IP result is never classifiable as "not found" (registrar and nameservers are typed not-applicable), and that a bootstrap outage throws a transport error without ever attempting a port-43 query.
