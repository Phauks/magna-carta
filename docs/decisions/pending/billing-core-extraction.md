**One billable lifecycle, not two.** Slice 3·1 grew the WIP state machine (`draft → (submitted → approved) → billed`, plus `void`, with `billed`/`void` freezing the row) inside `@magna-carta/timekeeping`. Costs (3·3) are the same kind of billable work-in-progress — captured, optionally reviewed, then frozen at billing — and 3·4 billing will inherit the same contract. Re-implementing the lifecycle in `@magna-carta/costs` would fork the freeze rule and the gate semantics into two copies that drift. **Decision:** extract the lifecycle into a new leaf package **`@magna-carta/billing-core`** that both domains depend on. It exports `BillableStatus` (`draft|submitted|approved|billed|void`), the two gate-keyed transition tables (`canTransition`/`assertTransition`, gate-off draining of in-flight `submitted`/`approved` rows to `billed`), `isFrozen` (`billed`/`void`), the `IllegalTransitionError` thrown on an illegal move, and the firm review-gate definition `billing.approval_required` (default **false**, key namespaced `billing.*` so it is shared across time and costs rather than per-domain). Timekeeping's `lifecycle.ts` is now a thin re-export that pulls `canTransition`/`isFrozen`/`assertTransition` from billing-core and aliases `BillableStatus` to `TimeEntryStatus`, so no other timekeeping file changes. The costs service maps the generic `IllegalTransitionError` to its own `CostValidationError` at the HTTP boundary so each domain keeps its own 409 vocabulary while sharing the one source of truth for the transitions. **Considered & rejected:** *duplicate the lifecycle in costs* (rejected — two freeze contracts drift; a freeze-rule fix would have to land twice and could silently diverge); *keep the lifecycle in timekeeping and have costs depend on timekeeping* (rejected — costs would drag in the whole time-capture package, the rate engine, and the timer DO surface just to reach a five-state enum; billing-core is the minimal shared floor). **Consequences:** a change to the lifecycle or the review-gate default in `@magna-carta/billing-core` ripples to BOTH timekeeping and costs (and to 3·4 billing) — the package header and both area guides call this out; the extraction was verified behaviour-preserving by re-running 3·1's lifecycle and freeze suites green.
