**The letterhead asset declares its own box; the image-format policy is PNG and JPEG decided by magic bytes; and a firm's fields bind by handle, lexed by exact length.**

**Context:** The document-automation design reserved the letterhead logo for this slice and left one question open — "does the template declare the box, or does the asset declare its dimensions?" — flagging it as the one place a Locations schema change might be needed. It named no image formats. Separately, the design fixed that a firm's own fields bind by `customField_` handle rather than by name, but the expression-language design's own example wrote a custom key as `custom.retainerCap`, a slug rather than a handle; a real handle contains characters the grammar's name production does not accept, and one of them is the subtraction operator.

**Decision:**

1. **The asset declares the box.** `location` gains the logo columns, and the only dimension stored is a printed **width**; the height is computed from the image's intrinsic proportions at resolution time. A firm sets how large its mark prints once, on the office it belongs to, where it can see the result — rather than every template author restating it in English Metric Units, which no word processor's interface exposes and nobody can check by eye. Two properties follow that a template-declared box would not have: a document has no way to print a stretched logo, and replacing a wide mark with a tall one re-lays every letterhead out correctly without touching a single template.

2. **PNG and JPEG only, decided by the first bytes.** Not by the declared content type and not by a file name: a caller's label is a claim about bytes we are about to embed into documents, and the sniff is where it becomes a fact. **SVG** is refused because an image format that is a document is a markup and script surface inside a package the registration pipeline asserts carries neither, and it would have to go through the same scrub the template does. **EMF and WMF** are refused because they are record-based metafiles replayed by a drawing interpreter — historically the richest parser-attack surface in the whole format family — and unreadable outside Windows. **GIF, BMP, TIFF and WebP** are refused because each widens the content-type set while giving strictly worse reader compatibility for a printed mark. The policy is enforced where the logo is set AND re-checked where it is drawn, because a format policy is worth exactly what the last place enforcing it is worth; bytes that fail at assembly resolve as a visible absence rather than failing the document.

3. **The asset is uploaded inline, not through a presigned session.** A firm's mark is tens of kilobytes, and one request carrying the bytes is the only shape where reading what they are, measuring them, and writing the row that points at them all happen together. A presigned upload would put unvalidated bytes in the bucket first and leave an orphan behind every refusal. The object is content-addressed under the office, so setting the same mark twice writes the same object and a replaced mark never overwrites bytes an already-assembled document was produced from.

4. **The two letterhead rules are service invariants, not column CHECKs.** SQLite can only add a table CHECK by rebuilding the table, and this lineage rebuilds no table; more to the point the content type is the RESULT of a magic-byte sniff rather than a value a caller supplies, so the enforceable version of the rule lives where the bytes are.

5. **A firm's fields bind as `custom.<customField_ handle>`, derived per firm at read time.** The catalogue is not a declaration but a read — one statement, shared by the registration check, the field-list surface, and the assembly re-check — which is what makes drift detectable rather than silent: an archived field contributes no entry, so a template bound to it fails naming the key, and a stored value behind an archived field is skipped and reported as an absence rather than printing what the firm withdrew.

6. **A custom key is lexed by its EXACT FIXED LENGTH.** A minted handle's alphabet includes the hyphen, which is also the subtraction operator, and a greedy word scan would stop at the first one and report a name nobody wrote. Because a handle is a fixed prefix plus exactly twenty-one characters, the atom's end is known before the character after it is read — so `custom.customField_a-b…c - 5` is a subtraction of a merge field and `custom.customField_a-b…c` is one atom, with no case where an author's spacing decides which. The expression folder restates the handle's shape rather than importing it (it stays free of platform imports so the checker can run in a browser for the authoring surface), and a test pins the restatement to the minted shape in both directions.

7. **The scale rule is reused, not restated.** `effectiveNumberScale` from `@magna-carta/custom-fields` decides what a stored `value_number` integer means, so the boundary that writes a value and the document that renders it cannot drift into disagreeing by a power of ten. A currency field whose administrator declared a scale other than the currency's minor unit renders as the exact decimal it is rather than as money that would look right and be wrong — a "cent" that is not a hundredth belongs to no currency.

8. **An image is a value with no rendering and no expression type.** `legalFormatsFor("image")` is empty, so `{{location.letterheadLogo:upper}}` is a registration failure by the same check every other format suffix passes through; `expressionTypeOf` returns undefined for it, so the key is simply absent from the expression scope and `{{#if location.letterheadLogo}}` is refused as an unknown merge field rather than inventing a type whose every operation is an error.

9. **A field a template binds cannot be hard-deleted.** The custom-field hard-delete guard gains its template-binding arm — the reverse obligation the custom-fields design named and left for this consumer. It scans stored field manifests for the key rather than maintaining a bindings table, because it runs on a rare administrative action and a bindings table is a second copy of a fact the manifest already states, with its own way of going stale. Both arms route to Archive, where the binding stays resolvable as a reported absence.

**Consequences:** Locations' letterhead columns are in use for the first time, and the office-settings interface for the logo is a named seam rather than shipped. The assembly engine now emits parts, content types, and relationships as well as text, so `packageIntegrityViolations` reads the package structure — a document whose words are right and whose picture wiring is not is a document no reader opens, and no assertion about the document's text can see it. The image work is reusable: a second image merge field is a dictionary row plus a resolution arm, not a second emitter. `ResolutionInput` grew a `currencyCode` and an optional asset reader, both supplied at the composition root, which is where a firm-currency setting and a per-firm bucket will plug in.
