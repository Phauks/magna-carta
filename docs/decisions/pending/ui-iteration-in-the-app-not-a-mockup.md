**UI rounds move into the app once the design system can express them; the mockup is a bootstrap surface, not a review surface.**

**Context:** The sign-in screen was iterated through 27 versions as a self-contained HTML artifact built from the real design tokens, each element annotated with the design-system component it was meant to become, and verified by a headless-Chromium assertion harness before publication. That loop was productive while the components it named were still being invented. It has now inverted: every element of the sign-in anatomy resolves to a component that exists, is exported, has a story, and is already composed by the shipped route. Two copies of one screen exist, only one is the product, and each further mockup round adds a transposition. Separately, the reason the mockup still *felt* faster is narrow and fixable — the real screen is a three-step state machine, so seeing one error state means clicking through to it once per theme and mode, whereas the mockup showed everything at once.

**Decision:** Iterate in a throwaway artifact only while both conditions hold — the round explores a shape with no component behind it, and the question is which of several alternatives rather than an adjustment to one. When every element of a round names an existing exported component and the screen exists as a route, the next round happens in the app. The `data-mc` annotation convention is kept, and its completion is read as the handoff signal. For sign-in, v27 is the last artifact round. Feedback rounds from here are applied against a screen-states page in the existing developer console and reviewed on an assets-only preview Worker carrying both the built SPA and the built Storybook catalog. Nothing is added to the toolchain: no second component workbench, no design tool, no visual-regression service. The existing container-baseline visual-regression harness is finished (its first authoritative baselines committed) before any of its surface is extended, and route-layer accessibility is covered by axe in the end-to-end harness that already runs a real login.

**Consequences:** Feedback batches produce mergeable diffs instead of translation debt, and fidelity stops being a promise about a file. The preview surface has no API, so sign-in cannot complete there — acceptable because the states page reaches every visual state without a backend, and explicitly not a substitute for the staging environment ADR-0075 defers. Transposition of any remaining v27 difference is routed by bucket — token, component, or composition — so a screen-local class string is never patched where a token or a component was the real answer; the screen's hand-assembled quiet-inline-link utility string is the first known instance and belongs in a new design-system component.
