**Docs maintenance splits at the determinism line: per-merge CI assembly + a weekly propose-only docs-sync routine; the roadmap becomes the fourth rendered tracker; public trackers are projections.** **Context:** authoring never drifts (docs-in-commit, fragments), but the `main`-side residue — running the assemblers and rolling up `ROADMAP.md` — was manual and lagged measurably (rendered `CHANGELOG.md`/`STATUS.md` 11 days and 235 commits behind `main`; 52 changelog + 25 decision fragments unassembled at decision time). The move to cloud sessions removed the last habitual trigger ("owner's machine, right after merge"). ADR-0058 decided the agent's shape (propose-only, mechanical drafting + coverage-gap flagging, never authors narrative, never auto-merges) but left it unbuilt, and its own principle — deterministic hygiene is machinery, not an agent — was not yet applied to assembly itself. The roadmap/changelog are also slated to become public-facing, which unbounded hand-written narrative cannot feed. **Decision:** (1) **Assembly is per-merge CI** (owner-directed: the changelog updates with every PR): `.github/workflows/assemble-docs.yml` runs the three fragment assemblers on every push to `main` and commits the rendered outputs — loop-safe (its own commit carries no fragments) and serialized; a bot push of a byte-deterministic transform of already-reviewed fragments is not agent authorship. (2) **The judgment half ships as a weekly Claude cloud Routine realizing ADR-0058** — a fresh session per firing executes the in-repo procedure (`.claude/skills/docs-sync/SKILL.md`): audit the merge window for coverage gaps (drafting missing changelog fragments; flagging missing user guides/ADRs), roll `ROADMAP.md` up, delete orphaned `docs/active-work/` notes, re-run the assemblers as a backstop, and deliver everything as **one reviewed pull request** from a single `docs-sync/<date>` branch. The trigger is a dumb clock; procedure, policy, and **state** (the run-report registry `docs/maintenance/reports/`, whose `window-end` SHA each run resumes from) live in the repository, seeded by a **verified baseline** (a walkthrough of every tracker against the actual program — trust established once by inspection, then maintained by machinery). (3) **The roadmap joins the rendered pipeline** (follow-up slice): `ROADMAP.md` splits into a bounded hand-authored narrative core plus sections generated from the changelog fold history and `status.d/`, emitted by a `roadmap-build` assembler alongside `roadmap.json`. (4) **Public trackers are audience-filtered projections:** changelog (and later roadmap) fragments gain reserved `audience: public|internal` + `public-summary` frontmatter; assemblers emit machine-readable JSON (`changelog.json`, `roadmap.json`; `STATUS.json` exists) and the ADR-0048 product-updates surface consumes only the JSON — public output is a curated filter, never a raw dump. Design: `docs/specs/2026-07-14-docs-sync-routine-design.md`; operations: `docs/maintenance/README.md`. **Considered & rejected:** weekly-batch assembly inside the routine (the first draft — left the changelog up to a week stale and put deterministic work on an agent); direct agent pushes to `main` for the judgment half (breaches propose-only); a persistent self-continuing session (stale carried context; the repo-held registry is deliberately the only memory); status quo by discipline (the measured drift is the refutation). **Consequences:** the changelog/register/status render with every merge; roadmap narrative and coverage stay within one week with one review touchpoint; going public later is additive (one more consumer of existing JSON); costs are the workflow's push access to `main` (branch protection must allow the bot), building `roadmap-build`, and holding the propose-only line. Realizes **ADR-0058**; reuses **ADR-0104** (fragment workflow) and **ADR-0037** (living docs); feeds **ADR-0048**.
