**Pangram is wired as the first vendor behind `AiTextDetectionPort`, platform-managed: one platform key, a per-firm consent setting enforced at the chokepoint, and a dedicated per-firm usage-metering table.**

**Context:** The vendor-agnostic AI-Text Detection core shipped with a deferred adapter — the package was whole and testable but the tool did not actually detect anything. A concrete vendor was needed to make it work. Detection is an arms race between generators and detectors; an actively-maintained external vendor beats a static in-house model that goes stale.

**Decision:** (1) **Vendor.** Pangram is the first adapter behind `AiTextDetectionPort`, chosen for independent accuracy and zero-retention handling of submitted text. (2) **Credential model.** The platform holds one Pangram key (a Cloudflare secret); the adapter's capability descriptor declares `credential: { kind: "none" }`, so it resolves for every firm without the per-firm credentialed-adapter machinery (`firm_secret` store, connection repo, refresh lock) — that infrastructure is not built for this vendor. When no platform key is configured, the worker route falls back to the existing deferred adapter and refuses honestly rather than construct a dead call. (3) **Consent.** Sending firm text to Pangram is gated by a per-firm setting, `aiDetection.externalDetectionEnabled`, default `false`. The worker route is the single enforcement point: it reads the setting and refuses before constructing the adapter or making any provider call, so privileged text never egresses on an implicit yes. (4) **Metering.** Each successful detection writes one row to a dedicated per-firm `ai_detection_usage` table — word-native (Pangram bills by words, not tokens, so the existing inference token meter is the wrong shape; detection is matter-less, so the matter-costs system is also the wrong home). The row carries the requester, word count, mode, a derived cost snapshot, adapter/vendor provenance, and the result band. (5) **Deferred seams (not built):** a BYO-key credentialed adapter for firms that want to supply their own Pangram key; billing pass-through (a future decision reads the usage table's word counts); document text-extraction (this slice is paste-text-only); a bulk-detection endpoint; the UI (arrives with the design-system shell).

**Fitness tests:** the Pangram adapter's response mapping (score, provenance, segments, paraphrase-suspected signal) against recorded fixtures, routed through the existing normalizer so "signal, not proof" stays structural; the consent gate refuses before any adapter construction when the firm setting is off or unset; the missing-platform-key path returns the same honest refusal as the deferred adapter; the per-firm `ai_detection_usage` write is firm-scoped and one row per successful detection; `tools:aiTextDetection` seeded to all five default roles (migration `0034_seed-tools-ai-text-detection`).

**Builds on ADR-ai-text-detection-architecture** (vendor-agnostic core, `AiTextDetectionPort`, calibrated `DetectionReport`), **ADR-0101** (Tools area), **ADR-0091 / ADR-0092** (integration ports-and-adapters), **ADR-0109 / ADR-0110** (AI-inference client-consent and confidentiality posture).
