**The decision assembler validates every file it reads and fails the build on a malformed one, and the same validation is a governance gate on every pull request.**

**Context:** The register in `docs/Decision-Log.md` is generated from `docs/decisions/*.md`, and it is where almost everyone reads a decision. Four fragments were authored with a Markdown title where the frontmatter belongs. The reader looked for a `---` fence, did not find one, and returned a record whose status, date, and area were all empty strings with the entire fragment — title included — as the body. Nothing threw. The assembler rendered four bullets with two blank fields and the title standing in for the decision text, the assembly succeeded, and the damage merged. A generated document with no other store had degraded silently, and the only detector was a human reading the register.

**Decision:** Reading a decision file is now a validating operation. `parseAdrFile` throws on a missing opening or closing fence and on an unknown frontmatter line; `validateAdrRecord` reports every semantic problem in a file at once — empty `slug` / `status` / `area`, a status that does not begin with a lifecycle word, a `date` that is not `YYYY-MM-DD`, and register text that is empty or begins with `#`. The last check is the specific guard against this failure: the register bullet ends with the explicit `summary`, or the body's first line when there is none, so a body that opens with a title is exactly the shape that produced the degraded output. The assembler reads and validates the **whole pending set before numbering anything**, because folding a fragment consumes it and a failure discovered halfway through would leave a branch half-assembled. Already-numbered files are validated on every run too: they are generated output, but a corrupt one re-renders its damage on every future build. And the same validation is exposed as `pnpm run lint:decisions`, wired into the gate's governance job beside the status-fragment lint, so an author sees the problem on their own pull request rather than after their fragment has been consumed by a merge.

**Considered & rejected:** **Parsing the title-first shape leniently** — deriving the title from the `#` line and the status/date/area from the `**Status:**` lines the four fragments happened to carry. Rejected: it makes a second undocumented fragment format real and permanent, and it guesses at author intent for a document whose whole purpose is to record intent exactly. **Failing only at assembly time** — the assembler runs on `main` after merge, so the author is gone and the repair is a follow-up pull request against merged output; a gate on the author's own branch costs one job step. **Validating only pending fragments** — would have let the four already-numbered corrupt files keep rendering degraded bullets indefinitely, which is the state this repairs. **A schema library** — the frontmatter is five flat string keys read by a twenty-line parser with no dependencies, which the assemblers deliberately have none of.

**Consequences:** A malformed decision file now stops the assembly with a message naming the file and every problem in it, rather than producing a plausible-looking register. The register can no longer contain a bullet with blank fields or a heading in place of a decision — a corpus test walks every decision file and asserts it. The cost is that the assembler is now strict about files it previously tolerated: any future frontmatter key has to be added to the known set deliberately, which is the intended trade.
