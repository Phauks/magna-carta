**The gate's post-merge and whole-repo tiers are suspended for the duration of the Actions-minutes budget limit, with the merge bar carried by full local verification plus orchestrator review.**

**Context:** The account's GitHub Actions minutes reached their budget limit on 2026-08-05. The gate is a fan-out DAG that verifies the same change up to three times — on its pull request, on the push that merges it, and again on a nightly cold sweep — and the two later passes are, by construction, re-proofs of a tree the first pass already covered, plus the two things the pull request deliberately defers: the whole-repo type-check and the unbounded lint closure. The nightly sweep bills a cold whole-repo pass every night whether or not anything changed, and the whole-repo type-aware lint is a single ~45-minute job. Together those are where the minutes actually go, and they are the passes whose absence is recoverable rather than the one a human waits on.

**Decision:**

1. **Suspend the recurring and post-merge tiers, not the pull-request tier.** The `schedule` (nightly sweep) and `push` to `main` triggers on the gate are commented out, and the `ALL` branch of the lint job's scope switch is made a no-op. The `pull_request` tier keeps running the full battery — format, type-check, rust, the whole test suite, governance, contracts, containers — with the type-aware lint scoped to the changed packages plus one hop, exactly as before. `merge_group` and `workflow_dispatch` are untouched, so a merge queue would still be proved and the sweep remains runnable on demand.

2. **Keep the per-merge docs assembly running.** `assemble-docs.yml` costs a few runner-minutes and is what keeps `CHANGELOG.md`, the Decision-Log register, and `STATUS.md`/`STATUS.json` current the moment their fragments land. Suspending it would save little and let the rendered trackers rot, which is a documentation-currency cost paid back at a worse exchange rate later.

3. **The merge bar moves forward onto the branch.** Because the post-merge tiers no longer run, an agent runs **full local verification** before merging — the whole-repo `pnpm check` and `vp test`, not just the scoped inner-loop check — and states that result plainly in the pull request, with the **orchestrator reviewing** the change. A pull request that could not run the full local pass says so rather than implying a gate that did not happen. This is a deliberate trade of automation for stated human and agent accountability, and it is only acceptable because it is time-boxed.

4. **Mark every suspension identically.** Each edited site carries the literal marker `TEMPORARY CI AUSTERITY 2026-08-05 — revert when Actions minutes reset`, so restoring the posture is one `grep -r "TEMPORARY CI AUSTERITY"` rather than an archaeology exercise. The revert checklist lives with the CI cadence it belongs to, in `docs/conventions/build-performance.md`.

5. **Close the window with a real sweep.** When the minutes reset, the triggers are restored and one full whole-repo gate plus the sweep equivalent is dispatched on `main` before `main` is treated as gate-green again — the window's specific blind spots (a global input that would have forced a whole-repo lint, and two branches that merge in quick succession and interact semantically without touching the same files) are exactly what that run is for.

**Consequences:** Every change is still type-aware linted over the packages it can affect, type-checked whole-repo, and fully tested before it merges; nothing merges unverified. What is genuinely given up for the window is the unbounded dependent-walk lint, the whole-repo lint fallback that a global input or a lintable file outside every package would force, and the nightly interleaving backstop. None of that is a release risk on its own — `main` is not the deploy branch, and a deploy is a deliberate `git push origin main:release` — but that push should wait for the restored sweep, or accept that it is shipping on the pull-request tier alone. The suspension is temporary by construction: it is recorded here, marked in every file it touches, and has an explicit end condition.
