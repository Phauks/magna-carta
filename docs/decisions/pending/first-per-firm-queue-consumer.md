**The first consumer of the shared per-firm bus.** The outbox relay sweeps every active firm's per-firm outbox onto one bound queue, tagging each message with the originating `firmId`. Slice 3·3 needs to turn `shipment.purchased` into recovered matter disbursements, so it lands the first **per-firm queue consumer** — a topic dispatcher over `env.QUEUE` (queue **`magna-carta-production-platform-jobs`**), the symmetric analogue of the control-plane `CONSUMERS` map but keyed on **`message.topic`** rather than a control-plane job type. **Two-hop firm resolution:** the message carries a `firmId` (a control-plane id), not a database handle, so the dispatcher reads `database_identifier` from the control-plane `firm` registry, then resolves that identifier to the bound D1 database; a missing firm row, a null identifier, or an unreachable binding is acked and skipped (no work this deployment can do, and a retry cannot make the binding exist — the same shape as the files-ingest bucket→firm resolution; `.all()` + `results[0]`, never `.first()`). **ACK-AND-IGNORE on unknown topics — a deliberate divergence.** The control-plane sweep THROWS on an unregistered topic because it owns its whole closed topic set; this per-firm bus is OPEN — the relay carries `shipment.created`, `shipment.refunded`, and every future per-firm topic alongside `shipment.purchased`, but this consumer owns only cost recovery for `shipment.purchased`. Throwing would dead-letter or retry-storm messages it simply does not handle, so an unknown topic is acked and ignored with an observability counter rather than thrown. The shipping adapter maps `shipment.purchased` (postage + an optional handling fee, read back against the matter the shipment binds to) into `pass_through`/`platform_fee` recoverable-charge lines, which the consumer resolves against the firm's per-category recovery policy and commits as cost captures. **Idempotency has two floors, both keyed on the per-line `recoveryRef` `${shipmentId}:${category}`:** a `runIdempotentEffect` per line committed in the same atomic batch as the cost insert, and the `cost_entry` `recovery_ref` unique index in the database — so a queue redelivery (at-least-once) re-derives identical keys and posts no second row; a producer re-emitting a changed amount under the same ref surfaces as an observable fingerprint-mismatch rather than a silent overwrite, and a permanently malformed line is ack-dropped with telemetry rather than retry-stormed. **DEFERRALS, stated:** the wrangler `consumers` declaration that subscribes the Worker to `platform-jobs` is a **deploy-activation follow-up** — the `index.ts` dispatch branch is built but DORMANT in production until the queue is declared a consumer; and the producer-side **`cost.recorded` emission is deferred to 3·4** (nothing downstream consumes it yet). **Considered & rejected:** *reuse the control-plane throw-on-unknown* (rejected — wrong for an open multi-topic bus; it would dead-letter sibling topics); *a separate `message.id` dedup table* (rejected — the per-line `recoveryRef` is the natural idempotency key, so no extra table is needed). **Consequences:** the per-firm bus now has its first consumer and a reusable dispatch shape (add a row to the topic→handler map to own a new topic); going live requires the deferred wrangler declaration.
