**Container-backed subsystems extract to dedicated Workers (not modules in the app Worker).** **Decision:** a subsystem whose compute runs in a Cloudflare Container is deployed as its **own Worker**, reached from the app Worker by **service binding** (or, for a browser-fronted renderer, called back over its existing token-guarded HTTP surface) — never bundled into the main `magna-carta` Worker. The malware scanner set the precedent (`apps/scan-worker` → `magna-carta-scan`: its own Container DO, image, deploy/refresh cron, `max_instances`, no public surface, outbound disabled). The rubric a subsystem must clear: ① heavy native / Container runtime, ② independent deploy cadence, ③ distinct scaling profile, ④ containment / blast-radius (processes untrusted bytes), ⑤ **the Container compute holds zero firm state** (state stays behind the data-access layer / in a coordination DO in the app Worker). The split is along the **compute ↔ coordination seam**: the Container (stateless compute) extracts; the coordinating Durable Object and all firm-scoped data-access stay in the app Worker.

**Editing (slice 2·2) — extract.** coolwsd scores ① (heavy native, ~2 GB image) ② (Collabora security-patch cadence, own image rebuild) ③ (per-document, bursty, long-lived sessions — unlike the app Worker's request profile) ④ (renders untrusted documents). ⑤ holds **because the seam is already clean in the build**: the coolwsd Container holds no firm state — the working copy lives in R2, session state in the `DocumentSession` DO, and the editor reaches data **only** by calling back into the cookieless, token-guarded WOPI host (`/wopi/files/*`). Unlike scan (app Worker → container), the editing container is the **caller**, not the callee: the browser iframes coolwsd and coolwsd calls our WOPI host, so the container never appears in WOPI-host logic and nothing is interleaved. So: **extract the coolwsd Container compute into `magna-carta-edit`** (its own Container DO, deploy/scaling, warm-poke cron, no egress, no R2/D1 credentials — least-privilege per [[collabora-editing-host-topology]]), and **keep `DocumentSession` and the WOPI host in the app Worker** next to the document/file logic and data-access they serve (moving them would only push coupling across a network boundary). The only app→edit coupling is the editor URL (already a config seam, `editorDiscoveryUrlsrc`) and the warm-poke; no firm-scoped data crosses the binding.

**Timing:** decided **before the container is built** — the live Collabora Container (slice 2·2 Task 4) is gated on the measurement spike and unbuilt, `DocumentSession` is a plain `DurableObject` in the app Worker, and no Worker code invokes a container. Task 4 therefore builds coolwsd in `magna-carta-edit` from day one; retrofitting a Worker boundary after the container beds into `magna-carta` is the expensive path this ADR avoids.

**Family.** The same pattern governs **document conversion (slice 2·4)** — its LibreOffice/OCR/render containers extract on the same rubric (coordinate with that stream). **Tantivy full-text search is the exception:** its per-firm index is durable, firm-scoped *data*, so it fails ⑤ — search stays a stateful subsystem behind the data-access layer, not a stateless-compute Worker. **Rejected:** bundling coolwsd into `magna-carta` (couples Collabora's deploy cadence + blast-radius to the app, the exact coupling scan extraction removed); extracting `DocumentSession` too (it is coordination over firm data, not stateless compute — extraction would only relocate coupling). Builds on [[collabora-editing-host-topology]] (per-document container + DO + WOPI host) and the `apps/scan-worker` precedent; the scan worker (its `wrangler.jsonc` + warm-poke/refresh crons) is the template to copy at Task 4.
