**Collabora editing — WOPI host, per-document hosting topology, and access-token auth.** **Decision:** in-app `.docx` editing runs Collabora Online (coolwsd) in **one isolated Cloudflare Container per open document**, coordinated by a **per-document Durable Object** (`DocumentSession`, addressed by `fileId`, durable state in `ctx.storage` SQLite). We are the **WOPI host**, Collabora the client; the host is built to the **standard `X-WOPI-*` contract as the baseline** with Collabora's `X-COOL-WOPI-*` extensions **additive**, keeping both Word futures (Office-for-web client; desktop-Word check-out) reachable. WOPI callbacks are a **token-authenticated surface off the cookie chokepoint**: a short-lived HMAC-signed capability (per-firm-derived signing key + `kid`, `sessionId`-bound, constant-time verify) whose firm-scope **and** capability are **re-derived/re-checked at use on every callback** (a firm-A token against a firm-B `WOPISrc` → 404; a view token cannot `PutFile`/`Lock`, server-side, independent of the advisory CheckFileInfo flags). Near-instant revocation rides a sub-ms DO `member.status` check **scoped to genuine permission-change** (in-flight `PutFile` allowed to complete; routine expiry via `access_token_ttl`). coolwsd runs **least-privilege**: `enableInternet` stays **false** (untrusted document bytes get no general egress), no R2/D1 credentials or key material, ephemeral per document. It is still a WOPI *client* that must call the host, so the WOPI callbacks ride Cloudflare **container outbound interception** (`static outboundByHost`, GA 2026-03-26): coolwsd's `WOPISrc` targets a fixed internal host that the `DocumentEditorContainer` class intercepts and forwards to the app worker over an `APP_WORKER` **service binding**, entirely inside the Workers runtime — so the container reaches the token-authenticated WOPI host and nothing else (default-deny). All object I/O flows through that host. The editor iframe is served from a **dedicated cookieless origin** with a `postMessage` origin allow-list; the ADR-0029 preview-sandbox does not apply (a trusted derived renderer; raw bytes never reach the browser). Container liveness while a document is open is carried **natively by the editor's WebSocket** — `@cloudflare/containers` (≥0.3.7) counts an open WebSocket as an in-flight request and renews the activity timeout without any alarm or heartbeat (the historical WS-frame-doesn't-renew bug #147 no longer reproduces; verified in the measurement spike). We deliberately do **NOT** run an alarm-driven keep-alive: it is unnecessary and rides the still-open alarm-scheduler spinloop (PR #191). On disconnect the container sleeps after `sleepAfter` (tuned to minutes for reconnect tolerance) so provisioned-memory billing stops when no document is open; durable reconnect (state in DO SQLite + R2, version-cut-on-reap) keeps lost work at zero. See the measurement-spike findings folded into [[container-subsystems-extract-to-dedicated-workers]] (also: idle floor ≈ 1.16 GiB → a ~2–2.5 GiB custom instance, single pre-spawned kit). **Rejected:** pooled/shared coolwsd (one process serving many documents — blast-radius + cross-firm-in-one-process, owner red-flag; the ~$8–100/mo amortization does not justify it); a hand-rolled per-`fileId`-claimed warm pool (collides with `getContainer(binding, fileId)` keying — use native `min_instances` pre-warming instead); a second native CRDT/structured editor (ADR-0010, fidelity). Builds on ADR-0010 (editor choice), ADR-0067 (chokepoint), ADR-0066 (OpenAPI contract; WOPI routes via the conformance allow-list), ADR-0046 (key-versioning), ADR-0075 (resource naming), the security-conventions untrusted-file bar, and ADR-0029 (preview origin).
