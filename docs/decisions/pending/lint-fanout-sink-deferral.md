**The pull-request tier defers the repository's fan-out sinks to the post-merge tier, and the union of the two tiers is proved to cover the full dependent closure.**

**Context:** The gate's type-aware lint (`vp check --no-fmt`, oxlint + tsgolint) is CI's tall pole. It was already scoped to the affected packages, and the scope was already sound — the changed packages plus their dependents, because a type-aware finding in an unchanged file can flip when a dependency changes. It was still, on a measured pull-request run of 2026-08-05, **26 billable minutes of roughly 60 for the entire 17-job run: 43% of the bill**, and the [CI evaluation](../research/2026-08-05-cloudflare-ci-evaluation.md) established that no platform change touches that number. The cause is the dependency shape. `apps/worker` depends **directly** on 39 of the 61 workspace packages, so it enters the affected set for almost any foundational change; and linting it is not one package's worth of work, because the type-aware linter builds its type program from the passed files' import closure, which for the worker is 1,261 of the repository's 1,669 lintable files.

Two candidate refinements were measured and rejected before this one. **File-granular scoping** — the changed files plus the transitive reverse-import closure over the repository's own module graph, resolved with the TypeScript resolver — is sound in principle and buys almost nothing here: for 37 of the worker's 38 package dependencies it still reaches 70–80% of the worker's 394 files, because `apps/worker/src/app.ts` mounts every route and 157 files import it. It would have added a module-resolution graph, whose failure mode is silent under-linting, for roughly a quarter off the worst case. **Content-hash caching of a package's lint result** misses precisely when it is needed: the cache key must cover the package's dependency closure, and a foundational change is by definition a change inside that closure.

**Decision:**

1. **Bound the scope by cost, not by distance.** A package's **type-program weight** is the count of lintable files in its transitive _dependency_ closure — itself plus everything it imports. That is the direction the linter reads, and it is what makes one package's lint two seconds and another's half an hour. A package is a **fan-out sink** when its weight is at least half of the workspace's lintable files. The threshold is a share rather than a file count so it scales with the repository instead of needing re-tuning; measured 2026-08-05 it selects exactly `@magna-carta/worker` at 75.6%, against 33.0% for the next package and a 2% median.

2. **Defer sinks that are in scope only as dependents, on the pull-request tier only.** `--defer-fanout-sinks` drops them; every other trigger passes no such flag and lints them. A sink the change itself touched is **never** deferred — an author's own code is always linted on their own pull request.

3. **Retire the one-hop depth cap as the pull-request tier's cost lever.** Every trigger now walks the full closure. Depth was a proxy for cost and it mis-measured cost on this graph: the expensive package sits one hop from nearly everything, so the cap paid full price while narrowing coverage everywhere it was cheap. `--max-hops` remains supported and tested; the gate no longer uses it.

4. **Prove the union rather than argue it.** `tooling/affected-lint/scope-fitness.mjs` (`pnpm run lint:affected-scope`, in the gate's `governance` job) simulates a change to **every** workspace package and asserts that the changed package is in its own pull-request scope, that the pull-request and post-merge scopes together contain the package's full transitive dependent closure, and that nothing but a declared sink is ever dropped. It derives that closure by an independent fixpoint over the same package graph the classifier reads — one source of truth, two algorithms, so a mistake surfaces as a disagreement rather than as two copies of itself. It also fails if the sink rule stops behaving like an outlier rule: no sink selected, more than two selected, or a selected sink weighing under 1.5x the heaviest non-sink.

5. **Read the test-shard breadth signal from the undeferred closure.** The shard heuristic asks "how broad is this change", which deferral does not answer; reading the narrowed scope there would call a foundational change small and quietly halve the test parallelism.

**Consequences:** A broad pull request's lint job drops from the whole worker's type program to the cheap remainder of the closure. Measured locally on a 4-core/15 GB box for a change to `@magna-carta/identifiers`: `apps/worker` alone is **2,755 s** (394 files), and the entire new 28-package pull-request scope is **9 s** (883 files). The cost is not removed, it moves to the tier that runs once per merged change rather than once per push; over a measured 19-day window that is 137 pull-request gate runs against 52 branches, so the sink's lint is paid 52 times instead of 137. What is genuinely traded is latency of a specific signal: a type-aware finding that a change flips inside a sink now surfaces on the merge push or the nightly sweep rather than on the pull request. Its blast radius is one type-aware lint rule — type-checking, the test battery and the contract checks are never scoped and still run whole-repo on every pull request — and it always lands before a deliberate `git push origin main:release` can turn anything into a deploy.

While the `TEMPORARY CI AUSTERITY 2026-08-05` window suspends the post-merge tier, the deferred sink is covered by that window's own merge bar, which already requires a full local `pnpm check` — a whole-repo lint, sinks included — before a merge. This decision does not restore, extend, or otherwise alter any suspension.

This is explicitly an interim shape. The real fix remains breaking the app worker's direct dependence on nearly every foundational package, which is carried in `docs/conventions/build-performance.md`. When that lands, the sink rule will select nothing, `lint:affected-scope` will fail, and that failure is the signal to delete the flag — never to widen the threshold.
