summary: Cut GitHub Actions billed minutes on the CI gate by deferring the ~24-min whole-repo type-aware lint to a daily scheduled sweep (PRs lint only their package closure), dropping the redundant full gate re-run on merge to `main`, and classifying the auto-generated docs-assembly commit as docs-only. Requires require-up-to-date-before-merge on `main` to preserve merge safety.
---

**The CI gate is restructured to cut GitHub Actions billed minutes, which were pressing against the 3,000-min/month ceiling.** **Context:** measured from the live run history, a full PR `gate` run was **~57 billed minutes across a ~15-job fan-out** (GitHub bills per job, rounded up to the whole minute). The single **whole-repo type-aware `lint` job was ~26 of those minutes** — tsgolint is single-threaded, whole-program, with no cross-run cache upstream, so it is CI's tall pole. And the gate ran that ~57-minute sweep **~2.5 times per merged PR**: once on the PR, again on the `push: main` merge commit, and a third time on the `docs-assembly` branch the fragment-assembler dispatches — the third run executing the full worker/typecheck/story suite (~32 min) to re-test code the assembly commit never changed. **Decision (three changes):**

1. **Defer the whole-repo lint off the per-change critical path.** `tooling/affected-lint` gains a **`--defer-global`** mode, which the gate's `changes` job now uses. Previously a change to a global input (the lockfile, root config, `tsconfig.base.json`, `.github/`, or a lintable source outside every workspace package) escalated the lint job to the ~24-min whole-repo pass. With `--defer-global` that escalation is **deferred to a new daily sweep** (`.github/workflows/nightly-sweep.yml`, `vp check --no-fmt` unscoped) instead. The change's **own package closure is still linted on its PR** (soundness for the touched code is unchanged); only the repo-wide re-verification — a global input flipping a rule in an **untouched** package — waits for the sweep, which re-runs it within a day. Everything else the gate scopes-or-shards is unaffected: type-check, tests, contracts, and governance still run whole-repo on every PR.

2. **Drop the redundant full gate on merge to `main`.** The gate's `on:` loses `push: [main]`; it runs on the PR (and the `workflow_dispatch` the docs assembler needs) only. The PR gate already proved the merge result, so the push-time run re-confirmed what was already true. To keep this safe, **`main`'s greenness now rests on the required PR gate plus "require branches up to date before merging"** (or a merge queue) — so the merge commit is exactly what the gate ran on — backed by the daily whole-repo lint sweep. **This is an owed operator setting:** the `main` ruleset must require up-to-date branches (or enable a merge queue); without it, two individually-green PRs merged against a stale base could land a combination `main` was never tested on.

3. **Classify the fragment-assembly commit as docs-only.** The assemblers emit only markdown (`CHANGELOG.md`, `STATUS.md`, `docs/Decision-Log.md`, `docs/decisions/NNNN-*.md`) plus the one non-markdown output `STATUS.json`, which branches never edit by hand (it is assembled on `main`). The `changes` `code` filter now exempts `STATUS.json` alongside markdown, so the `docs-assembly` gate runs **format + governance** instead of the full suite (~32 min → ~4). The exemption is exact (`^STATUS.json$`) and only ever matches the auto-generated assembly commit.

**Consequences.** Per merged PR, CI drops from ~2.5 full gate runs to one, the ~26-min whole-repo lint moves from every PR/merge to once a day, and the docs-assembly tax nearly vanishes — a large cut in billed minutes. The cost: a repo-wide type-aware lint regression from a global-input change is caught by the daily sweep rather than at merge (the touched code is still linted on its PR), and merge safety now depends on the require-up-to-date ruleset rather than a belt-and-suspenders push-time gate. The sweep restores the same wasm cache the gate builds; its first run after a Rust change on `main` pays one cold Docker wasm build (~7 min), then hits cache. Sweep cadence (daily) and the option to widen it to a full nightly gate are tunable if repo-wide regressions start slipping to merge. **Considered & rejected:** keeping `push: main` but running only the whole-repo lint on it (still pays the tall pole on every merge — merges are frequent); a nightly *full* gate (~57 min/night ≈ half the monthly budget, defeating the saving); reducing test shard counts (small saving, trades wall-clock, and the user opted to keep current sharding). Realizes the build-performance standard's "scope the whole-repo sweep; keep the inner loop fast" principle at the CI tier — home: [`docs/conventions/build-performance.md`](../conventions/build-performance.md).
