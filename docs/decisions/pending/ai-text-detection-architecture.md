**AI-text detection ships as a vendor-agnostic core on the integration ports-and-adapters framework; the result is a calibrated likelihood band with structured caveats (never a boolean verdict); external detection is opt-in and off by default; no concrete vendor is wired yet.**

**Context:** A lawyer needs to ask whether a document was written by a person or generated — of an opponent's filing, a client's submission, or their own work product before filing. Every AI-text detector available today is unreliable enough that, in a legal or evidentiary context, its output cannot be presented as proof: accuracy collapses on short, edited/paraphrased, and non-native-English text; independent benchmarks contradict each other on which tool leads; false positives have caused real-world harm. The most actively-maintained, accurate detectors are external commercial services, so the owner chose an external-vendor engine over a static in-house model that loses the arms race — which makes confidentiality (sending privileged content out) the governing concern.

**Decision:** (1) Detection is a credentialed, request/response capability modelled on the existing integration ports-and-adapters framework as the `ai-detection` category — our `AiTextDetectionPort.detect` returns a typed `Dispatch<DetectionReport>`, never a throw; each vendor is one swappable adapter behind it. (2) "Signal, not proof" is structural: `DetectionReport` cannot express a bare boolean verdict — its headline is a coarse `LikelihoodBand` (`unlikely`/`mixed`/`likely`/`inconclusive`) plus a `reliability` grade and structured `caveats` computed by our own normalizer from input characteristics (length, language, vendor-confidence, paraphrase/mixed-authorship signals), independent of the vendor's claimed confidence; a low-reliability result is forced to `inconclusive` so it never asserts a direction. (3) Sending privileged content to a third-party detector inherits the AI-inference confidentiality posture — an opt-in firm policy, off by default, with recorded consent; the report carries egress provenance. (4) No concrete vendor is registered in this build: the `ai-detection` category ships with a single deferred adapter returning `not-connected`, so the package is whole and testable with zero vendor wired; the concrete vendor adapter + its credential scope are a follow-on decision.

**Fitness tests:** package purity (only relative + allowed workspace type imports); manifest well-formedness for the `ai-detection` category; the normalizer's band/caveat/reliability logic including the low-reliability→inconclusive override and the moderate-path negative; the deferred adapter's `not-connected` Dispatch contract.

**Builds on ADR-0101** (Tools area), **ADR-0091 / ADR-0092** (integration ports-and-adapters), **ADR-0109 / ADR-0110** (AI-inference client-consent and confidentiality posture). Spec: [`docs/specs/2026-06-28-ai-text-detection-design.md`](../specs/2026-06-28-ai-text-detection-design.md).
