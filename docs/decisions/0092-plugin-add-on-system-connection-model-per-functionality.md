**Connection model, per-functionality scoping & credential seam — connection identity splits into provider-config (the adapter's first-party app/OAuth registration; one per adapter, Worker secrets, not per-firm) vs grant (one authorized account, recorded per-firm in `integration_connection`, handle `integrationConnection_…`); _scope is declared by the port_ — `firm` or `user` — not a global default, so a user-scoped port (calendar/email: each attorney authorizes their own account, the ethical-wall-correct answer) keys on `{firmId, userId}` and a firm-scoped port (e.g. firm accounting) keys on `{firmId}`; each connection carries a health state machine `connected | degraded | needs_reauth | disabled` driven from dispatch outcomes plus a capability snapshot; the `CredentialStore` is a framework interface whose real backing is slice 1·2's per-firm envelope-encrypted `firm_secret` store (`getSecret`/`putSecret`, ADR-0084); token refresh is framework-owned and serialized by a Durable-Object-per-credential lock (providers silently rotate refresh tokens — concurrent refreshes race), surfacing `invalid_grant` as `needs_reauth` after one retry, never a silent loop.** **Context:** the white paper said "per-firm scoped secrets" blanket, but research (2026-06-16) confirmed calendar/email connections are per-user in practice (and for ethical walls), while other categories are firm-wide — so scoping must be a per-port property. Storing OAuth refresh tokens is exactly the envelope-encryption job ADR-0084 already specified (it names "plugin credentials" as an encrypted-unindexed protected payload), so the credential store is that store, not a new mechanism — which makes _live credentialed_ adapters gate on slice 1·2 while the framework and its credential-less proof adapter do not. **Considered & rejected:** a single global per-firm (or per-user) scope (wrong for half the categories); a bespoke credential store separate from `firm_secret` (duplicates ADR-0084's envelope/AAD/shred machinery); per-adapter token refresh (each adapter reinventing the rotation race inconsistently — the framework owns it with a single-writer DO lock). **Consequences:** corrects the white-paper _Plugin / Add-on system_ wording (per-functionality scoping, not blanket per-firm); credentials inherit ADR-0084's per-firm isolation + crypto-shred for free; the OAuth/refresh machinery is designed here and built with the first credentialed adapter (gated on 1·2 + the Google CASA / Microsoft verification compliance review). Builds on **ADR-0091** (the framework), **ADR-0026/0084** (the credential store), **ADR-0003** (per-firm isolation), **ADR-0068** (decrypt/manage-secrets permissions), **ADR-0039** (the DO refresh lock).
