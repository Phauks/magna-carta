**Property external-links are a pure, registry-driven, credential-less utility (`@magna-carta/property-links`), distinct from credentialed property _data_: a `LinkProvider` registry + a total `resolvePropertyLinks(reference) → PropertyLink[]` that turns a property reference (address; optionally APN/jurisdiction) into the external "view this property on X" links available for it. Zillow and Redfin are the first two providers; Google Maps/Realtor/Trulia and a county-assessor provider wrapping `@magna-carta/parcels` are one-row seams. Delivered as plain `https` hyperlinks (Universal/App Links open the native app when installed, else the website — no custom `zillow://`/`redfin://` schemes).** **Context:** the owner wants one-click property lookups (reduce clicks, increase access to information). Load-bearing constraint: **Zillow retired its public API (~2021) and Redfin has none; scraping violates ToS** — so for these services the deep-link is the ceiling (no Zestimate/listing/ownership/history programmatically). That richer data is a _separate, credentialed_ concern (ATTOM/Regrid/HouseCanary — [`docs/research/property-data-integrations.md`](research/property-data-integrations.md)) behind the integration framework's future credentialed adapters, which Zillow/Redfin cannot feed. This package is the **external-links half**, mirroring `@magna-carta/parcels` (the county-assessor deep-link resolver — the same capability, folded in via the assessor provider seam). **Decision:** a built-in pure utility, not a framework adapter (white-paper build-in-vs-plugin rule: "pure utilities are libraries, not plugins") — a credential-less framework-adapter wrapper behind a `propertyExternalLinks` port (the `parcels`-as-adapter precedent, ADR-0091) stays a named seam. URL construction only; the anchor attributes (`target="_blank" rel="noopener noreferrer"`) and buttons are the consuming UI's concern, gated on the Locations UI. **Considered & rejected:** wiring through the integration registry now (heavier — registry resolve + firm context — for a pure URL builder with no credentials, and the one-adapter-per-category model can't express "show all providers at once"); custom URL schemes (undocumented, fragile, no web fallback); a Zillow/Redfin-only widget (the unified external-links concept absorbs Maps/Realtor and the existing assessor link, surfacing anywhere an address lives — Location now, Directory property entity / matter subject-property later); pulling listing/valuation data from Zillow/Redfin (no API; ToS). **Consequences:** one-click external lookups at near-zero cost with a clean growth path (more providers, more surfaces, keyed by more identifiers); the credentialed property-data subsystem stays cleanly separate. Mirrors the `parcels` pattern; relates to **ADR-0091** (optional adapter seam), **ADR-0031** (Location address), **ADR-0040** (future per-firm provider config).
