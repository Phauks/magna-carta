**The neutral refusal stops being a discipline each route keeps and becomes a fitness function every anonymous surface passes.**

**Context:** Invitation redemption's refusal was recently made structural — the three proving facts share one stored digest so the handler cannot know which was wrong, the comparison runs against an unmatchable value when no row is found, one balancing write runs on every refusal so the timing does not differ, the refusal is built in exactly one function, and the attempt count in it is the caller's own rather than the invitation's. The sweep that followed found the pattern generalises. Four new methods multiply the anonymous failure paths several-fold, and each arrives with its own protocol-shaped temptation to be helpful: a WebAuthn allow-list, a "no account with that address" from a magic-link request, a relayed identity-provider error, a portal that shows which firms know you.

**Decision:** Four checks bind every refusal on an unauthenticated surface. (1) **One refusal per surface, built in exactly one function**, with nothing row-derived in it. (2) **Any number in it is the caller's own** — never a count belonging to the thing being probed. (3) **The work does not vary with what was found** — the unmatchable-digest comparison, the balancing write, the same hashes on every path. (4) **The difference goes to the channel, not to the caller** — where there is something to say, it is said in mail to the address in question. A fitness function, `lint:refusal-neutrality`, modelled on the shipped conflicts-vocabulary and custodian-vocabulary lints, asserts that every handler reachable from a `surface: "public"` route touches at most one refusal-constructing call site and that no refusal constructor takes an argument derived from a database read. It cannot prove neutrality; it can prove that a **second construction site** was added, which is precisely how a neutral answer stops being neutral. Per method the specific oracle is closed by **shape** rather than by care: a passkey sign-in uses a **discoverable** assertion with an empty `allowCredentials` and takes **no address**, because an allow-list for a typed address publishes how many passkeys that address holds and their credential identifiers, and registration options are minted only for an authenticated session; a link request answers the same body in the same time for an unknown address, a known one and a federated domain; an identity provider's own errors are never relayed, and an assertion the platform will not accept produces the platform's one neutral sentence; and which firms hold grants for a portal address is rendered only after authentication.

**Considered & rejected:** _leaving it as a reviewed discipline_ (it has already failed once per surface built, and four methods is four more chances); _a source scan for banned wording_ (the defect is structural, not lexical — the invitation refusal read perfectly and still carried the invitation's own count); _proving neutrality mechanically_ (undecidable in general; the achievable property is "there is one construction site and it is fed nothing from a row", which catches the real regression); _supplying `allowCredentials` for a typed address to improve the passkey prompt_ (it is the enumeration oracle in protocol form, and the discoverable flow is the better interaction anyway — no address to type); _relaying the identity provider's error to help the visitor_ (the provider's vocabulary is not the platform's, and its errors distinguish exactly the cases this posture exists to collapse).

**Consequences:** The two shipped references — `neutralRedemptionRefusal` and the registration address-in-use branch — must pass unchanged, and are the gate's own regression fixtures. Every method's slice carries an enumeration test asserting byte-identical answers across the found and not-found cases. Builds on **ADR-0280** and `ADR-invitation-refusal-reports-only-the-caller-budget` (the posture this generalises), **ADR-0051** (coherence fitness functions as the enforcement idiom), **ADR-0068** (the reserved absent answer).
