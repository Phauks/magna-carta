`STATUS.md` was the last hand-edited shared tracking file — a single column-aligned Markdown table that every worktree edited on every slice. Three properties compounded into recurring merge pain: the formatter (oxfmt) re-pads the whole table on any cell-width change, so a one-word note edit diffs as "all rows changed"; one physical line per slice means two branches editing a slice's row is a direct line-level conflict; and the "edit only your own row" discipline could not hold against either. Decision: make `STATUS.md` a **build output** assembled from per-slice fragments — `status.d/<slice>.md`, flat frontmatter (stage tokens + dev fields) plus a one-line note — by `vp run status-build`, extending the fragment workflow already proven by `changelog.d/` → `CHANGELOG.md` (ADR-0104) and the ADR register (ADR-0105). Two deliberate departures from the changelog model: (1) status fragments are **persistent, not consume-once** — a slice's status keeps moving across the pipeline, so the build re-renders the whole file from the current set every run and never deletes a fragment (this follows `decisions-build`'s render-from-persistent shape, not `changelog-build`'s fold-and-delete); (2) the build also emits `STATUS.json`, a machine-readable index carrying each slice's structured stages plus development fields (next action, branch, spec/plan/ADR links) so an agent resuming a slice reads data instead of parsing a padded table. Generated tables are emitted width-independent (no padding to column max-width) to kill the re-pad churn, and `STATUS.md`/`STATUS.json` are formatter-ignored and CI-drift-gated (`git diff --exit-code` after a rebuild) like the OpenAPI snapshot; a `pnpm run lint:status` fitness function validates the fragment set (schema, unique slot, link existence). Rejected: keeping a single hand-edited file with a tighter discipline (the formatter defeats it); a machine-first single data file (re-introduces the single-file collision); rendering per-slice blocks instead of the matrix (loses the one-screen overview for no collision benefit).
