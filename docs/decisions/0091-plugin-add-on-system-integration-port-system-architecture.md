**Integration port-system architecture & contract — the ports-and-adapters foundation in one pure `@magna-carta/integrations` package: a typed category _port_ (interface in our domain vocabulary, not a vendor's); _adapters_ implementing it; a _capability descriptor_ per adapter so callers degrade gracefully; a canonical-model contract (normalized record per category + vendor-native `remoteId` + opt-in untouched `raw` + zod-validated boundary + two passthrough tiers + additive-only versioning); a registry resolving `{firm, principal, category} → adapter` with a typed `Dispatch` sum (`not-connected` / `capability-unsupported` / `adapter-error`, never a bare throw); RFC 9457 problems extended with `retryable`/`category`; and framework-owned cross-cutting machinery (retry/backoff, circuit breaking, idempotency, rate-limit, redaction) behind interfaces, thin now. Isolation = in-process first-party modules now, with the in-process → service-binding/Worker-RPC → Workers-for-Platforms split as the documented, contract-stable marketplace seam. Proven by retrofitting the credential-less `parcels` resolver as the first adapter behind a `ParcelLookupPort` (zero procurement, zero slice-1·2 dependency); the same port later carries credentialed vendor adapters (Regrid/ATTOM) — one port, many adapters across the credential boundary.** **Context:** integrations are the highest-leverage parallel-to-UI backend work, and ADR-0015 fixed only the posture (uniform plugin model, Worker-per-integration behind typed ports). Owner reframing (2026-06-16): integrations _now_ are first-party features Magna Carta builds that reach out to external platforms — not outside vendors providing services, not actors bringing credentialed services in (those are seams, not built). Five-stream research (2026-06-16) found strong industry convergence (Merge/Apideck/Nylas/Cronofy/Paragon/Finch) on the canonical-model + `remoteId` + raw + passthrough + capability-descriptor + additive-versioning shape, which also matches the house code-as-contract style (ADR-0022). **Considered & rejected:** separate deployed Worker per integration _now_ (per-integration deploy/scaffold overhead before a marketplace justifies it — deferred to the seam); pure TS interfaces with no runtime boundary validation (external data is untrusted; cheap zod validation guards the domain and sets the marketplace seam); schema-first generated contracts (only worth it for third-party authors who don't exist yet); forcing every pure utility behind a port (the white paper's "pure utilities are libraries, not plugins" stands — `parcels` becomes an adapter because its port will carry credentialed siblings, not as dogma). **Consequences:** a real, tested integration framework lands parallel to the UI track with no gate on unlanded slices; calendar is the first _credentialed_ adapter, designed at the seam level and built later (ADR-0092, §11 of the spec); the connection table joins the load harness when that adapter lands (accretion rule, ADR-0083). Concretizes **ADR-0015**; builds on **ADR-0022** (code-as-contract), **ADR-0039** (async-capable dispatch / compute placement), **ADR-0071** (package seam), the RFC 9457 problem module (ADR-0066).
