**WHOIS lookups resolve via RDAP-first (IANA bootstrap → authoritative base URL → structured JSON), with a legacy port-43 TCP socket fallback for ccTLDs that have no RDAP entry; no third-party WHOIS vendor is used.** Builds on the shared SSRF guard (see `outbound-fetch-ssrf-guard-invariant`) and the integration framework's http transport seam.

**Context.** Domain and IP registration data is available via two public mechanisms: **RDAP** (Registration Data Access Protocol — HTTP/JSON, structured, standardised by RFC 7480–7484, with an IANA-maintained bootstrap registry mapping TLDs and IP blocks to their authoritative base URL) and the legacy **port-43 WHOIS** protocol (free-form text, TCP, one format per registry with no standard schema). RDAP is the current standard and is available for all major gTLDs (`.com`, `.net`, `.org`, etc.); many ccTLDs (country-code TLDs) have not yet published an RDAP server in the IANA bootstrap. A third-party WHOIS aggregator service could provide a single API covering both, at the cost of introducing a vendor dependency and routing investigation subjects through a third party's infrastructure.

**Decision.** (1) **RDAP first.** Look up the target TLD or IP block in the IANA bootstrap files (`https://data.iana.org/rdap/dns.json`, `/ipv4.json`, `/ipv6.json`) to resolve the authoritative RDAP base URL, then fetch the structured record. Parse the JSON response into a typed result: registrar, registration/expiry/last-changed dates, nameservers, status codes, and registrant entity (where the registry publishes it). RDAP is fetched directly from the Worker — no third-party vendor. (2) **Port-43 fallback.** When the IANA bootstrap returns no RDAP entry for a TLD, fall back to a direct TCP socket via Workers' `connect()` from `cloudflare:sockets` to the TLD's known WHOIS host on port 43. Return the raw text, clearly labelled as *unparsed legacy WHOIS* — the long tail of free-form ccTLD WHOIS formats is not parsed. (3) **No third-party WHOIS vendor.** The investigation subject (the domain or IP being looked up) is sensitive context; routing it through a third-party service introduces a data-handling dependency with no commensurate benefit. RDAP + port-43 cover the full range of public registries directly. (4) **Input normalisation and SSRF guard.** The input (bare domain, extracted host from a URL, or IP address) is normalised and passed through `assertPublicTarget` before any outbound work.

**Consequences.** Registration data for all major TLDs returns as a structured, typed result. ccTLDs without RDAP return labelled raw text — acceptable for the hygiene use case. No vendor dependency or procurement step is needed. A short-TTL KV cache keyed by normalised target would reduce load on public registries and is a noted future optimisation, not built in the first iteration. The `source` field on the response (`"rdap"` or `"whois-43"`) lets the UI label parsed vs. raw results appropriately.
