**Schema migration & the database fleet — Drizzle + drizzle-kit as the single TS source of truth for types and migrations (under the firm-scoped DAL); a Cron-Workflow rollout orchestrator across the per-firm-D1 fleet with control-plane version tracking, per-firm failure isolation, eager + lazy application, and expand-contract zero-downtime discipline; built now though one firm runs as a fleet of one.** **Context:** one firm = one D1 (ADR-0003), so schema evolution is a distributed fleet operation across thousands of databases + the control-plane D1, not a single migration ("add a column" = thousands of tracked `ALTER TABLE`s with a mixed-version window); Better Auth already constrained the query layer to a Drizzle or Kysely adapter (ADR-0004); Cloudflare's guidance is explicit — "build this [fleet migration] tooling before you need it." The heaviest §9 member. **Decision:** (1) **Tooling = Drizzle ORM + drizzle-kit** — schema defined once in TypeScript is the single source of truth for **both** the DAL's generated types **and** the migrations (`drizzle-kit generate` from schema diffs), so types and migrations never drift (the Kysely failure mode where they are separate); Drizzle sits **under** the firm-scoped DAL, which still owns firm-scoping/`protected()`/audit/outbox/idempotency; two independently-versioned lineages (control-plane, per-firm). (2) **Fleet state in the control-plane** — each per-firm D1 records applied migrations; the **firm registry (ADR-0003) mirrors each firm's schema version** (it already tracks which DBs exist / which firm they serve — version is one more column), giving the fleet-wide visibility Cloudflare requires. (3) **Rollout orchestrator** — a **Cron-triggered Workflow** iterating firms (the recurring fleet-fan-out primitive shared with ADR-0050 backups and ADR-0064 outbox relay): applies pending migrations per firm, updates the registry version, with **bounded concurrency, per-firm failure isolation** (a failed firm quarantined + alerted to observability ADR-0038, the fleet continues), **idempotent/resumable** application (current firms skipped), and a migration-state report. (4) **Eager + lazy** — active firms migrate in the fan-out; **dormant firms catch up lazily on next access** (the DAL applies pending migrations on connect) — Cloudflare's "migrate active tenants, dormant ones when they return"; lazy is a clean seam over the eager floor. (5) **Expand-contract discipline** (zero-downtime, the part that makes a non-atomic fleet safe) — every migration backward-compatible with deployed code, ordered _expand → deploy tolerant code → backfill → contract_, so running code never meets an incompatible schema; a fitness function (ADR-0051) flags a destructive change (DROP COLUMN, NOT-NULL-without-default) shipped with the same release as the code that needs it. (6) **Provisioning & safety nets** — a new firm's DB is created at the current schema (runner's "v0 → apply all"); per-DB **Time Travel** (ADR-0050) is the instant-PITR net; migrations tested against the **load-profile fixtures** (ADR-0034) + dry-run in CI; restore drills (ADR-0050) exercise the path; control-plane migrations apply first. **Built now as a seam** — single-firm today exercises the same runner as a fleet of one (ADR-0003: the fan-out is the only real cost of per-firm isolation, cheaper before firm #2). **Considered & rejected:** **Kysely + manual migrations** (type/migration drift — "nasty bugs"; no schema-diff generation); **raw SQL + Wrangler d1 migrations** (no type-safety, hand-written types and migrations separately; Wrangler's per-DB apply isn't fleet-aware); **a heavy ORM** (Drizzle is SQL-first/lightweight with raw escape hatches, fits the control-first stance); **per-DB manual migration / no orchestrator** (unmanageable past a handful of firms — Cloudflare's explicit warning); **deferring the tooling until multi-firm** (Cloudflare's "build before you need it"; retrofitting fleet migration mid-flight is far costlier). **Consequences:** schema evolves safely across the fleet with drift-free types, visibility, failure isolation, and zero-downtime; cost is building the orchestrator now (exercised on one firm) and holding expand-contract discipline. Reuses **ADR-0003** (tenancy/registry), **ADR-0050** (Cron-Workflow fan-out + Time Travel), **ADR-0034** (fixtures), **ADR-0051** (fitness function), **ADR-0004** (Better Auth adapter); underpins every per-firm schema in the platform. Implementation detail in the _Foundational data conventions_ spec.
