**The typecheck of record covers test files, through a second non-emitting project per package rather than a widened build project.**

**Context:** The reference graph's member projects are `composite` + `emitDeclarationOnly` with `rootDir: "src"`, so their `include` is src-only — a file outside `rootDir` cannot take part in that emit. All 71 members list `test/**/*.ts` in their own `tsconfig.json` and the generated build config replaces that `include` rather than extending it, so the 885 test files beside the 1,233 source files were type-checked by nothing: `vp check` runs with `lint.options.typeCheck: false`, and Vitest strips types rather than checking them. A test file could carry a genuine type error indefinitely with every gate green, and the errors that had accumulated were not exotica — a database double missing a method the real interface declares, fixture literals that had lost fields the production types gained, a round-trip test that had silently stopped covering a policy field.

**Decision:** `tooling/tsconfig-refs` emits a **`tsconfig.test.json` per member** alongside the build project. It is `composite`, because a solution file can only reference composite projects, and `noEmit`, because nothing consumes a test — that pair is what frees it from the `rootDir` constraint. It references the package's **own** build project first and then the same dependency build projects, so `../src/thing.ts` and `@magna-carta/thing` both resolve to declarations `tsc -b` has already produced and no source is checked twice. Its `include` is **derived, never restated**: the package's own `include` minus `src/**` and minus `.svelte`, plus the ambient `.d.ts` from the package root and from `src/` (declaration files emit nothing, so listing them in both projects is free, and without them a test's `.wasm` or `cloudflare:test` import fails as TS2307). The invariant that falls out — the two generated projects together cover exactly what the package's own `tsconfig.json` declares — needs no new gate, because the existing `node tooling/tsconfig-refs/index.mjs --check` diff-gates both files. A second root solution `tsconfig.test.json` collects the members, and `vp run typecheck` becomes `tsc -b tsconfig.build.json tsconfig.test.json`. The 53 errors this surfaced are fixed at the seam each names; none is silenced with `any`, `@ts-expect-error`, or a widened production type. **`@magna-carta/worker` is deferred**: it keeps its generated test project and is checkable on demand, but is held out of the root solution by a named list, for two measured reasons — one of its test files does not type-check in 600 seconds on its own, and the other 234 report 156 errors (89 of them one repeated unchecked `await response.json()`).

**Considered & rejected:** _widening the build project's `include` to `test/`_ (gives up the declaration emit that makes the graph incremental; the `rootDir` error is not negotiable); _dropping `composite` on the test projects_ (then no solution file can reference them, and `vp run typecheck` becomes 71 command-line paths); _hand-writing 71 `tsconfig.test.json` files_ (the generator owns every other config in the graph and the `--check` gate only holds what the generator produces); _restating each package's test include in the generator_ (a second home for a fact the package's own `tsconfig.json` already states, which would drift the first time a package added a directory); _turning the graph on without the burn-down_ (`main` red by dozens of errors at once); _batching `apps/worker`'s tests in the gate to work around its cost_ (hides the fan-out that causes it behind machinery, and the fan-out is already the tracked structural fix); _raising the shipped `SqlStatement`/`ConflictsPolicy`/`StatuspageSummary` types to admit the fixtures that failed_ (the fixtures were wrong and the types were right — that is the whole value of checking them).

**Consequences:** A test that does not type-check now fails `pnpm check`, `pnpm check:scoped`, and the CI gate, so the discipline in [`typescript.md`](../conventions/typescript.md) — fix the seam, never silence it — is enforced rather than advised. Cost is small and incremental: cold, both roots are 1 min 53 s against 1 min 32 s for the build half alone, and warm the pair is 1.1 s against 1.0 s, so `check:scoped` keeps the whole graph and pays nothing on the common path; the gate's existing `.tsbuild` cache already covers the new `.tsbuildinfo`. Two packages had to declare what they actually contain rather than being cast past — `@magna-carta/product-updates` lists the `tooling/doc-fragments/*.mjs` its corpus test imports (a composite project must list every file in its program) and turns on `allowJs`, and `apps/status-worker` gained the `worker-env.d.ts` its sibling workers all have. The deferral of `apps/worker` is the one hole, it is named in `DEFERRED_TEST_PROJECTS` with both of its measurements, and it closes with the app worker's dependency-shape work already tracked under _To formalize_ in [`build-performance.md`](../conventions/build-performance.md) rather than on its own schedule. Builds on the project-references rollout in [`build-performance.md`](../conventions/build-performance.md).
