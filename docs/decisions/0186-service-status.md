**Service status — component matrix + upstream aggregation + an isolated read worker, over the platform's first KV namespace.** ADR-0048 already put the *live* status content in control-plane KV, written by an operator-gated endpoint, and served as a public Workers surface kept off the app's fate so it survives an incident — but scoped that to a single banner. This design grows it into a full status system while keeping ADR-0048's shape intact.

**(1) Three signal sources feed one snapshot.** **(A) Upstream providers** — a static registry (`packages/status`) with one **Statuspage adapter** covering every Atlassian-Statuspage-based provider (Cloudflare, GitHub, …): fetch `/api/v2/summary.json`, normalize `status.indicator` into our vocabulary. A provider with no public feed is `kind: "manual"` (operator-set only); a fetch failure surfaces that single row as `status_unavailable` rather than a fabricated verdict, and — critically — never poisons the overall rollup, because their outage is not ours. **(B) Our components** — **exception-based, default Operational**: a component leaves Operational only on positive problem-evidence (an operator declaration, a telemetry error-rate signal on traffic already flowing through it, or a failed probe against the cheap always-on core primitives — the status worker's own health check, a control-plane `SELECT 1`, an R2 head, a `STATUS_KV` read). We never boot a container (Collabora, LibreOffice, Tantivy, OCR, scan) merely to check it is alive — that burns per-second cost and defeats scale-to-zero, so idle components read the same green as everything else; there is no "unknown" state. **(C) Service events** — operator-declared disruptions (title, impact, affected components) with a rolling update timeline, lifecycle `investigating → identified → monitoring → resolved`, plus manual component overrides and scheduled maintenance windows.

**(2) Two writers, separate keys, no race.** The cron (A + B) writes `status:derived`; the operator endpoints (C + overrides) write `status:authored`. There is no `status:published` key — every reader computes the published snapshot via a shared `mergeSnapshot(derived, authored, { audience })` in `packages/status`. An override always wins over the derived status for its component; `overall` is the worst active component/provider status combined with any active event impact, with the `status_unavailable` carve-out from (1); `stale` is set once `generatedAt` ages past a threshold. This removes the write race structurally — no lock, no Durable Object needed for the datastore itself.

**(3) Audience-scoped attribution.** `mergeSnapshot` takes an `audience` of `"public"` or `"internal"`. For `"public"`, `authorUserId` is stripped from every event, update, and override before it is serialized; for `"internal"` it is preserved so an in-app operator view can show who posted what. The status worker's public endpoints always request `"public"` — an operator's identity structurally cannot reach the public KV read path.

**(4) A new isolated, read-only, unauthenticated worker: `apps/status-worker`.** Its only job is to read `STATUS_KV`, merge, and serve `GET /api/status.json` (and a placeholder `/`, HTML deferred). It binds **only `STATUS_KV`** — no app binding, no D1, no per-firm binding, no service binding into the app worker — so it survives the app worker, control-plane D1, or any per-firm database being down, which is exactly when people go looking for it. It never returns a 500 on the public path: a KV read failure falls back to a minimal static page linking out to Cloudflare's own status. It is a separate deployable with its own Workers Build, deliberately not part of `build-all` (the same posture as the scan/bundle/convert workers). The one failure it does not survive — all of Cloudflare down — is precisely when Cloudflare's own status page becomes the authority, which the fallback links to.

**(5) `apps/worker` keeps every write path.** The cron (probe + poll) and the operator endpoints (`/api/v1/platform/status/*`, gated by the new `platformOperatorGuard` — see the companion `platform-operator-principal` fragment) live in the existing app worker, reusing its session resolution, telemetry, and cron infrastructure. The status worker exposes no write surface at all.

**(6) `packages/status` is the shared, pure, DAL-free core** (the ADR-0044 pattern — package isolation *is* the confidentiality boundary here too, though no per-firm data ever crosses it): the snapshot zod schema and vocabulary, the provider registry + Statuspage adapter, health derivation, and `mergeSnapshot()`. Both workers import it; nearly all unit tests live here.

**Considered & rejected.** **A `status:published` key written by whichever side runs last** — reintroduces a lost-update race between the cron and an operator mid-incident; rejected for the two-key read-time merge. **Serving the public feed from the app worker itself** — defeats the entire point (the status page must survive the app worker being down); rejected for the separately deployed, binding-starved `apps/status-worker`. **An "unknown/idle" component state for anything with no recent traffic** — would make every rarely-used container perpetually amber and would force us to synthetically probe otherwise-scale-to-zero containers just to keep them green; rejected for the exception-based default-Operational model. **Fabricating a status for an unreachable upstream provider** — an honest `status_unavailable` that does not worsen `overall` was chosen over guessing at their state.

**Consequences.** The public status page can answer "is it down?" truthfully even during an app-wide outage, without a special-cased datastore or a second control plane. The component health model stays honest about what "green" means (no known problem, not "just tested passing") and adds zero cost to idle containers. Deferred: all rendered UI (public page HTML, in-app banner presentation), subscriber notifications, per-firm-scoped status filtering (ADR-0048's `audience` seam covers a future split), and the diagnostics-agent propose-then-publish workflow ADR-0048 named. Extends **ADR-0048** (product-updates + live-status surface); introduces the platform's first **KV** namespace; depends on the new **`platform_operator`** principal recorded in the companion fragment.
