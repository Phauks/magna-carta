**Deleted-file lifecycle: trash → Infrequent Access → policy-driven destruction; capability built, default indefinite.** **Context:** ADR-0035 tiers _superseded versions_ to IA but left _deleted files_ undefined; deletion in a legal system is not a synonym for purge (retention schedules, legal/discovery/Custodian holds, and privacy-law erasure all bear on it), and a multi-tenant "keep everything forever" default carries unbounded cost and discovery exposure. **Decision:** deletion is a **soft-delete** (a firm-scoped DAL state change that hides the record; bytes are not immediately purged), and the R2 object moves through three stages — (1) **trash window** on **Standard**, recoverable in place with no copy/retrieval fee, **default 30 days**, sized to IA's 30-day minimum-storage charge so delete-then-undo churn pays no IA penalty; (2) **cold retention** via **Standard → IA** in place using the **same `CopyObject` (`x-amz-storage-class: STANDARD_IA`)** path as version tiering (server-side, no bytes through the Worker, no retrieval fee, ~33% cheaper on a never-read segment); (3) **destruction** — a per-record **retention/destruction date** can trigger a true **hard-delete** (the one place file bytes are deleted), **blocked by any legal/discovery/Custodian hold** and audited like any irreversible act. The **destroy machinery is built but retention defaults to indefinite** — keep-by-default behavior today (matching version history's _tiering, never pruning_), with a per-matter/jurisdiction switch for when a bar rule, client purge instruction, or GDPR/CCPA erasure _requires_ destruction, no re-architecture. **Cost finding:** IA storage is cheap at single-firm scale either way (~$0.12/GB-yr, egress free) — cost does not force destruction per firm — but at platform scale "never destroy" trends to a multi-petabyte, $1M+/yr-and-climbing line, while IA tiering of the cold/deleted segment is worth doing regardless (~$300k/yr saved at 1,000 firms × 5 TB; current R2 rates Standard $0.015 vs IA $0.010/GB-mo, IA $0.01/GB retrieval, 30-day minimum). **Considered & rejected:** **soft-delete → IA, never destroy** (simplest and safest against spoliation, but cannot satisfy a must-destroy obligation and grows unbounded — preserved as the _default behavior_ via indefinite retention, not as the _only_ path); **trash → hard-delete, no IA** (cheapest, but discards the retained-but-cold archive legal/discovery/Custodian may require and ignores the IA tier). Extends **ADR-0035** (version tiering — shared `CopyObject` path); touches **ADR-0026** (per-firm crypto-shred is the separate whole-firm destruction path), **ADR-0012** (discovery/legal holds) and **ADR-0014** (Custodian retention/destruction dates) as destruction blockers. D1 backup/snapshot strategy is the open second half of this design and not yet decided.
