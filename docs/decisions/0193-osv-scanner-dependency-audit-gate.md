**The dependency-audit CI gate moves to osv-scanner, covering the Rust supply chain the npm-only `pnpm audit` never saw.** **Context:** the gate's `pnpm audit --audit-level high` step covered only the npm/pnpm tree and depended on npm's audit endpoint, which npm is retiring (HTTP 410 brownout from 2026-07-15; a stopgap `--ignore-registry-errors` kept it limping). More importantly, the audit provided **zero coverage of the Rust supply chain** — 8 crates and 7 first-party `Cargo.lock` files (`crates/` + 6 `containers/`) whose engines parse **untrusted, privileged bytes** (PDFs, email, archives, images), which is the highest-risk surface in the codebase and the one the memory-safe-Rust posture exists to protect. **Decision:** replace the CI audit step with **osv-scanner v2.4.0** scanning both ecosystems against the OSV database (GHSA for npm, RUSTSEC for crates), scoped to the 8 first-party lockfiles via explicit `-L` flags (never `-r .`, which would pull in the throwaway `spikes/`). osv-scanner's `scan` has no severity threshold (it exits 1 on any finding), so the gate replicates the prior high-only strictness by classifying findings in the step: it fails **only** on a remaining HIGH/CRITICAL, keyed on the finding group's `max_severity` (**CVSS >= 7.0**), falling back to the advisory's `database_specific.severity` text when no CVSS vector exists; moderate/low pass. **npm severity is keyed on CVSS, not the vendor label** (owner decision) — stricter than the old label-based `pnpm audit`, so a CVSS-high advisory a vendor under-labels is still caught. Scan/config errors (osv exit >= 127, e.g. 128 = no packages found) **fail the gate** — a broken scan never silently passes. Accepted advisories live in a repo-root **`osv-scanner.toml`** passed with `--config` (auto-discovery does not reach child directories in a monorepo). **The migration immediately paid off:** on first run osv-scanner surfaced **four real high advisories (all CVSS 7.5) the npm-only audit could never see** — `RUSTSEC-2026-0187` (lopdf stack-overflow DoS parsing untrusted PDFs, squarely on the untrusted-input path), `RUSTSEC-2026-0194`/`0195` (quick-xml), and `GHSA-w5hq-g745-h8pq` (uuid; CVSS 7.5, GitHub-labeled Moderate). Per owner decision (**adopt now, track the four**), these are accepted in `osv-scanner.toml` with cause and a **`ignoreUntil` time-box (2026-10-14)** — a forcing function that re-surfaces them if unremediated — so the gate begins protecting against new advisories immediately while the four are fixed by carrier upgrades (lopdf >= 0.42.0; quick-xml; uuid) in follow-up work. **Scope kept tight:** this changes the CI gate only. The **pre-push hook still runs `pnpm audit`** (and still reads `package.json` `pnpm.auditConfig.ignoreGhsas`), so that config is retained; migrating the hook to osv-scanner and dropping `auditConfig` is a follow-up. **Considered & rejected:** staying on `pnpm audit --ignore-registry-errors` (leaves the Rust supply chain unaudited and depends on npm's retiring endpoint — a degrading bridge); bumping pnpm to a bulk-endpoint version (verified: current pnpm 11 still 410s and relocates `auditConfig`, so not a clean fix, and it would still be npm-only); osv-scanner as a non-blocking report-only job (a security check that does not block tends to be ignored); fixing the four advisories before flipping (the most secure path, but the owner chose immediate adoption with tracking so protection against new advisories starts now). **Considered for severity basis & rejected:** keying npm on the GitHub vendor label for exact `pnpm audit` parity (would miss uuid; owner chose stricter CVSS). **Consequences:** both supply chains are audited on every PR against a maintained, endpoint-independent database; a previously-invisible class of high-severity Rust advisories on the untrusted-parsing surface is now visible and tracked; the gate is stricter for npm; costs are installing the osv-scanner binary per CI run (curl from GitHub releases; no SHA256 pin yet — a hardening follow-up), the in-step jq severity classifier (verified to discriminate — empty at CVSS 8.0, catches the four at 7.0, pulls moderates at 4.0), a network call to osv.dev at gate time (fails closed on error), and holding two ignore lists (`osv-scanner.toml` for CI, `auditConfig` for the pre-push hook) until the hook is migrated. Realizes the _Vulnerability / dependency management_ control in [`docs/conventions/compliance.md`](../conventions/compliance.md); relates to slice 0·6 (the original audit gate) and golden rule 14 (memory-safe posture — this audits the Rust dependencies that posture rests on).
