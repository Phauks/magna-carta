**Finish the osv-scanner migration's follow-ups: pin the scanner binary, retire the local `pnpm audit`, and collapse the two ignore-lists into one.** **Context:** the CI dependency-audit gate moved to osv-scanner over both supply chains, but three follow-ups were deferred — the scanner binary was fetched unpinned, the pre-push hook still ran the npm-only `pnpm audit`, and accepted advisories lived in two places (`osv-scanner.toml` for CI, `package.json` `pnpm.auditConfig` for the hook). **Decisions:** (1) **Pin the binary.** The gate verifies the downloaded `osv-scanner_linux_amd64` against a SHA256 taken from the release's own `osv-scanner_SHA256SUMS`, before making it executable, and fails closed on mismatch — so a swapped or compromised release asset never runs. The pin is an env var updated in lockstep with the version. (2) **Remove the hook's dependency audit rather than replace it.** The pre-push hook is a fast local courtesy; a dependency audit is a whole-repo guard the CI gate now owns authoritatively over both ecosystems, and `pnpm audit` both under-covered (npm only) and leaned on npm's retiring audit endpoint. Rather than download and run osv-scanner on every local push (slow, a network round-trip, and blocked in some sandboxes), the hook simply drops the step and points to the CI gate as the authoritative audit. (3) **Drop `auditConfig`.** With the hook's `pnpm audit` gone nothing reads `package.json` `pnpm.auditConfig`; its two accepted advisories (esbuild, lodash) already live in `osv-scanner.toml`, which becomes the single accepted-advisory home. **Considered & rejected:** replacing the hook's audit with a local osv-scanner invocation (per-push binary download + osv.dev round-trip defeats the hook's fast-and-local purpose, and the release binary is unreachable in some egress-restricted environments); keeping `auditConfig` "just in case" (a second ignore-list that can silently drift from the real one); pinning by version tag alone (an immutable tag still lets the asset bytes be replaced — only a content hash detects that). **Consequences:** the audit binary is tamper-evident; there is exactly one audit of record (the CI gate) and one accepted-advisory list (`osv-scanner.toml`); local pushes are slightly faster. The cost is that a vulnerable dependency is now caught at the pull-request gate rather than pre-push — an acceptable trade since the gate is required before merge and the hook was never the gate of record. Realizes the _Vulnerability / dependency management_ control in [`docs/conventions/compliance.md`](../conventions/compliance.md).
