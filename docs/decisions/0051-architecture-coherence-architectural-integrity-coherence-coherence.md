**Architectural integrity & coherence — coherence _by construction_ for an AI-built codebase: chokepoint seams + registry-first + four-tier fitness functions + generated read-first indexes; spec→plan→execute as session memory; bespoke memory infrastructure rejected.** **Context:** the platform is large and built largely by AI across sessions that start with **no memory of the last**, so the dominant long-run risk is accumulating _incoherence_ — reinvented utilities, features that skip a cross-cutting concern, relitigated decisions, and work no successor session can resume. The _Design system & UI consistency_ model (ADR-0028) already proves the cure on one axis (CSS): **structure + CI, not discipline.** **Decision:** generalize that model to the **whole architecture**, ordered by how little each mechanism depends on the builder choosing right — (1) make the wrong thing **impossible** (structure/types), (2) make it **fail loudly** (CI/tests), (3) make the right thing **cheap to discover** (read-first artifacts); memory/discipline is never the strategy. Four mechanisms: **(a) Chokepoint seams** — every cross-cutting concern is a property of an _unbypassable path_, generalizing the firm-scoped **DAL** (ADR-0003) and **`protected()`** field type (ADR-0026) to the audit log, conflicts-re-check on _add-party_ (ADR-0013), and the comms ports (ADR-0047); the test of a seam is "can the dangerous thing be done without touching it?". **(b) Registry-first** — anything that is "a growing list of similar things" is a **declarative registry** (extending the settings registry ADR-0040, the conversion format registry ADR-0030, design tokens ADR-0028, plugin ports ADR-0015), making each addition uniform, discoverable, and machine-introspectable. **(c) Architectural fitness functions** — CI checks whose subject is the _architecture itself_, in four tiers of decreasing determinism: **boundary/dependency rules** (dependency-cruiser / ts-arch — only the DAL imports D1, no cross-firm import, UI never imports an adapter), **custom AST lint rules** (Oxlint JS plugins, ADR-0042 — alpha-accepted under the toolchain's ESLint/OSS fallback), **conformance tests over the registries + the emitted OpenAPI contract** (ADR-0022) asserting structured metadata not source text (every mutating route audited + role-gated; every `protected()` field has a role; every port has an adapter), and **LLM-as-fitness-function** (the ADR-0016 maintenance-agent pattern pointed inward, **propose-only**) for fuzzy rules. **Seams prevent; fitness functions prove no path escaped** (belt and suspenders). **(d) Generated read-first indexes** — a capability map **generated from registries/module surfaces, never hand-maintained** (a stale index lies — worse than none), regenerated in CI with **fail-on-drift**, surfaced read-first by per-area `CLAUDE.md`; the non-UI analogue of the Storybook/Histoire catalog (ADR-0041). Carried across sessions by **spec → plan → execute** with a persisted plan file per vertical slice (ADR-0020 / ADR-0039). **Considered & rejected:** **bespoke memory infrastructure** (vector DB / knowledge graph / custom context server) — rots, needs babysitting, and duplicates what the **codebase + git history + generated indexes** already are; **discipline / convention alone** (the very failure mode this ADR exists to escape — same reasoning as ADR-0028); **hand-maintained architecture/capability maps** (drift silently, then mislead). **Consequences:** coherence is enforced structurally and in CI rather than trusted to memory; the scariest failure — missed wiring on money/ethics paths — becomes **unmergeable** rather than hope-based; cost is the discipline of routing concerns through seams, preferring registries over bespoke code, maintaining the fitness-function suite, and the fallback-bounded alpha risk of Oxlint JS plugins. Generalizes **ADR-0028**; builds on **ADR-0003** / **ADR-0026** (seams), **ADR-0040** / **ADR-0030** / **ADR-0015** (registries), **ADR-0042** / **ADR-0022** / **ADR-0041** / **ADR-0016** (fitness functions), and **ADR-0020** / **ADR-0039** (workflow & vertical slices). A full subsystem spec (seam catalog, four-tier fitness-function suite, generated-index contract, per-area `CLAUDE.md` template) is the planned next step.
