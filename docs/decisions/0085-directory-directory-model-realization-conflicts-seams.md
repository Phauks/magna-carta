**Directory model realization + conflicts seams (slice 1·3): the SSOT graph built as two equal-depth node tables (`directory_person` / `directory_organization`, type-prefixed handles, distinct standard fields — not a polymorphic table) + one typed `directory_edge` table (endpoints are entity handles; the global prefix discriminates, no kind column); a **category is a per-firm classification label, not a schema variant** (all field variability is slice 1·4 — ADR-0087); all names (incl. the current one) live in `directory_name` as queryable rows (role + temporal validity + frozen normalization), name changes append-and-flip never edit-in-place; the write-time search substrate = scheme-keyed `directory_name_phonetic_code` rows (Double Metaphone via pinned `words/double-metaphone` at launch — the scheme key makes Beider-Morse additive-by-sweep at Phase 4, no schema change) + an FTS5 trigram table synced by triggers; sensitive identifiers are `protected()` rows declared against the ADR-0084 policy table with `directory:viewSensitiveIdentifiers` as the decrypt permission, **EIN added to that policy table** (standalone blind index L=16, digit-strip — a tax-ID exact-match channel); edge types include the conflicts seam-4 set explicitly (affiliation/principal-of-org, spouse/family relationship, corporate parent/subsidiary/successor, representation, role-assignment); temporal validity on names/edges/identifiers/`matter_party`/contact rows, core identity untimed; soft-delete, never hard-delete.** **Context:** ADR-0006 fixed the SSOT model and the conflicts research ([`docs/research/conflicts-matching-engine.md`](research/conflicts-matching-engine.md) §F) named six cheap-now/expensive-to-retrofit Directory seams for the Phase-4 engine; this slice realizes the model and builds the seams (recall side only — the scorer, severity bands, strictness/depth, graph traversal, and immutable log are Phase 4). The phonetic feasibility ([`docs/research/directory-mechanics.md`](research/directory-mechanics.md) §C: Double Metaphone is Workers-safe today, Beider-Morse has no mature JS impl) drove the minimal-go gate. **Decision (additional — firm personnel, flagged revisitable):** firm personnel are **not** modeled as Directory entities — staffing is the 0·4 `member` axis; intra-firm imputation is a Phase-4 logical join (`member` ↔ matter ↔ `matter_party`), not a personnel node; prior-firm lateral-conflict history is a documented seam built in Phase 4 (self-reported, unreliable, no consumer until the engine exists); a lawyer who is genuinely a party is an ordinary entity (optional `member_id` link). **The owner reserves this firm-personnel decision for reconsideration in the Phase 4 Conflicts design cycle** — the 1·3 position adds no personnel-entity data to retrofit, so revisiting is cheap. **Considered & rejected:** a single polymorphic `entity` table (loses equal-depth distinctness, needs a kind column the handle prefix already gives); category-specific standard columns (sparse real columns = per-firm DDL churn; JSON = breaks merge relink + field audit — both are exactly the 1·4 engine's job); fixed phonetic-code columns (the scheme-keyed table grows without migration); Beider-Morse now (no production-grade JS implementation; it rides the Phase-4 Rust/WASM core); modeling personnel as entities for imputation (conflates the assigned-to/about-them axes and creates a third identity to reconcile). **Consequences:** Phase 4 Conflicts builds on a ready graph + exact-identifier channel; merge's relink surface stays bounded to real indexed columns (§7); the Directory volume profile + a blind-index/protected-read/graph-expansion measured set join the load harness (accretion rule). Refines **ADR-0006**, serves **ADR-0013**; builds on **ADR-0084** (protected fields + EIN policy row), **ADR-0031** (address/Location reuse), **ADR-0062/0071** (handles, package seam).
