**Docs-maintenance agent — a propose-only §25 agent for mechanical doc drafting + coverage-gap flagging; authoring stays in-commit, deterministic hygiene goes to CI.** **Context:** ADR-0016 named a "changelog/roadmap maintenance agent" only in passing and never made it first-class, while the documentation model (golden rules 5/9, _Product updates_, _Development guidelines_) is **docs-in-commit / one-home-per-fact** — so an agent that _authors_ feature documentation as a downstream step would reintroduce exactly the drift "version-accuracy by construction" exists to prevent (the running app could advertise what it does not contain). The need is real but must be scoped so automation never becomes the authoring path. **Decision:** add **one propose-only docs-maintenance agent** to the _Maintenance agents_ (§25) family, scoped to two jobs: (1) **mechanical drafting** — draft `[Unreleased]` CHANGELOG entries from merged PRs and roll ROADMAP status up from the changelog (the work ADR-0016 promised in passing, now owned); (2) **docs-coverage-gap flagging** — a user-visible PR with no `docs/user/` guide, a design change with no ADR, a referenced `ADR-NNNN` that does not exist. It **never originates design narrative or user-guide prose** (that ships in-commit with the change author) and **never auto-merges** (trust/ledger/conflicts paths always require human review, per ADR-0016). **Deterministic doc hygiene is CI, not the agent:** the cross-reference rule (a `§N` reference from _outside_ the white paper), dead/broken links, and an empty-`[Unreleased]`-on-a-user-facing-PR soft gate are **`vp check` lint rules** — cheaper, faster, and more reliable than an LLM; the agent carries only the judgment-bearing residue. This is the **LLM-as-fitness-function** pattern (ADR-0051) pointed at the docs corpus: structure/CI first, agent for the fuzzy part, discipline never the strategy. **Considered & rejected:** a **docs-authoring agent** (writes feature docs as a separate step — breaks docs-in-commit, manufactures the very drift the model prevents); a **maximal docs auditor** that also does prose/style review and cross-reference integrity _itself_ (overlaps the deterministic CI checks and risks the agent re-authoring docs — the integrity checks are deterministic and belong in CI); **leaving it as scattered prose** (the current half-specified state across the white paper, `documentation.md`, CHANGELOG, and ROADMAP — relitigated each time it is read). **Consequences:** the changelog/roadmap automation and coverage-gap safety net are captured as a first-class agent with an explicit boundary, so docs automation gains leverage without ever becoming the authoring path or sacrificing version-accuracy-by-construction; cost is building the agent plus the CI doc-lint rules, and holding the line that the agent proposes and never authors narrative. Extends **ADR-0016** (maintenance agents — does not supersede it); reuses **ADR-0037** (living docs), **ADR-0051** (LLM-as-fitness-function, propose-only), **ADR-0022** (PR/CI surface, `vp check`), and the _Product updates_ design (ADR-0048).
