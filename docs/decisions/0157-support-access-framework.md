**Support access — the rails.** Help desk will need to reach a firm's instance to diagnose problems, which collides head-on with the platform's confidentiality posture: each firm's sensitive data is envelope-encrypted (a per-firm data key wrapped under `ROOT_KEK`; `protected()` values unreadable without it), telemetry redacts by default, and the platform deliberately cannot casually read firm content. Support access must be a constrained, attributed, expiring path _through_ the same enforcement everything else traverses — never a back door around it.

**Decision.** Support is **pull, not push**: help desk can never open a session unilaterally — a session exists only because someone inside the firm requested help, and that request _is_ the consent and the audit anchor. A request mints a control-plane `support_grant` `(firm_id, requested_by_user_id, tier, scope, status, reason, principal_id, requires_cosign, cosigned_by_user_id, expires_at)`; a named `platform_staff` principal (own credentials, MFA mandatory, modelled as a `principal` so a future agent variant is the same machinery) redeems an _active_ grant for a short-lived HMAC-signed bearer token presented as the `X-Support-Session` header. The token is only the bearer proof; the live grant row is re-checked on every request, so revocation and expiry kill access immediately. The "temporary key" the owner floated is therefore a temporary **grant** (Sense 1), not handed-over crypto (Sense 2): the firm AES key never leaves our compute and decryption stays server-side, so a copied token cannot read plaintext off our infrastructure after it "expires."

Two tiers, one mechanism, slotting into the route chokepoint (`apps/worker/src/chokepoint/`) as an alternate principal rather than a bypass — the `loadPermissions` port now takes the full session and branches by tier:

- **`diagnostic`** → a fixed allow-list, the whole `diagnostics:*` namespace (`packages/access-control/src/registry.ts`). It holds **no** `view*`/decrypt key, so the audited-decrypt gates never open and privileged content is unreachable _by construction_, not by promise. Any firm member may request it (`support:request`, seeded to every default role).
- **`privileged` + `scope:self`** → exactly `loadEffectivePermissions(firmDatabase, requestedByUserId)` — the requesting member's own effective permissions, nothing more. No firm-level privilege is expanded (the user sharing their own view). Authority is keyed to the requester's id; the staff principal id is stamped into every audit row. An optional firm policy (`firm.support_requires_cosign`, default off) inserts an admin co-sign before a privileged grant goes active.

**Considered & rejected:** _help-desk-initiated access_ (rejected — collapses the consent story; the firm member's request is the only entry); _handing help desk a re-wrapped firm key for a TTL_ (rejected — plaintext-capable material can be copied before expiry and read off our compute, breaking the core guarantee, for no benefit a live-diagnosing help desk needs); _admin co-sign as the default for privileged_ (rejected as the default — self-scoping already bounds the blast radius to one member's own access, so co-sign is opt-in hardening, not a deadlock on every ticket); _a shared platform-admin bearer key as the staff identity_ (rejected — a shared key cannot attribute an action to a named human, and per-person attribution is the feature's whole product).

**Consequences.** Net-new control-plane tables `platform_staff` + `support_grant` (migration `0004_support-access`) and the per-firm role seeds (`0028_support-access-permissions`); a firm-visible audit trail over the existing `auth_audit` lineage is the product surface ("who looked, when, why, what scope"). Deferred named seams: **staff self-service authentication + MFA** (interim, the redeem route is gated by the existing platform-admin key with the named principal validated against `platform_staff`); **UI** (support console + the privileged view-as render path); **notification transport** (admin notify on request/redeem); **AI-agent principals** (the principal model reserves them); **promoting `support_requires_cosign` into the declarative settings registry**; and **per-request fine-grained audit** (redemption + lifecycle are audited now).
