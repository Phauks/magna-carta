**`noindex` on every private application surface.** Magna Carta is a private, authenticated, multi-tenant product. The application Worker is the single front door for the SPA shell, the API, Better Auth, health, and every branded per-firm subdomain — all of which serve only a firm's own privileged data. A firm's client portal appearing in a search result would be a confidentiality breach, not merely an SEO problem. The decision:

**(1) Authoritative control is `X-Robots-Tag: noindex, nofollow`, not robots.txt.** `robots.txt` governs *crawling* but not *indexing* — a disallowed URL can still be listed (snippet-less) if a crawler discovers it via a link. `X-Robots-Tag: noindex` is what actually keeps a page out of the index. The existing Cloudflare dashboard-managed `robots.txt` is kept as complementary, not redundant. `nofollow` is included so a crawler that does reach a private page does not harvest the in-app links it carries.

**(2) The control lives in code, not a dashboard Transform Rule.** A Cloudflare Response-Header Transform Rule would be zero-code and edge-level, but it is invisible to the repo and to PR review, untestable in CI, and prone to per-environment drift. A Worker middleware is version-controlled, carries a standing fitness test that fails if the directive ever stops being stamped, sees every response through the one front door, and matches the "everything through Workers / code-as-contract" posture. The edge-level advantage of a Transform Rule buys nothing here because every surface already flows through the Worker.

**(3) Blanket on the app origin; the sealed cookieless `files.*` edge is excluded by registration order.** The middleware is `app.use("*")` registered AFTER the cookieless preview route. Hono middleware only wraps routes registered after it, so the preview route and the files-host catch-all — which serve only `Content-Disposition: attachment` bytes and bare, deliberately-minimal 404s (never an indexable page) under an exhaustive payload-derived header set — keep that set pristine. Omitting the directive there is correct: attachments are not indexed, and the edge's "every header derived from the verified payload, nothing leaked" contract stays intact.

**(4) Immutable Static-Assets responses are copied to stamp the directive.** The SPA shell is served by the Workers Static Assets binding, whose `Response` carries immutable headers. The middleware sets the header directly when possible and, on the immutable case, copies the response (`new Response(body, response)`) — re-wrapping the body stream, never buffering — before stamping.

**Considered & rejected.** A Cloudflare dashboard Transform Rule (not version-controlled, untestable, drifts across environments) — rejected; the existing `robots.txt` stays as a complementary edge artifact. robots.txt `Disallow` alone (blocks crawling, not indexing) — insufficient as the sole control. A blanket directive registered before the preview route (would stamp the sealed cookieless edge) — rejected to keep that edge's header contract exhaustive and self-contained.

**Consequences.** Every private application surface this Worker serves is kept out of search indexes by a code-owned, CI-guarded control, ahead of building the public marketing site. The marketing site is a separate future app on its own host (apex/www); because it does not run through this Worker it will not inherit this directive, so the blanket cannot accidentally de-index the one surface that *should* rank. When that site is built, the indexable/non-indexable boundary becomes explicit per host.
