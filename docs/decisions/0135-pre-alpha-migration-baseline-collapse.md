**Collapse the per-firm migrations to a genesis baseline before alpha.** Migrations earn their keep by incrementally evolving databases that already exist. No production firm database has ever been created from the per-firm lineage (the platform is pre-distribution; every firm DB is built fresh from migration 0 at provisioning), so the 17 incremental per-firm migrations (0003→0016 and counting) are developer history — preserved in git regardless — not deployed state. Collapsing them into one CREATE-everything baseline equal to the current drizzle snapshot is a real, low-risk simplification: faster provisioning + tests (apply one migration, not seventeen, in the per-firm-migrations test and the load-profile harness), a cleaner single-file schema-of-record (no archaeology through diffs), and removal of accumulated cruft (the `0009→0011` phonetic-index renumber, the e_billing `ALTER`-via-table-rebuild, the `scoped_setting` and `kick_back_reason` mid-slice snapshot amendments, and the hand-edited D1 PRAGMA dances). **Two gates before executing:** (1) **no durable per-firm state to preserve** — the production `DB_FIRM_POOL_1/2` are empty pre-provisioning pools; if per-firm migrations were applied to them, recreate them from the collapsed baseline (no data loss, the point of doing it pre-alpha); (2) **all in-flight slice branches merged/quiesced** — each adds and references specific migration numbers, so the collapse must land as a single baseline commit on `main` during a lull, not while parallel worktrees are appending migrations. **Timing:** the natural moment is when the Phase 1–3 backend schema stabilizes and the first real alpha firm is about to be onboarded — that first firm DB becomes the new immutable migration-0 baseline and everything after is incremental again; before that line the collapse is free, after it a reconciling migration would be required. **Control-plane lineage is NOT collapsed:** the production control-plane D1 is live (`0000_firm-registry` applied 2026-06-10, auth/provisioning on top), so it is deployed history and stays incremental. **Mechanically** cheap: the drizzle snapshot already represents the full schema; generate one consolidated genesis migration from it (a fresh drizzle init, or assembled by hand), reset the journal to a single entry, fold in the per-firm role/permission seeds, recreate the empty pool DBs. **Considered & rejected:** collapsing piecemeal as slices land (collides with parallel branches — must be a single quiescent baseline); collapsing the control-plane the same way (it has real applied state); keeping all 17 forever (carries dev-only intermediate states a fresh-provisioned firm never needs). Tracked as a pre-alpha operational gate in [`ROADMAP.md`](../ROADMAP.md).
