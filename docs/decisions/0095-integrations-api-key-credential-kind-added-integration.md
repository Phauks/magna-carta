**API-key credential kind added to the integration credential model, amending ADR-0091 and ADR-0092: a new `api-key` `CredentialKind` joins the existing credential shape with `{ kind: "api-key"; key: string }` typed as `ApiKeyCredential`, carried through `@magna-carta/integrations` alongside the previously assumed OAuth-flow kind. The decision amends ADR-0091/0092 because those ADRs implicitly assumed the first credentialed adapter would be OAuth (calendar/email) — the shipping adapter (EasyPost) uses a static API key per firm account, so the `api-key` kind must be modeled explicitly.** **Context:** EasyPost authenticates with a static per-account API key passed in the `Authorization: Bearer` header; the Forge child-user model provides a child API key per authorized firm user. The original credential model in ADR-0092 described the `CredentialStore` interface in terms of token refresh and `invalid_grant`, which presupposes OAuth flows — but EasyPost's static key requires neither rotation machinery nor a Durable-Object refresh lock. **Decision:** extend the `Credential` discriminated union with `ApiKeyCredential` (`kind: "api-key"`, `key: string`); credential-kind branching in the EasyPost adapter reads the `api-key` branch and injects the key as the `Bearer` token; the `CredentialStore.get()` contract remains unchanged (the store returns the appropriate credential shape; the adapter narrows). OAuth kinds remain the seam for calendar/email adapters. Rotation: API keys do not rotate automatically (unlike OAuth refresh tokens), so the DO refresh lock is not exercised by this kind — the credentials module carries the `api-key` kind as a no-rotation branch. **Considered & rejected:** coercing the EasyPost key into an OAuth-shaped token (a category error — forces meaningless `expires_at`/`refresh_token` fields onto a static credential); a separate per-provider credential interface (violates the typed-discriminated-union contract that callers narrow over — an adapter must receive a `Credential` and narrow, not a bespoke type). **Consequences:** the framework supports both static-key and OAuth-flow adapters from the first credentialed adapter; future adapters (accounting APIs, PACER, court-filing services) can declare the `api-key` kind without further model changes. Amends **ADR-0091** (credential model, `Credential` union) and **ADR-0092** (adds `api-key` to the `CredentialKind` enumeration; rotation machinery is kind-gated, not universal). Realized in `@magna-carta/integrations` (`src/credentials.ts`). Serves **ADR-0094** (EasyPost adapter).
