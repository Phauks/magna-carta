**Inbound upload path & quarantine ingest: uniform direct-to-R2 (bytes never transit the Worker — it authorizes, mints single-key short-TTL presigned URLs via one R2 S3 token held as a Worker secret, and records metadata); two transfer modes behind one pinned client library (Uppy AwsS3 — presigned PUT below a config threshold, resumable S3 multipart above it); quarantine is a status gate on `file_version` (`pending`/`quarantined` vs `clean`), not a separate key — bytes land at the final key and promotion is a status flip; one ingest consumer (R2 event notification → `files-ingest` queue) does everything needing the bytes in a single read: magic-byte/size/bomb gates, SHA-256, the malware-scan port (engine deferred — launch adapter records an explicit `unscanned` verdict), no-op-skip check, commit + metering + outbox.** **Context:** the white paper's named open item ("likely its own ADR"): Worker body caps (100 MB plan-bound) and 128 MB memory make through-Worker ingest impossible for legal files (discovery video, large scans); research (slice 1·1 research doc, section A) verified R2 presign/multipart mechanics, limits (parts ≥ 5 MiB, ≤ 10,000, 7-day auto-abort), and event-notification throughput on primary docs; the owner chose both-modes-now over presign-only after full briefing (design cycle, 2026-06-11). **Decision (additional):** per-firm max-size/content-type policy enforced twice (refused at presign; re-verified against real bytes at the gate — the client controls the bytes); `FirmResourceProvider` gains idempotent `configureBucketNotifications` (prefix `files/` → `files-ingest`, purpose-named queue per ADR-0075); stale pending sessions/versions expire via the 0·4 cron plumbing; presigning via `aws4fetch` (pinned); the ingest consumer is idempotent under queue redelivery; quarantined files are never auto-deleted (evidence; hold-blocked destruction). **Considered & rejected:** tus (R2 has no native endpoint — a tus-shim Worker is extra infrastructure for a protocol nicety; reserved); through-Worker small-file path (two code paths, no benefit — direct-to-R2 composes with quarantine identically); pending-key-then-copy quarantine (promotion re-copies multi-GB objects; R2 single CopyObject caps ~5 GiB; the data-access layer already mediates every read, so the status flag is structurally enforced — golden rule 3); per-firm presign tokens (secret sprawl, no isolation gain — the signed key already pins the firm's bucket); hand-rolled upload client (re-hardens retry/resume/parallelism Uppy has solved). **Consequences:** large/flaky uploads work from day one; portal (Phase 6) and Discovery ingest (Phase 5) reuse the path unchanged; the malware engine drops into a ready port (verdict + engine-version columns, re-scan-sweep seam) — engine choice stays its own deferred ADR, flagged for future research. Implements the white paper _Matters and File Manager_ upload item; builds on **ADR-0075** (resources), **ADR-0078** (hash-on-write), **ADR-0068** (`files:upload`), **ADR-0027** (zips stored opaque).
