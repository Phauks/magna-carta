**Storage-foundation follow-ups to ADR-0077, governed by the owner-set build-when-in-the-area principle: when a slice is already open, the cheap-from-the-getgo / expensive-to-retrofit parts (seams, schema columns, instrumentation) are built up front — "build when measured" gates are reserved for heavy machinery, never for foundations.** Three decisions + one parked question: **(1) Content hash on every stored object from day one (slice 1·1):** every file/version object records a SHA-256 content hash computed at write time — retrofitting means re-reading every byte ever stored. Serves evidence-grade fixity (chain-of-custody / discovery defensibility), the ADR-0077 roundtrip verification, duplicate-detection UX, an upload short-circuit ("these bytes are already held"), malware-scan verdict caching keyed by hash, and a no-op version skip (an explicit Save with unchanged content cuts no version). **Cross-matter blob dedup is explicitly not decided** — sharing bytes across matters collides with ethical walls (existence leakage), per-matter destruction (refcounting), and hold semantics; its own design if measurement ever justifies it. **(2) Backup dumps compressed from the first build (extends ADR-0050):** the per-firm SQL export snapshots are **zstd-compressed as they stream** — SQL text compresses ~85–95%, and neither of ADR-0035's no-compression rationales applies (a dump is not pre-compressed media and is never range-streamed); the ADR-0050 restore drills exercise the compressed path; `zstd --patch-from` deltas against the GFS weekly/monthly fulls as keyframes are the named later option. **(3) Per-firm storage metering built in-area (slice 1·1):** a rollup of bytes + object counts by storage class and key prefix per firm, feeding the existing Analytics Engine path (ADR-0074) — the instrument that fires every storage adopt-when trigger (ADR-0077's ~100 GB/firm delta threshold, ADR-0056's Iceberg cost-at-scale, ADR-0049's destruction economics) and doubles as the per-firm billing/capacity number; without a measurer, "adopt when measured" gates never fire. _Amended 2026-06-11 (slice 1·1 design cycle, ADR-0081 research): Analytics Engine is sampled, single-index, and 3-month-windowed, so it cannot be the authoritative figure — the **billing/capacity number and every adopt-when trigger read from an exact incremental rollup in per-firm D1** (counters by storage class × artifact role × prefix, maintained on the create/tier/delete write paths, trued-up by a scheduled R2 LIST reconciliation); Analytics Engine stays the trend/dashboard feed._
