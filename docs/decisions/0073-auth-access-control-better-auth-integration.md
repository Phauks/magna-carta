**Better Auth integration shape & firm-provisioning model (slice 0·4) — Better Auth mounts in the worker against control-plane D1 via the Drizzle adapter with `firm_id` as an additional user field joined to the firm registry (the organization plugin rejected: it would centralize membership join tables the tenancy model deliberately keeps per-firm); membership is invitation-only (no open signup) so every user creation rides our idempotent write path; the per-firm `member` mirror syncs through a new control-plane `outbox` + `idempotency_key` pair (reusing ADR-0063/0064 machinery — no second consistency mechanism); factors this slice are email/password + TOTP (seeds under Better Auth's built-in encryption until the `protected()` crypto module lands), passkeys deferred to the auth UI slice because WebAuthn ceremonies require a browser; firm provisioning is an idempotent, resumable orchestration behind a `FirmResourceProvider` port (dev adapter claims pre-declared Miniflare bindings; Cloudflare REST adapter creates real D1/R2, with the new database's binding accepted as a config-commit + deploy step for a fleet of one); user ids are `usr_` handles via the custom-id hook (ADR-0062).** **Context:** slice 0·4 realizes ADR-0004's first-party auth and ADR-0068's RBAC skeleton on the slice 0·2 primitives; the white paper fixes the model (control-plane identity, per-firm member mirror, roles-as-data) but leaves the library integration shape, the cross-database sync mechanism, and the provisioning seam to this design. **Consequences:** the access-control resolver lands as a pure package (`@magna-carta/access-control`) the ADR-0067 chokepoint consumes in slice 0·5; the worker cron handler gains the relay-sweep + TTL-purge wiring slice 0·2 deferred; a platform-admin secret guards `POST /v1/firms` until a real platform-admin principal model exists (named seam). **Rejected:** Better Auth organization plugin (membership centralization); open signup (uncontrolled user-creation path would bypass the outbox sync); synchronous dual-write for the member mirror (reinvents consistency the outbox already provides); building passkeys UI-less (dead, unexercisable surface); dynamic D1 binding dispatch now (fleet of one). Spec: `docs/specs/2026-06-09-slice-0-4-auth-rbac-provisioning-design.md`. **Amendment (2026-06-12, build findings):** (1) **No Better Auth CLI exists for the 1.6.x line**, so the decided "CLI generate as reference" route was impossible — the control-plane schema was derived empirically from the pinned package's `getAuthTables()` under our exact config; the schema-sync fitness test is the version-bump tripwire as designed. (2) The Worker requires the **`nodejs_compat` compatibility flag**: better-auth 1.6.16's workerd build needs `node:async_hooks` (the AsyncLocalStorage transaction context) — without it every mutating auth route 500s. (3) **Invite activation: Path A confirmed** — `resetPassword` on 1.6.16 creates the missing credential account; the build additionally added an `onPasswordReset` hook flipping `email_verified` (completing a reset proves mailbox possession — without the flip, `requireEmailVerification` would lock every invitee out). (4) Signup-disabled surfaces as `EMAIL_PASSWORD_SIGN_UP_DISABLED` (HTTP 400). (5) **`generateId` hardened to fail loud:** an unknown Better Auth model throws instead of the planned silent `verification` fallback — a silent wrong-prefix handle would defeat ADR-0062's self-describing ids. (6) **Idempotency is auth-gated and tenant-scoped** (security-review finding): the route middleware chain runs session + permission checks _before_ the idempotency pre-decision, and stored keys are scoped `${firmId}:${clientKey}` (the control-plane convention; platform-admin routes use `platform:${clientKey}` — the namespaces cannot collide because every firm scope starts with the `firm_` handle prefix) — closing an unauthenticated replay/key-existence oracle and cross-firm replay/poisoning; the data-access middleware gained an optional `deriveStoredKey` hook, and the run-idempotent-effect contract now sanctions an effect performing its own guarded resumable commits provided the response-bearing write rides the final batch (the firm-provisioner pattern). (7) **Firm-provisioning resume identity:** `firm.name` UNIQUE with `database_identifier` nullable (the row exists before its database); same name + same owner email = idempotent no-op, a different owner = 409. (8) **Audit hook wiring as landed** (decided #10 allowed shrink/grow): `session.create.after` → `login.success` (also fires on the session rotation Better Auth performs when 2FA is enabled mid-session — accepted as a fresh proof of the same principal); no dedicated twoFactor plugin hook exists, so `two_factor.enabled`/`two_factor.disabled` is transition-exact via paired user.update.before/after hooks; no password-reset databaseHook exists, so `password.reset` rides `onPasswordReset`. Hook audit writes are guarded (they never fail the auth flow they describe); request-path audit writes ride the atomic effect batch — a deliberate split documented at its one home, `auth-audit-statements.ts`. (9) **Runtime migration bundling:** per-firm migration SQL ships in the Worker via plain `.sql` imports under a wrangler Text rule + a vitest plugin (Vite `?raw` does not survive wrangler's esbuild). From the post-build adversarial review (2026-06-12, 14 confirmed findings, all fixed): (10) **`firm.owner_user_id` records the owner** — the already-active idempotency check joins on it; deliberately no FK, `user.firm_id` already owns the edge. (11) **Concurrency abort fence:** the activation batch carries an INSERT-SELECT fence so a concurrent same-name run cannot double-commit owners. (12) **Firm names are normalized at the route boundary** (trim + NFC) — the name is the resume identity. (13) **The REST resource adapter is find-first** (probe by name, create only when absent); the already-exists message regex is demoted to a race-window fallback. (14) The data-access idempotency middleware gained a **`conflictResponse` hook** so pre-decision 409/422s carry the same RFC 9457 problem bodies as the handler path. (15) **Deactivated members lose all permissions at the read path** (member-status join); `/v1/me` answers 404 for a deactivated member per the spec's absent semantics. (16) **Per-firm queue messages carry `firmId`** — tenant-tagged before any consumer exists. (17) **Dead-lettered outbox rows are revived via the documented requeue statement** (operator seam). (18) **Executed provision/invite arms schedule a best-effort request-path sweep** (`waitUntil`) so activation doesn't race the 5-minute cron; the cron stays the at-least-once guarantee.
