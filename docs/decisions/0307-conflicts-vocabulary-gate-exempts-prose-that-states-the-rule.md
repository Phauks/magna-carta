**A vocabulary gate has to be explainable without being breakable. The assertion rule gets one inline, per-line, reasoned exemption; the field rule gets none.**

**Context:** The conflicts-vocabulary gate bans two things in the conflicts package, the conflicts route, the web conflicts surfaces, and `docs/user/`: phrases that assert a matter is free of conflict, and response or read-model fields whose names read as a verdict. The rule cannot be documented without writing the sentence it bans — the comment explaining why the posture read has no aggregate contains the phrase, the fixture test that proves the gate fires has to hold every banned phrase as data, and the area's invariant list has to name the forbidden field names to forbid them. A gate with no exemption forces authors into two bad outcomes: word-golfing the prose until it no longer says what it means, or dropping the explanation entirely, which is how a mechanical rule loses the reasoning that justifies it. Special-casing comments automatically is worse than useless — the most dangerous strings in the codebase are user-facing prose, and `//` is one keystroke away from any of them.

**Decision:** (1) A line carrying `conflicts-vocabulary:allow — <reason>` is exempt from the **assertion-phrase** rule, and only that rule. (2) The marker binds to **one line**: it does not open a block, a file, or a directory, so an author cannot silence the gate for a region and a reviewer sees the exemption on the line it applies to. (3) The **verdict-shaped-field** rule has no marker: a field named `clear`, `clean`, `ok`, `passed`, or `conflictFree` in a scanned tree has no meta-use — the lint's own fixture data lives in `tooling/`, which is outside the scanned trees — so the rule that a caller could actually render stays absolute. (4) The gate self-tests both rules on every run against known-bad and known-good lines, including a line proving the marker does **not** exempt a field, so a pattern regression fails loudly instead of reading as a permanently green governance step.

**Considered & rejected:** _no exemption at all_ (forces word-golf or silence, and the reasoning is the part worth keeping); _exempting any line beginning with a comment marker_ (a rendered string is one `//` away, and the strings are the risk); _a file-level or block-level allowlist_ (an exemption that outlives the sentence it was granted for is how a fitness function goes quiet); _a separate allowlist file_ (the reason ends up far from the line, and nobody re-reads it).

**Consequences:** The gate can be explained in the code that implements it, in the tests that prove it, and in the area's own invariant list, without any of those becoming a hole. Every exemption is greppable, carries a reason, and is visible in the diff of the line it protects. The asymmetry is deliberate and is the part to preserve: prose can be read in context, a field name is rendered by whatever consumes it. Implements the fitness function required by the conflicts reporting-posture decision.
