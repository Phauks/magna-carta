**Matter shell, lifecycle & consultations: status `prospective → open → closed` where Prospective = an unnumbered consultation surfaced only in a per-attorney virtual Consultations folder (a filter, not a container); Open draws the number; Closed = archived-but-additive (leaves active lists, still accepts documents/notes) behind a named close-precondition hook — empty in slice 1·1, Phase 3 registers "all bills paid, no remaining balance"; pre-Directory client reference = display-only fields (`client_display_name`, `client_code`) with the `matter_party` role-on-the-link shape sketched but not created; matter types = per-firm data rows (name, code, active), custom-fields engine deferred to a shared design with Directory.** **Context:** slice 1·1 needs the matter shell before Directory (slice 1·3) exists; the owner's practice (design cycle, 2026-06-11) batches consultations in a special per-attorney matter and assigns no number until retention, and corrected the white paper's "Closed/Archived (read-only)" — closed matters must still accept late-arriving items and may close only with a zero balance. **Decision:** everything is a matter (one data model); consultations are individual Prospective matters so their documents never move on retention and (Phase 4) their parties feed conflicts permanently; the Consultations folder is `status = prospective AND responsible_member = X`; stale consultations (per-firm age setting, default 1 year) get a filter + bulk-close at launch, automation later; `reopen` exists permission-gated; closed prospectives are retained forever as conflict history; no link table until Directory designs the entity side (1·3 migrates the display fields into real links). **Considered & rejected:** a placeholder party/client table now (pre-decides Directory's shape, heavier 1·3 migration); creating the link table empty (foreign-key target doesn't exist; shape may shift in 1·3 design); a special consultations-matter entity (the virtual filter gives the same UX with zero extra model); read-only closed status (contradicts practice reality). **Consequences:** dense sequences, retention-year numbering, conflicts-complete consultation history, and a Phase 3 close gate that needs no schema change. Refines **ADR-0007**; revises the white paper _Matters and File Manager_ lifecycle line (amended same commit); builds on **ADR-0068** (permission-gated transitions). _Amended 2026-06-12 (slice 1·3 design, ADR-0087): the "custom-fields engine deferred to a shared design with Directory" line is resolved — the engine is promoted to its own **slice 1·4** (shape designed in the 1·3 spec)._
