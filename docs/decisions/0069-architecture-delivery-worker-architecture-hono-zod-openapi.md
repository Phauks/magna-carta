**Worker architecture — the `@hono/zod-openapi` Worker is the deployment entry point and owns `/api/*`; the SvelteKit SPA is built to pure static assets (`adapter-static`, `ssr=false`) and bound to that Worker via Cloudflare Workers Static Assets (`not_found_handling: single-page-application`, `run_worker_first: ["/api/*"]`); one origin, one deploy. Refines the white paper's `adapter-cloudflare` note.** **Context:** the white paper fixed Workers static-asset hosting + a SvelteKit SPA + same-origin `/api` on Hono (ADR-0066/ADR-0022) but named the adapter as `adapter-cloudflare` without resolving which framework _owns the Worker_. June-2026 doc verification settled it: `adapter-cloudflare` emits its own `_worker.js` and its docs require SvelteKit endpoints to own all routes, so a Hono/OpenAPI surface could only live nested inside SvelteKit's request lifecycle. Slice 0·1 (the Phase-0 walking skeleton) must settle the request-handling shape the platform inherits. **Decision:** (1) **Hono owns the Worker** — the `OpenAPIHono` app is `main`; the SPA is built with **`adapter-static`** (`ssr=false`, SPA `fallback: index.html`) to plain files and bound as Workers Static Assets (`assets.directory`, `binding: ASSETS`, `not_found_handling: "single-page-application"`, `run_worker_first: ["/api/*"]`). `/api/*` always hits Hono (billable); static files and SPA navigations serve from assets (free, off the Worker); unmatched paths rewrite to `index.html` (200). This is Cloudflare's documented full-stack pattern and makes the OpenAPI app _the_ server (the code-as-contract assumption of ADR-0066/0067), keeping the frontend a dumb static bundle that also loads trivially inside Tauri (ADR-0002/0023). (2) **One deployable, one origin** (`app.magnacarta.esq`); the reserved public `api.magnacarta.esq` token surface (ADR-0022) is not built here. (3) **Build ordering:** `apps/worker` build/dev/deploy `dependsOn apps/web#build`. **Considered & rejected:** **`adapter-cloudflare`, SvelteKit owns the Worker, Hono nested** (the literal white-paper note — but it subordinates the OpenAPI surface to SvelteKit's lifecycle, drags unused SSR machinery, and fights the adapter's "endpoints own all routes" model); **two Workers (web + api) same-origin via routing** (clean separation and mirrors the future `api.` split, but two deploys + routing config — premature for a login-gated app whose public API is reserved-for-later). **Consequences:** a single-origin, single-deploy app where Hono is unambiguously the server and SPA navigation stays off the Worker bill; the SPA is portable to Tauri unchanged; cost is one deliberate refinement of the white paper (`adapter-static` over `adapter-cloudflare`). **Refines** the white-paper _Delivery model_ adapter note (does not supersede its SPA-mode/Workers-static-assets intent); builds on **ADR-0005** (Workers static assets), **ADR-0066**/**ADR-0067** (Hono contract server), **ADR-0001** (API-first), **ADR-0002**/**ADR-0023** (Tauri reuse / parity). Detail in the _Phase 0 · walking skeleton_ spec.
