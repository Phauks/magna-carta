**URL & navigation architecture — matter-number-canonical permalinks by default (firm-configurable, opaque fallback), firm-from-session (never in the URL), host split (app/api/portal/marketing), tabs-nest/entities-flat, and server-side-only access enforcement (404-not-403).** **Context:** the _Delivery model_ committed to a deep-linkable URL per view but left the addressing scheme, host topology, identifier strategy, and confidentiality behavior unspecified — and matter numbers/names are explicitly **mutable** (renumbering, location prefixes, LEAP-preserved numbers, name/alias history), so the scheme must survive identifier change without breaking links, while staff want to read the matter number in the address. **Decision:** (1) **Every matter carries an immutable opaque handle** (always resolvable plumbing), but the **canonical human-facing URL is the matter number by default** (`/matters/8181-3`) — staff think in numbers and a number leaks **no client identity** (unlike a party-name caption, so **name slugs are rejected**). The scheme is **firm-configurable** (_Settings & configuration_, ADR-0040): matter-number default, **opaque** selectable for maximum confidentiality, and a **per-matter force-opaque override** for sealed/sensitive matters (the settings scope chain: matter-override → firm-default). Resolution is **firm-bound** — a number need only be unique within the firm, so two firms may share `8181-3`. (2) **Link stability is engineered, not free:** prior numbers are **kept as aliases that 301-redirect** to the current one, and the opaque handle always resolves, so renumber/rename never breaks a saved link; an **un-numbered prospective matter** uses its opaque handle until _Open_. Matter-numbering config is constrained to **URL-safe characters** (no `/`/space, else percent-encoded). Entities with **no human number stay opaque** (documents, Directory entities, calendar events); numbered records (matters, invoices) use their number. (3) **Firm comes from the session, never the URL** — no firm segment to spoof; hosts split into `app.` (staff SPA, same-origin `/api`, cookie auth + CSRF), `api.` (**reserved**; public/SDK OpenAPI surface, token auth, no cookies/CSRF), `portal.` (client-portal external principals), and `magnacarta.esq`/`www` (marketing/help/intake/public product-updates). (4) **Path = addressable state, query = ephemeral refinement**; canonical, no trailing slash. (5) **Tabs nest, entities stay flat** — sub-views nest under the parent (`/matters/8181-3/documents`), entities with their own movable identity stay shallow (`/documents/{id}`); **the last identifier resolves and earlier segments are advisory** (a stale parent or superseded number 301-redirects to canonical). (6) **A maintained reserved route-namespace list** prevents feature/system route collisions and stops any user-influenced segment (a matter number, an intake-form path) shadowing a system route. (7) **Access enforcement is server-side on every API request (session → firm → RBAC + ethical walls); the SPA route guard is UX only**, never the boundary — logged-out → **401** → login-with-return-to; a **cross-firm matter is absent from your firm's separate D1 → 404 with no cross-database path to forget** (structural isolation, ADR-0003); unauthorized-but-existing resources (incl. ethical-walled matters) return **404 not 403** to avoid an existence oracle. Matter numbers are **enumerable by design and that grants nothing** (every request is gated; guessing reveals only volume to someone already inside the firm, never a name or access — a firm that must deny even that picks opaque); **`Referrer-Policy: same-origin`** keeps any URL out of third-party `Referer`. **Considered & rejected:** **opaque-only with no firm choice** (most confidential but staff lose the readable matter number; offered as the configurable/forced option instead of mandated); **name/caption slugs** (leak the party caption into history/referrer/shoulder-surf — disqualified, though the _number_ is kept because it carries no client identity); **matter number as the sole key with no opaque handle** (would break links on renumber and has no handle for un-numbered prospective matters — solved by keeping the opaque handle underneath + redirect aliases); **per-firm vanity subdomains** (`firm.magnacarta.esq` — reintroduce a mutable firm slug for branding that white-label custom domains deliver better; the _custom-domain_ seam is kept); **firm-in-path / tenant-in-URL** (a redundant, spoofable second source of truth over the session). **Consequences:** the default URL is readable (`/matters/8181-3`) yet stable across renumber/rename and leaks no client identity; confidentiality remains **structural** (separate-DB 404 + 404-not-403) independent of the chosen scheme; cost is the alias/redirect + URL-safe-number machinery and a per-firm/per-matter setting. Builds on **ADR-0001** (SPA/API-first), **ADR-0003** (tenancy/isolation — the separate-DB 404), **ADR-0004** (RBAC/ethical walls), **ADR-0005** (Workers static assets), **ADR-0007** (configurable matter numbering — now URL-safe-constrained), **ADR-0022** (OpenAPI surface on `api.`), and **ADR-0040** (the scheme setting); the white-label custom-domain path and the reserved-namespace registry are carried-forward seams.
