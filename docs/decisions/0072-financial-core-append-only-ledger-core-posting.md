**Append-only ledger core — posting model: direction + always-positive amount lines, a structural account model (no CoA product), materialized per-account balances with bounds-CHECK as the D1 batch-abort mechanism, dual entry dates (civil `effective_date` + UTC `recorded_at`), first-class linked reversals; realized as `@magna-carta/ledger` (first domain package) with the `@magna-carta/fixtures` harness calling the domain write paths directly.** **Context:** ADR-0008 fixed the append-only double-entry ledger as the Financial Core's foundation but left the posting model, line encoding, balance mechanism, and correction semantics undesigned; slice 0·3 builds the ledger as the first real consumer of the slice 0·2 primitives, under D1's no-interactive-transactions reality (ADR-0063/0064 amendments: every write is one atomic `batch()`), and must leave the no-negative-trust invariant (ADR-0009, Phase 3) enforceable with zero write-path retrofit. The line encoding is permanent-storage representation — the expensive-to-migrate part (the ADR-0061 logic). **Decision:** (1) **Line encoding = direction + always-positive amount** (`direction TEXT 'debit'|'credit'` + `amount_minor INTEGER CHECK (> 0)` — the Modern Treasury shape): structurally eliminates the silent sign-flip (a flipped sign still sums to zero; direction-as-data must be _stated_, negative/zero lines are impossible at the schema), keeps permanent rows journal-legible for bar audits/exports, and keeps amounts in the domain `allocate()` (ADR-0061) operates in; the balance aggregate is one CASE expression written once in the domain layer. (2) **Structural account model, no CoA product:** `ledger_account` carries type (asset/liability/equity/income/expense; normal balance derived in code, never a column), single currency (lines inherit — no currency column on lines), a parent/subledger seam (a Phase-3 client trust ledger is just a child account row), and soft-close `active` (accounts are never deleted); chart-of-accounts management UI/numbering is Phase 3 on this unchanged schema. (3) **Materialized `account_balance` now, bounds seam included:** one row per account in **normal-balance terms** (positive = normal, so trust bounds read as the rules are written), updated in the same batch as every posting, with nullable `min`/`max` bound columns and a CHECK — **a failed CHECK is D1's only mechanism for aborting a batch on a business condition**, so when Phase 3 sets a trust child's min to 0 an overdraw rolls back the entire posting atomically with zero retrofit; a fitness query proves SUM(lines) = balance. (4) **Dual dates by kind (ADR-0055):** backdatable civil `effective_date` (`YYYY-MM-DD` — what statements/reconciliation key off; no zone column, zone resolution is a boundary concern) + immutable system-set UTC `recorded_at` (audit truth; the gap between them is audit signal); no future-dating beyond the injected clock's today. (5) **First-class reversals:** `reverses_entry_id` UNIQUE FK + `reverseEntry` composing the exact mirror; reversed status derived from the link, never a flag; double-reversal structurally impossible under race (the loser's batch rolls back); the Phase-3 adjustment workflow composes on these primitives additively. (6) **Validation = ledger invariants only:** balanced ≥ 2-line single-currency entries, active leaf accounts only (parents are roll-ups), non-empty description; consumer rules (trust bounds values, period close, type-posting warnings) defer to their consumers atop existing seams. (7) **Packages:** `@magna-carta/ledger` is the first domain package (`ledger → data-access → database → identifiers`, `ledger → money` — acyclic per ADR-0070/0071), validating in memory and composing statements into the `composeEffectBatch` chokepoint; `@magna-carta/fixtures` realizes ADR-0034 — one seed → `FixtureContext` (seeded faker + fixed clock + the ADR-0062 seeded identifier source; byte-identical replay), layered factories with **the domain service as the canonical write path forever** (HTTP, arriving slice 0·5, is just another caller), named scenarios with baked-in assertions (`retainerDeposit`, `trustCorrection`, `boundsRejection`, `multiLineSettlement`) doubling as write-path integration tests, a tiny demo CoA explicitly bounded as demo-only, and a production guard (explicit opt-in + environment assertion + package never imported by production code). **Considered & rejected:** **signed single-column lines** (prettiest SUM but the sign _is_ the direction — a `negate()` in the wrong branch posts a balanced, wrong, undetectable entry on the table where that is most catastrophic); **two-column debit/credit** (journal-familiar but a per-row XOR CHECK, two-column aggregates everywhere, and a column-swap is still silent); **derive balances by SUM until trust needs them** (forces Phase 3 to retrofit materialization into every posting batch right when stakes are highest); **convention-only corrections** (lineage in prose, double-reversals possible, Phase 3 builds the linked version anyway); **full adjustment workflow now** (Phase-3 product surface with no consumer; composes later on these primitives); **ledger inside `data-access`** (mixes domain rules into the generic access layer — the exact seam ADR-0071 split on); **a full timestamp for `effective_date`** (drags in a zone; a check "dated June 27" renders June 26/28 by viewer — the precise bug ADR-0055 forbids). **Consequences:** the Financial Core's foundation is posting-correct by construction — sign-flips impossible, balance enforcement atomic, corrections linked, audit dates honest — and Phase 3 trust/billing/GL land on seams (bounds, effective-date, reversal links, subledger accounts) that already exist; fixtures are valid by construction and double as integration coverage; cost is the materialized-balance consistency discipline (fitness-checked), the leaf-only posting rule, and two new packages. The ROADMAP's slice 0·3 API-spike side-task is corrected as already resolved (ADR-0066 + the empirical spike suite). Extends **ADR-0008** (does not supersede); reuses **ADR-0061** (money/rounding), **ADR-0062** (client-minted ids enable up-front batch binding; seeded source), **ADR-0063/0064 as amended** (single-batch write path, outbox `ledger.entry.posted`), **ADR-0065** (migrations), **ADR-0070/0071** (package boundaries), **ADR-0034** (fixtures), **ADR-0055** (time by kind), **ADR-0051** (fitness functions); prepares **ADR-0009** (trust bounds) and Phase 3.
