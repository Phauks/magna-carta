**In-app conversion stays in-house only — confidentiality absolute, one engine per edge; the pluggable external-engine model is reconsidered and rejected.** Affirms and extends **ADR-0030**.

**Context:** an earlier 2026-06-21 reframe proposed a pluggable model — external engines (Microsoft 365, Adobe) as peer adapters with a per-firm egress policy and a per-content-class `in-tenant`/`egress` posture on each capability descriptor — to allow firms to opt into outside engines. Reconsidered the same day: the model's load-bearing assumption is that the platform can reliably decide which content is safe to egress. In a law practice **nearly all content is privileged or confidential by default**, so any classifier that ever returns "safe to send to a third party" is one wrong call away from leaking privileged client material — an ethics/malpractice event, not a recoverable bug. The egress policy + content-classification is a large product and code surface whose only purpose is to manage a risk the platform can simply decline to take, and the fidelity advantage of external engines over the in-house engines (LibreOffice et al.) is marginal.

**Decision:** (1) **Conversion is in-house only.** Bytes go R2 → our in-tenant Container/WASM → R2 and **never** egress to a third party; ADR-0030's confidentiality guarantee stands **without exception**. (2) **Architecture retained:** a `ConversionPort` with engine adapters, and a **format registry** of formats + **weighted, single-engine edges** with **multi-hop pathfinding** (`WPD → ODT → PDF` computed when no direct edge exists). **One engine per edge** — no candidate ranking, no `confidentiality` axis, no `EgressPolicy`, no `ContentClass`. (3) **No content classification of any kind.** (4) The port/adapter seam is kept because it is good design in-house (testable, swappable engines) and it leaves a clean path for a future, **deliberate** decision to add an external adapter *iff* a format ever genuinely requires one — but none is enabled and **no speculative policy machinery is built** now.

**Consequences:** removes the subsystem's worst failure mode (privileged egress) and an entire product/policy surface; reaffirms ADR-0030 as an absolute guarantee; reverses the 2026-06-21 pluggable reframe **before any code** (design-stage only — the cost is doc edits). Builds on **ADR-0091**/**ADR-0092** (the integration port architecture, reused for in-house adapters). The pure core (`ConversionPort`, registry, pathfinding) + the libvips adapter are built substrate-independently; the orchestrator/Container/Durable-Object execution and the registry storage model remain deferred to the gated 2·4 design cycle.
