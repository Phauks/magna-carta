**Cloudflare resource naming, environment model & deploy path — resources are named `magna-carta-<environment>-<scope>[-<purpose-or-slug>]` (environment baked in from day one because D1/R2 cannot be renamed; `platform` scope = the handful of shared resources, `firm` scope = the per-tenant fleet, so the two sort as adjacent blocks at any fleet size); per-firm resource names are NEVER derived from firm handles (R2 names allow only lowercase/digits/hyphens; `frm_` handles contain uppercase/underscores) — the provisioner mints a dedicated lowercase slug per firm, one slug naming both its D1 and its R2 bucket, recorded in the firm registry and never parsed; queues grow by PURPOSE, never per firm (queues are shared transport carrying firm-tagged pointers; isolation lives in per-firm D1/R2 + the firm-scoped data-access layer, ordering in the outbox `seq` — per-firm queues rejected as a consumer-config explosion buying no isolation); production deploys go through Cloudflare Workers Builds (the dashboard GitHub connection) rather than a GitHub-Actions-held API token, with GitHub Actions remaining the test/quality gate and PR preview deploys disabled until an isolated `staging` environment exists (previews would bind production data).** **Context:** first real deploy required creating the production resources, which forced the permanent naming decision; the owner chose the Workers Builds path over token custody. **Created 2026-06-09:** `magna-carta-production-platform-control` (D1, `a0982ab7-97d9-471b-8dd7-19f18aa53f04`), `magna-carta-production-platform-files` (R2 — documented walking-skeleton placeholder until per-firm buckets land in slice 0·4), `magna-carta-production-platform-jobs` (Queue). **Environment model:** local dev/tests are Miniflare-only (no cloud twins); the demo tenant is a firm inside production, not an environment; `staging` is the probable second environment (returns PR previews), `loadtest` a possible ephemeral third (the golden-rule-10 harness against real infrastructure). **Consequences:** binding names (`DB_CONTROL`, `R2`, `QUEUE`) stay the code-facing contract; Workers Builds deploys what reaches `main` independent of Actions, mitigated by PR-only merges with green CI; the known manual step from ADR-0073 (new firm D1 binding = config commit + deploy) is unchanged. **Rejected:** environment-less names (unrenamable resources would force a parallel-rename migration later); deriving resource names from firm handles (charset mismatch + names-as-data is the wrong coupling); per-firm queues; the GitHub-Actions API-token deploy path (workable, declined by the owner for custody simplicity).
