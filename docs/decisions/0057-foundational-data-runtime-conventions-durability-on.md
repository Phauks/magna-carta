**Durability on close / graceful shutdown — no close is trusted to be graceful: durability is engineered _before_ the close (acknowledged-write source of truth + idempotency + transactional outbox + on-disk desktop queue + DO durable storage + at-least-once idempotent Queues), and shutdown hooks are best-effort flush-then-warn only, never the correctness mechanism.** **Context:** the cloud is the source of truth (ADR-0003), so "losing data on close" reduces to one class — **client-held state the server has not yet durably accepted** — across four surfaces (web tab/window close, desktop quit, server Workers/DO lifecycle, logout/session end); a design that leans on a clean shutdown hook firing loses data on a crash, kill, or power cut, so the convention must make loss impossible independent of the hook. Cross-cutting and expensive to retrofit, so settled here in _Foundational data & runtime conventions_ alongside the time model (ADR-0055). **Decision:** adopt the **prevent → loud → discipline** ordering (ADR-0051). **(1) Loss made impossible:** an acknowledged write is durable server-side; **idempotency keys** + the **transactional outbox** (queued §9 members) make replay-on-reconnect safe; the **desktop (Tauri) outbound mutation queue is on-disk** (ADR-0054), surviving quit _and_ crash and replaying next launch; **Durable Object state — the cross-device live timer (ADR-0033), job orchestration (ADR-0039) — lives in DO durable storage, not memory**, so hibernation/eviction/deploy are lossless; **Queues are at-least-once with idempotent consumers** so an interrupted job (OCR/conversion/discovery/export) retries; long local desktop jobs **checkpoint** to resume rather than corrupt. **(2) Loss made loud:** a close/logout carrying unacknowledged state trips a guard — web `beforeunload`/`visibilitychange`, Tauri `close-requested` — that **flushes first, then warns only if loss is genuinely unavoidable**; editor/form input **autosaves as server-side drafts** so it is never purely tab-local. **(3) Discipline last, per surface:** web close → guard + autosave (the timer is DO-backed, survives the tab); desktop quit → intercept, drain/persist the queue + confirm checkpoints (offline quit safe by construction); server → stateless handlers complete-or-fail under idempotent retry, no correctness on clean teardown; logout → cache-clear (ADR-0054) **gated on the outbound queue being drained or persisted**. **Enforced, not trusted:** the close/logout guard is a **single shared client primitive** (not per-screen), and a **coherence fitness function** (ADR-0051) asserts live-timer/job state is written through DO durable storage, not held only in memory. **Considered & rejected:** **shutdown-hook-as-durability** (loses on crash/kill/power-loss — hooks are best-effort UX only); **warn-only / "you have unsaved changes"** with no durable queue (data still lost when the user is forced to quit or the OS kills the app); **a full local-first sync engine** as the close-safety mechanism (rejected platform-wide in ADR-0054 — fights the server-authoritative ledger; the on-disk outbound queue is the bounded subset that suffices). **Consequences:** loss-on-close is prevented by construction across all four surfaces; cost is carrying the on-disk queue + draft-autosave plumbing and holding the discipline that DO/job state always lands in durable storage. Per-tier flush/checkpoint/autosave **intervals are deferred to the build** — the convention binds now, the numbers arrive with the code (the same intentional seam as ADR-0039). Reuses **ADR-0003** (source of truth), **ADR-0054** (desktop queue + cache model), **ADR-0033** (live timer), **ADR-0039** (job DOs / compute placement), **ADR-0051** (fitness function); depends on the queued **idempotency** and **transactional-outbox** §9 members.
