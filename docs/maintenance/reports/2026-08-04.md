2. **Root cause of the divergence: `assemble-docs.yml` checks out shallow.** `build-decisions.mjs`
   orders pending fragments by `firstCommitTime` — a `git log --diff-filter=A` on each fragment path —
   and falls back to alphabetical when that yields nothing. The workflow uses `actions/checkout@v7`
   with no `fetch-depth`, so the runner has a depth-1 clone, every fragment scores
   `Number.MAX_SAFE_INTEGER`, and the tie-break assigns ADR numbers **alphabetically by slug** instead
   of chronologically. Fix: add `fetch-depth: 0` to that workflow's checkout step. Until then, every
   bot-assembled ADR batch is numbered in the wrong order, silently.
