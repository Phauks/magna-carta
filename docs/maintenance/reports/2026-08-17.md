## A second instance of the ADR cross-reference bug — and why it's a different bug this time

Last report found and fixed nine dangling `ADR-<slug>` references and diagnosed the cause as
`rewriteReferences` walking only `docs/`. This run found one more, inside the assembled batch itself:
`docs/decisions/0306-the-neutral-refusal-becomes-a-fitness-function.md` cited
`` `ADR-invitation-refusal-reports-only-the-caller-budget` `` (ADR-0281 in the same batch) and the
reference was never rewritten, even though both files are under `docs/`. The cause is different from
last time: `assemblePending()` reads **all** pending fragments into memory before numbering any of
them (`readPendingRecords`, called once, up front), then writes each numbered file from that frozen
in-memory copy. `rewriteReferences` does walk the disk correctly mid-loop and does patch a
not-yet-numbered pending file sitting on disk — but the in-memory record for that same fragment was
already captured before the patch landed, and the later `writeFileSync` overwrites the disk with the
stale in-memory text. So any reference from one fragment to another **fragment in the same batch**
cannot survive assembly, regardless of processing order — only cross-batch references (this batch
citing a previously-numbered ADR) go through `rewriteReferences` cleanly. Repaired by hand here (one
occurrence, verified no others in ADR-0281-0375 by grepping the batch for `ADR-[a-z]`). The tool fix —
re-read each pending file's current disk content immediately before serializing it, instead of reusing
the pre-loop snapshot — is left to an owner; it is application-adjacent tooling, not a doc.

Three further dangling references predate this window and were repaired the same way: `CHANGELOG.md`
still named `ADR-ai-inference-client-consent` (now ADR-0109), and two already-numbered decision files
still named slugs from their own era — `docs/decisions/0217-...md` named
`ADR-consensual-guided-data-conversion` (now ADR-0214) and `docs/decisions/0165-...md` named
`ADR-ai-text-detection-architecture` (now ADR-0163). `docs/specs/2026-08-13-unified-identity-design.md`
carries two more slug-style references, but both already have the resolved number written in
parentheses immediately after them (author habit, not a defect) — left alone.
