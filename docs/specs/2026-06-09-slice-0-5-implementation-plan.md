# Slice 0·5 Implementation Plan — API contract pipeline

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build slice 0·5 — the OpenAPI 3.1 code-as-contract pipeline: `RouteMeta` + `defineOpenAPIRoute`, the ordered chokepoint middleware (ADR-0067), the RFC 9457 error model, the committed spec snapshot with Spectral/oasdiff/Prism CI gates, and the generated typed client — wired onto the real routes.

**Architecture:** Every route becomes a `defineOpenAPIRoute(meta, route, handler)` bundle: `RouteMeta` is emitted as both the OpenAPI-native `operationId`/`tags` and `x-mc-*` extensions, and one chokepoint middleware reads it to enforce session→firm → authn → RBAC → idempotency → rate-limit in that fixed order. The emitted 3.1 document is a **committed snapshot** (`apps/worker/openapi/openapi.json`): CI re-emits and fails on drift (code-as-contract enforcement), Spectral lints it, oasdiff gates breaking changes against the base revision, Hey API regenerates the committed typed client (`packages/api-client`) and fails on drift, and conformance fitness tests assert the §3.5 security posture over it.

**Tech Stack:** `@hono/zod-openapi` 1.4.0 + zod 4 (in place), `@hey-api/openapi-ts` + `@tanstack/svelte-query` plugin (validated by the spike), `@stoplight/spectral-cli`, `@stoplight/prism-cli`, oasdiff via its official GitHub Action, Node-native TS execution for the emit script.

**Spec:** [`2026-06-04-api-contract-design.md`](2026-06-04-api-contract-design.md) (ADR-0066/0067) · spike findings in [`docs/conventions/api.md`](../conventions/api.md) · **depends on slice 0·4 being merged** (uses `resolveSession`, `@magna-carta/access-control`, the idempotency middleware, and migrates the 0·4 routes onto the chokepoint). **Split-start (decided 2026-06-11):** Tasks 1–6 — the contracts layer (problem module, pagination, `RouteMeta`, rate-limiter seam, dev response validator) — build off main immediately; their only 0·4 import, the `Permission` registry, is already merged. **The build pauses after Task 6** and resumes at Task 7 (the chokepoint, which consumes 0·4's `resolveSession`) once 0·4 lands. Tasks 6/7 were swapped from the original order so the pause is a clean suffix.

## Decided up front (read before coding)

1. **The snapshot is committed, and CI re-derives it.** `apps/worker/openapi/openapi.json` is generated by `apps/worker/scripts/emit-openapi.mts` (Node ≥23 runs TS natively — the spike pattern) and committed. CI runs the script and `git diff --exit-code` on it: a route change without a spec change fails review (spec §8.2). The same file is oasdiff's head revision and Hey API's input — one artifact, three gates.
2. **`operationId` is emitted natively from `RouteMeta.operationId`** (`subsystem.action`), _and_ as `x-mc-operationId` — the spike showed Hey API needs the native field for stable SDK names. `tags` defaults to the route module name; `description` is **required** by `defineOpenAPIRoute`'s type (Spectral's base ruleset flags it missing — spike finding).
3. **Conformance assertions split by tool:** the §3.5 logic-bearing checks (mutating⇒audited, permission∈registry, money-routes⇒idempotency-required, no-silent-public, surface consistency, operationId uniqueness/shape) are **Vitest fitness tests over the emitted document** — the spike's proven pattern, debuggable, typed against `PERMISSIONS`. Spectral carries the **hygiene ruleset** (`spectral:oas` + info/servers/tags/description rules). Don't write Spectral custom functions for what Vitest already does better.
4. **Rate limiting is a seam with a real-but-modest default.** `RateLimitBucket` names are data (`"default"`, `"auth"`, `"expensive"`); the Phase 0 enforcement is a per-isolate in-memory sliding-window limiter behind a `RateLimiter` interface — honest limitation (per-isolate, resets on eviction) documented in code; a distributed (DO/KV) limiter is a later adapter behind the same interface. The chokepoint position and the 429 problem shape are the contract being locked now.
5. **The chokepoint replaces 0·4's in-handler checks.** `firms`/`members`/`me` migrate to metadata-declared `permission`/`idempotency`; their handler-level permission code is deleted (the §3.4 failure mode — per-handler discipline — must not survive this slice). `POST /v1/firms` keeps its platform-admin-secret guard via `surface: "public"` + `authenticated: false` + an explicit allow-list entry (the documented exception, asserted by the fitness test).
6. **404/403 semantics are centralized in the chokepoint** (ADR-0052/0068): cross-firm/unknown → 404 problem; within-firm permission denial → 403 problem with `requestAccess: true` extension field (the request→grant _flow_ stays out of scope — the field is the seam).
7. **Dev-only response validation** (`spec §4`): a middleware that parses outgoing JSON against the route's response schema and throws on divergence, enabled when `env.ENVIRONMENT === "development"` (Miniflare/`wrangler dev`) and in tests — never in production (double-parse cost).
8. **The generated client is committed** at `packages/api-client/` (`.gen.ts` files from Hey API + `@tanstack/svelte-query` plugin, plain-object `openapi-ts.config.mjs` — the spike's jiti finding). CI regenerates and diff-fails on drift; `apps/web` imports it in later slices without a local generation step. `openapi-generator`/Speakeasy for non-TS SDKs stays a documented seam (no consumer yet — YAGNI).
9. **oasdiff runs as its official GitHub Action** (Go binary; verify the current action ref at build — `oasdiff/oasdiff-action`), comparing the base branch's committed snapshot to the PR's, `breaking` mode, fail-on `ERR`. 3.1 support is beta (verified in the spike research) — if the action chokes on a 3.1 construct, record the workaround as an ADR-0066 amendment.
10. **Prism is a dev command + one CI smoke test:** `pnpm --filter @magna-carta/worker run mock` serves the committed snapshot; CI starts it, curls one mocked route, asserts a 2xx envelope. Frontend/plugin consumers get their mock server from the snapshot, not from a running backend (spec §8.4).
11. **Problem `type` URIs are a registry** (spec §4): `apps/worker/src/contracts/problem-types.ts` — a const map `problemType("validation")` → `https://api.magnacarta.esq/problems/validation`; unknown keys are compile errors. Starts with: `validation`, `unauthenticated`, `permission-denied`, `not-found`, `idempotency-key-missing`, `idempotency-key-conflict`, `idempotency-fingerprint-mismatch`, `rate-limited`.
12. **Versioning starts now:** all business routes mount under `/api/v1` (the existing `/api/health` stays unversioned platform plumbing, documented); the snapshot's `servers` carries `https://api.magnacarta.esq/v1` + the app-surface origin (Spectral hygiene + spec §6 hosts; actual DNS attach is still deferred ops).

### Task 4: `RouteMeta` + `defineOpenAPIRoute` (`src/http/contracts/route-meta.ts`)

TDD — this is the centrepiece type:

```ts
import type { Permission } from "@magna-carta/access-control/registry";

export type RateLimitBucket = "default" | "auth" | "expensive";
export interface RouteMeta {
  operationId: string; // 'subsystem.action' — ^[a-z][a-zA-Z0-9]*\.[a-z][a-zA-Z0-9]*$
  surface: "app" | "public" | "portal";
  authenticated: boolean;
  permission: Permission | null; // null only when authenticated: false
  resource: "matter" | "firm" | "location" | "directoryEntity" | "portalShare";
  audited: boolean;
  idempotency: "required" | "optional";
  rateLimit: RateLimitBucket;
  tags?: string[]; // default: [operationId namespace]
  deprecated?: boolean;
}
```

`defineOpenAPIRoute(meta, routeConfig)` returns the `createRoute` result with: native `operationId` = `meta.operationId`, `tags` defaulted from the namespace, `description` required (compile error if absent), every meta field spread as `x-mc-<field>`, and the meta object attached for the chokepoint (exported `routeMetaOf(route)` accessor — a `WeakMap`, not a magic property). `defineOpenAPIRoute` must also mark the `idempotency-key` header parameter `required: true` in the emitted document when `meta.idempotency === "required"`: the shared `idempotencyKeyHeader` fragment is optional at the schema layer because presence enforcement belongs to the chokepoint, and without this flip the generated client types the header optional on routes that demand it and Prism mocks won't model the requirement. Note also that the chokepoint runs before route validation once Task 7 lands, so the fragment's "would preempt" comment becomes historical at that point. Tests: emitted operation carries native + x-mc fields; tags default; missing description rejected at type level; `routeMetaOf` round-trips. Commit `feat(worker): RouteMeta + defineOpenAPIRoute — metadata emitted natively and as x-mc extensions`.

### Task 5: Rate-limiter seam (`src/http/chokepoint/rate-limiter.ts`)

TDD. `interface RateLimiter { check(bucket: RateLimitBucket, key: string): { allowed: boolean; retryAfterSeconds?: number } }`; `BUCKETS: Record<RateLimitBucket, { limit: number; windowSeconds: number }>` (`default` 100/60s, `auth` 10/60s, `expensive` 10/60s — generous, values are the deferred seam); in-memory sliding window with injectable clock. Tests: under-limit allows; over-limit denies with retry-after; window slides; buckets isolated per key. The per-isolate limitation is a documented code comment + api.md note (Task 14). Commit `feat(worker): named rate-limit buckets behind a RateLimiter seam`.

**Amendment (decided during the Task 5 review):** `RateLimiter.check` returns `RateLimitVerdict | Promise<RateLimitVerdict>`, not the sync-only shape above — the future distributed adapter (Durable Objects or KV) must await I/O, and a sync-only seam would force a breaking interface change at adapter time. The in-memory implementation stays synchronous (`InMemoryRateLimiter` narrows the return back to the plain verdict); the Task 7 chokepoint always `await`s the result, which is free on a plain value.

**0·5b forward-obligations (from the 0·5a adversarial pass, 2026-06-12) — fold into the tasks below:**

- **Component-name uniqueness fitness function (Task 8/10).** zod-to-openapi 1.4.0 does NOT throw on duplicate `.openapi(name)` registration — it silently first-write-wins, so two components (e.g. two `paginated(X).openapi("…")` list pages) registered under a colliding name produce a document where one masquerades as the other. Add a conformance fitness function asserting every registered component name is unique. (The "fail loud at emission" promise the contracts layer makes does not hold for this case without it.)
- **Tenant-scope the rate-limit key (Task 7).** `RateLimiter.check(bucket, key)` takes a caller-supplied key; the chokepoint MUST derive it as `firmId`-scoped (and IP/session-scoped for `auth`/unauthenticated buckets) or one firm's traffic could consume/evade another's bucket.
- **Migrate the data-access idempotency middleware to `problemJson` (Task 8).** `@magna-carta/data-access`'s Hono idempotency middleware still replies with bare `{ error: "…" }` JSON; the `idempotency-key-missing`/`-conflict`/`-fingerprint-mismatch` problem types exist to replace those — migrate so the one-error-shape claim holds.
- **Posture note for `api.md` (Task 14):** record "no secret-bearing field is validated through the body/query/header validators that feed `defaultHook`" — `defaultHook` reflects `issue.message` into `errors[].detail`, so a future secret-bearing schema field could leak its value back to the caller on a validation failure.

### Task 7: The chokepoint middleware (`src/http/chokepoint/chokepoint.ts`)

TDD with fakes (fake session resolver, permission reads, limiter). The §3.4 **fixed order** — resolve session→firm → authn (`401` problem if `meta.authenticated` and no session) → RBAC (`404` problem if the resource’s firm context is absent/foreign — ADR-0052; `403` problem + `requestAccess: true` if visible-but-denied) → idempotency (apply the 0·4/0·2 Hono idempotency middleware when `meta.idempotency === "required"`) → rate-limit (`429` problem + `Retry-After` header) → handler. Resolves meta at registration time from the route bundles via `routeMetaOf` — app.ts iterating the bundles, or per-route middleware closing over the meta. The WeakMap key is the exact `defineOpenAPIRoute` return object; it does **not** survive into the library registry (`app.openapi()` rest-destructures the route, so the openAPIRegistry stores a shallow copy) or into Hono's request-time `matchedRoutes`, so meta can never be looked up from the matched route. A registered `/api/v1` route **without** meta throws at startup (registration-time assertion, not per-request). **Amendment (recorded at the pre-pause review, 2026-06-12):** the 403 `requestAccess: true` reply requires an extension channel `problem.ts` does not yet have — `ProblemOptions`/the `Problem` schema are closed to the RFC 9457 fields + `errorId`/`errors[]`. Task 7 adds the extension seam to `problem.ts` (an optional, typed extensions field — not an open passthrough) together with its chokepoint consumer; Task 8 declares the extended 403 response schema. This is planned work, not scope drift. Tests: each gate in isolation; the order itself (a request failing authn never touches the limiter — fakes record invocation order); `surface: "public"` routes skip cookie/CSRF assumptions. Commit `feat(worker): ADR-0067 chokepoint — ordered tenancy/authn/RBAC/idempotency/rate-limit enforcement`.
