## 1. Scope

**In 2·2:** an isolated Collabora container per open document, coordinated by a per-document Durable Object; the client-agnostic WOPI host; the editor-launch + access-token path; the `current` working object + immutable version-cut; the Standard→IA tiering _mechanism_ (conservative trigger); real-time browser co-editing; never-blocked read; the offline working-copy check-out/check-in path (through quarantine ingest) with conflict-copy-on-divergence + a human reconcile-to-resolution flow; the opt-in exclusive lock; the stale-lock clearing policy; the keep-alive + durable-reconnect reliability work; the `documents:` permission namespace; the editor-iframe origin/CSP posture.

**Deferred / fast-follow (§11):** the polished in-app Compare/redline reconciliation UI (lean on desktop Word Compare initially); one-click "Open in desktop Word" (WOPI-desktop client); Office-for-web as an alternate WOPI client; periodic auto-checkpoints; the ADR-0077 delta-compression pipeline; aggressive auto-tiering policy; client-portal (external) editing; container pooling (**red-flagged**, §2).

## 2. Hosting topology (`ADR-collabora-editing-host-topology`)

**One isolated Collabora container per open document, coordinated by a per-document Durable Object** (`DocumentSession`, addressed by `fileId`). **Pooled / shared coolwsd is forbidden** (owner red-flag): a shared coolwsd serving many documents lets one document's crash or memory runaway drop every co-resident session, and puts multiple firms' documents in one process tree — both unacceptable, and a violation of firm-scoping (golden rule 3) at the compute layer. The ~$8–100/mo amortization a pool would save (in-cycle cost model) does not justify the blast-radius and isolation cost.

- **The `DocumentSession` Durable Object** owns, in its **`ctx.storage` SQLite** (durable across container sleep/eviction — never plain DO class fields, which do not survive hibernation): the live-session participant set, the WOPI session-lock value + coolwsd affinity, the version-cut state, the `current`-object metadata (hash/size/server-assigned timestamp), and a pointer to any durable exclusive-checkout lock. It spawns/sleeps its container and runs the keep-alive + heartbeat alarms (§9).
- **Open-speed.** Cold-open is mitigated with Cloudflare's **native instance pre-warming (`min_instances`) + image pre-fetch**, sized by the §9 spike against the ~1–3 s platform cold start (plus coolwsd boot). A hand-rolled "warm pool claimed per `fileId`" is **rejected** — it collides with `getContainer(binding, fileId)` keying (a generically-keyed warm instance is a different DO id than the per-`fileId` one, so an open would route to a cold instance). Built-in container autoscaling/routing is roadmapped at Cloudflare and may later supersede whatever warming we configure.
- **Dispatch seam (not pooling).** The DO reaches its editing backend through a `getEditorBackend(fileId)` indirection with one implementation today (the per-document container). The seam keeps the editor backend **swappable** — Collabora today, Office-for-web or a desktop-Word check-out path later (§3) — **never** to pool documents into one coolwsd.
- **coolwsd container least-privilege (security.md untrusted-file bar).** coolwsd is a native document processor handling attacker-craftable `.docx` — treat an escape as possible. The container has **no egress** (or a tight allowlist to the host only), **no R2/D1 credentials and no key material** (all object I/O flows through the host WOPI surface, authenticated by the per-document token, §4), is **ephemeral per document**, and runs under resource caps. Cross-firm reachability is structurally impossible: a container can only reach its own document's host endpoints.
- **Account ceiling is a non-constraint** (6 TiB / 1,500 vCPU; early demand <1%).

## 3. The WOPI host — client-agnostic (`ADR-collabora-editing-host-topology`)

We are the WOPI **host**; Collabora is the WOPI **client**. The host is built to the **standard `X-WOPI-*` contract as the baseline**, with Collabora's `X-COOL-WOPI-*` extensions **additive** — the single choice that keeps both Word futures (Office-for-web client; desktop-Word check-out) reachable without a rebuild.

Host surface (per-document, fronted by the `DocumentSession` DO):

- **Tenancy at _use_, not just at mint (load-bearing).** For `GetFile`/`PutFile`/`Lock`/`Unlock`/`RefreshLock`, the R2 object key and the firm database + R2 bucket binding are **re-derived solely from the verified access token** (`firmId`+`fileId`+`versionId`); any path/`fileId` in the `WOPISrc`/request line is ignored or asserted-equal. A valid firm-A token replayed against a firm-B `WOPISrc`, or a tampered `fileId`, resolves to **404** (ADR-0052 absence-not-existence) and touches no firm-B object. (Fitness function, §12.)
- **Capability is enforced server-side, not via CheckFileInfo flags.** `CheckFileInfo`'s `UserCanWrite`/`ReadOnly` are **advisory UI hints**, not an authorization boundary. `PutFile`, `Lock`, `RefreshLock`, `Unlock`, `UnlockAndRelock` **hard-reject any token whose `capability != edit`**, server-side, independent of CheckFileInfo. A view-capability (or replayed-view) token mutates nothing and cannot disrupt the lock. (Fitness function, §12.)
- **`CheckFileInfo`** — returns metadata + the per-user hints; `UserCanWrite` mirrors the launching member's matter-scoped edit permission; a viewer launches `UserCanWrite=false`.
- **`GetFile`** — the host streams the token-derived object from R2 to coolwsd (the live `current` for an active session; the last committed version for a read-only view). coolwsd never touches R2 directly; bytes flow host↔R2 and host↔container, never to the browser.
- **`PutFile`** — coolwsd PUTs the document bytes to the host; the host computes SHA-256 via a **streaming digest** (the body is piped through a hashing transform into the R2 put — single streaming pass, no buffered copy; ADR-0078), writes to the `current` object (§5), records hash/size/timestamp on the DO. Timestamp-guarded (§5). Saves are periodic (not per-keystroke) and `.docx` is small, so host-received bytes here are acceptable — distinct from the bulk-content presign rule (ADR-0081), which governs _client_ upload/download (see checkout/check-in, §7).
- **`Lock` / `Unlock` / `RefreshLock` / `UnlockAndRelock`** — the live co-edit session takes **one** WOPI lock (first editor locks; co-editors join the same lock/coolwsd; last leaver unlocks). The host honors the standard **409 + `X-WOPI-Lock` current-value** mismatch contract, and the separate **409 on an unlocked non-zero-byte `PutFile`** — kept distinct from the timestamp-conflict 409 (§5). The DO refreshes the lock while the session is live (honoring the client's `X-WOPI-LockExpirationTimeout`, default 30 min), so it never expires under active editing; the 30-min expiry is only the dead-session backstop (§7/§9).
- **`PutRelativeFile` / Save-As** — deferred (§11) unless trivially free.

### 3a. Editor iframe — origin, CSP & sandbox posture (security.md; ADR-0029)

- **Dedicated cookieless origin.** Collabora's editor iframe is served from coolwsd's host origin fronted by the Worker — a **dedicated cookieless origin** distinct from `app.magnacarta.esq` (reusing or a sibling of the 2·3 `files.*` origin), so the editor cannot read app session cookies.
- **The preview-grade `<iframe sandbox>` + `Content-Disposition: attachment` posture (ADR-0029) does NOT apply here.** That defends against raw untrusted bytes rendered in the browser. The live editor is a **trusted derived renderer** (coolwsd), and `GetFile→coolwsd` is pure **server-side R2→container** streaming — the raw `.docx` bytes never reach the browser; the browser only receives Collabora's rendered editor UI. (The untrusted-bytes defense lives at ingest, §7, and at coolwsd least-privilege, §2.)
- **Framing + postMessage.** The host page sets `frame-ancestors`/CSP to the app origin; the SvelteKit shell ↔ Collabora `postMessage` channel uses an **explicit origin allow-list on both ends — never `'*'`**.

## 4. Editor auth & access tokens (`ADR-collabora-editing-host-topology`)

Collabora authenticates **every** WOPI callback with an opaque `access_token` query parameter (no cookie), so the WOPI callbacks are a **distinct surface** with a route-specific guard — not the cookie-session chokepoint (which derives `firmId` from the cookie WOPI callbacks lack). The token is the gate; firm-scope and capability are re-checked at use (§3).

- **Token = short-lived HMAC-signed capability.** The editor-launch route (a normal session-authenticated, chokepoint-guarded route) mints a token over `{firmId, matterId, fileId, versionId, memberId, capability, sessionId, exp, jti}`. The WOPI guard verifies the MAC **constant-time** (`timingSafeEqual`, reuse `apps/worker/src/constant-time.ts`) and **verify-before-trust** (no field is read before the signature checks), statelessly on the hot path.
- **Per-firm signing key + versioning (bounds blast radius).** The signing key is **derived per firm** (`HKDF(rootSigningKey, firmId)`) so a leaked derived key is firm-scoped, and the token envelope carries a **`kid`/key-version** (ADR-0046 algorithm-versioning) for graceful rotation. Compromise blast radius = one firm + the token window. `access_token` **must never be logged** (§4a).
- **`access_token_ttl` vs the internal expiry.** `access_token_ttl` (handed to Collabora) is an **absolute epoch-ms expiry**, not a duration; set it to a sane window (hours) so the client's save-and-refresh machinery and the `Reset_Access_Token`/`App_TokenExpiring` handshake work. The internal HMAC `exp` is a short, independent claim with an allowed clock-skew tolerance; the token is **bound to the DO `sessionId`** and rejected once that session is reaped/rotated (kills replay of a leaked-but-unexpired token).
- **Near-instant revocation, scoped to permission change.** The guard consults the per-document DO — already in every callback's path (a sub-ms local SQLite read, so revocation is instant **and** ~$0) — whose live authorization read reflects `member.status` (deactivation / lost matter access). On a genuine **permission-change** event (WOPI-sanctioned: scenarios where the host signals lost permission via callback failure), the open session is dropped within seconds via `Reset_Access_Token`/callback failure. This is **not** an arbitrary per-callback drop: routine expiry relies on `access_token_ttl`, and an **in-flight `PutFile` is allowed to complete (or the user is prompted to save)** rather than hard-failed — protecting against mid-edit data loss while keeping the owner's near-instant-revocation intent for the real permission-change case.

### 4a. Errors & diagnostics on the WOPI surface (golden rule 4; error-logging.md)

WOPI callbacks are off the cookie chokepoint, so they do **not** inherit its telemetry/`onError` boundary — this surface wires the standard pipeline itself. The WOPI guard + handlers mint/propagate a `cor_` correlation ID through the `@magna-carta/telemetry` `Logger` seam; a fault returns the WOPI-contract status to coolwsd **and** emits a **structured, redacted** event carrying an `err_` Error ID. **Document bytes are never logged** (the allowlist-event-builder gives an undeclared field no slot — the structural backstop), and the `access_token` query param is scrubbed from every log/URL. The launch route surfaces an Error ID on container-spawn / keep-alive failure; coolwsd's own COOL error overlay maps to a user-facing Error ID.

## 5. Version model — the `current` working object + immutable versions (amends ADR-0035)

Slice 1·1 shipped versions as **immutable, opaque-keyed, monotonic** rows with `current` as a _D1 pointer_ (`file.current_version_id`) and **no mutable `current` R2 object**. This slice **adds a distinct mutable `current` working object** under an opaque key (`files/{fileId}/current`), leaving the immutable version chain untouched.

- **`current` is the live working copy** Collabora overwrites on every (auto)save via `PutFile`. It is **not** the history.
- **Stale-write guard — the accurate mechanism.** The guard honored when the client is **Collabora** is its extension header **`X-COOL-WOPI-Timestamp`** — a Collabora-specific _request_ header on `PutFile` (sourced from `CheckFileInfo`'s `LastModifiedTime`) that the host compares to the stored object's timestamp and **409s with `{"COOLStatusCode":1010}`** on mismatch (ADR-0035). **There is no _standard_ WOPI host-enforced stale-`PutFile` reject** — the standard equivalents are the WOPI **Lock** + `Version`/`LastModifiedTime`, with the client managing conflict avoidance (e.g. M365 merges client-side). So the timestamp guard is a Collabora extension we honor for the Collabora client; the **universal backstop** (client-agnostic) is the host's own compare of the presented timestamp against the **server-authoritative** `current_wopi_timestamp` recorded on the DO — the value is **host-assigned, never client-asserted**. (This is what keeps the "both Word futures" claim honest: the host-side compare protects lost-update regardless of client.)
- **Cutting a version** = a server-side R2 `CopyObject` from `current` into a _new_ immutable `files/{fileId}/{versionId}` + a `commitVersion`-style row (monotonic `version_number`, meter increment, audit, outbox `file.version_committed`). Because `PutFile` already computed `current`'s SHA-256, the cut needs **no re-read**: it compares `current`'s hash to the latest version's hash for the **no-op skip** (ADR-0078); `CopyObject` moves bytes server-side (no Worker egress). A **sibling commit path** is added because 1·1's `commitVersion` assumes an `upload_session`; the editing cut mints from `current` with server-computed facts and no upload session.
- **Granularity (Design 1).** A version is cut on **explicit Save** and on **session-close** (last editor leaves). **Autosaves and a co-author _join_ never cut.** Periodic auto-checkpoints are **deferred** (§11) — the in-cycle cost model showed the storage difference is immaterial ($0.15–$8/firm/yr), so this is a clean-history UX call, not cost.

## 6. Storage & tiering (ADR-0035 / ADR-0077 / ADR-0078)

- **Format: real, byte-exact `.docx`, `storage_encoding='full'`.** The ADR-0077 **delta-storage** optimization stays **deferred** (Phase 2, gated on measured ~100 GB/firm churn); 2·2 writes only `full` and never assumes a version object is raw bytes outside the data-access layer.
- **Standard→IA tiering — mechanism built, trigger conservative.** This slice wires the first production caller of `meterTierChangeStatements`: a superseded version transitions Standard→IA in place via server-side `CopyObject` (`x-amz-storage-class`), updating the per-firm `storage_meter` counters **in the same batch** (ADR-0078), **never deleting**. The **auto-tier trigger is conservative / off by default**: only **superseded, non-current** versions, past the IA 30-day-minimum window — the live `current` and latest version never tier. Aggressive policy is deferred to a measured gate (golden rule 10); IA's retrieval fee + 30-day minimum punish premature tiering.
- **Metering.** Every version-cut and tier-change updates the exact per-firm D1 `storage_meter` rollup, trued by the existing scheduled R2-LIST reconciliation — also what feeds the Phase-2 ~100 GB delta gate.

## 7. Concurrency & reconciliation model (`ADR-document-editing-concurrency-reconciliation`)

Three access intents (identity = firm `member`; matter scoping governs view vs edit). The per-document DO is the single authority. **Invariants:** (1) **reading is never blocked**; (2) **no work is ever silently lost or merged** — every merge is human-reviewed; (3) **one isolated container per document**.

- **Online — real-time co-editing (default).** Connected editors share one Collabora session (one WOPI session lock); Collabora merges. A second editor opening a live document **joins** — never blocked. (Lock model confirmed against WOPI: lock taken under the first user's token; lock ops issued under a still-editing user's token as others leave.)
- **Read — always.** A viewer joins a live session **read-only** (`UserCanWrite=false`, with write hard-rejected server-side per §3) and sees edits live; otherwise gets the last committed version. (Rich inline preview is slice 2·3.)
- **Offline — optimistic, never blocked.** A member may take an offline **working copy** even while others co-edit online.
  - **Checkout download** = a **short-TTL presigned GET** for the single committed-version object, key derived server-side from the session's `firmId`+`fileId` (never caller-supplied), no host byte-streaming (ADR-0081/0082 presign rule). The presigned URL cannot be edited to address another firm/file (fitness, §12).
  - **Check-in upload routes through the ADR-0081 quarantine ingest path.** The returning bytes are **untrusted** (a `.docx` is a zip, edited on an uncontrolled device): presigned PUT → lands `status='pending'` at its final key → the `files-ingest` consumer runs the full gate pipeline (magic-byte, real-size, decompression-bomb, malware scan) → only **after clearing** does it become a committed version. **A checked-in object is never opened by a container before it clears** (closes the server-side-RCE/macro/zip-bomb vector).
  - **Divergence + reconciliation.** On a cleared check-in, divergence is detected by the recorded **base version id** (+ content hash): no advance → fast-forward to a normal new version; advanced → the returning copy is kept as a **conflicting copy** (parallel version, nothing lost), the document is **flagged `needs reconciliation`**, and a human **Compare/redline** delineates what stays. **No automatic merge** — `.docx` is not line-mergeable. **Resolution:** a `documents:reconcile` mutation (§10) records the human decision (which copy/copies become authoritative), cuts the resolved version (or marks the conflicting copy superseded), flips `reconciliation_status` `conflict_pending → reconciled`, clears the flag and the reconciling checkout, audits `document.reconciled`, emits an outbox event. **A conflicting copy is retained forever** (legal-hold-safe) regardless of outcome. 2·2 ships **conflict-copy + flag + the resolution mutation**; the polished in-app Compare UI is a fast-follow (Word Compare is an interim review convenience, **not** a prerequisite for never-lose-work safety, which holds with both copies preserved).
  - **Offline copy is not recallable.** The §4 near-instant revocation does **not** reach bytes already on a member's device. On deactivation / lost matter access mid-checkout: the member's **check-in is refused** (changes cannot return) and the outstanding checkout is **force-released + audited**; already-downloaded bytes are acknowledged as unrecallable (inherent to offline).
- **Exclusive lock — opt-in.** A member may deliberately take an **exclusive lock** to avoid a reconcile up front (a large solo revision, or the desktop-Word path). While locked, others **read** but do not edit. A tool, not the default.

**Stale-lock clearing** — two timers, opposite goals:

- **Dead co-edit session → reaped fast.** The DO heartbeat (alarm-driven, §9) detects no live connections and reaps the session (cutting the session-close version, returning to idle) on the order of ~60–90 s, tuned by the spike. The 30-min WOPI expiry is only the outer backstop. Because editing isn't exclusive, others rarely wait (they join).
- **Stale exclusive lock → generous auto-release + manual force-release.** Shows "checked out by [name] since [time]," marked **stale** after inactivity, **auto-releases after a generous, firm-configurable idle period** (so a genuine multi-hour/day offline edit isn't cut short), and is **force-releasable at any time** by an authorized member. **`documents:forceReleaseLock` resolves matter-scoped** (via `RESOURCE_BY_PERMISSION_NAMESPACE → matter`), so an ethical-wall-excluded member is **denied even if firm-admin** (404; fitness, §12). Default authority: matter-team-with-edit + firm admins/owners. Force-release is always **safe** (immutable versions + reconcile catch any returning work).

## 8. Schema additions (per-firm D1; design altitude — exact DDL in the plan)

Through the `@magna-carta/database` Drizzle-as-source path, with CHECK constraints on the enums. **The migration is numbered at integration time** (next free after the per-firm head at merge — the branch head is already churning, mirroring 1·1's renumber), **never pinned now**. All additions are **expand-contract-safe** (ADR-0065) with safe defaults.

- **`file`** gains working-copy fields: `current_r2_key`, `current_sha256`, `current_size_bytes`, `current_wopi_timestamp` (server-authoritative guard value — all nullable until first edit), and `edit_state` (`idle | coediting | checked_out`, DEFAULT `idle`).
- **`document_checkout`** (new) — the durable exclusive-lock / offline working-copy record: `file_id`, `holder_member_id`, `lock_type` (`exclusive | offline_working_copy`), `base_version_id`, `acquired_at`, `last_activity_at`, `status` (`active | stale | released | reconciling`), `idle_release_at`. **The live co-edit session lock is NOT here** — it is ephemeral in the DO's SQLite (must not outlive a reap).
- **`file_version`** gains `reconciliation_status` (`clean | conflict_pending | reconciled`, DEFAULT `clean`) and `diverged_from_version_id` (the base a conflicting copy diverged from).
- **`current`-object lifecycle (ADR-0049 / ADR-0035).** Soft-deleting a file with a live session first **reaps the session** (cut session-close version) then soft-deletes; `current` is included in the file's deletion (destroyed-with-file, its `storage_meter` row decremented — `current` never tiers, so ADR-0049's IA path does not cover it and it must be explicitly handled). On undelete, `current` is restored or lazily re-materialized from `current_version_id`. Version-restore copies an archived `vN` forward into a new `current` and cuts a new version (forward-only, never rewrites history).
- **Permissions:** a new **`documents:`** namespace in `@magna-carta/access-control` — `documents:edit`, `documents:checkout`, `documents:forceReleaseLock`, `documents:reconcile` — wired through `RESOURCE_BY_PERMISSION_NAMESPACE` (matter-scoped), seeded to roles.

## 9. Reliability & the de-risking spike

- **Cloudflare Containers WebSocket keep-alive (bugs #147/#162).** #147's root cause is that the DO's JS does **not** run per WebSocket frame, so the DO cannot self-detect liveness from the editing socket. The keep-alive is therefore **alarm-driven (or host-callback-/autosave-cadence-driven), never WebSocket-frame-driven** — an alarm calls `renewActivityTimeout()` / pings the container; `sleepAfter` is pre-extended before long operations (#162). Both issues are open, so the mitigation is load-bearing.
- **Durable reconnect.** Lock + version-cut state live in the DO's SQLite, working bytes in R2's `current`; a container death loses **zero** work — the session re-establishes against durable state (exercised in tests).
- **The spike (precedes the build; feeds the plan).** Measure on a real Cloudflare container: (1) steady-state coolwsd RSS (idle, +1 doc, +Nth doc, a heavy doc); (2) cold-start request → `/hosting/discovery` ready → first `.docx` open, incl. image pull; (3) that the alarm-driven keep-alive keeps a busy session alive past `sleepAfter`. These set warm-instance sizing (§2) and the reap timing (§7) and replace the in-cycle _reported_ figures.

## 10. Worker / DO surface, idempotency, audit & contract

- **Session-authenticated routes** (chokepoint, `defineOpenAPIRoute`, Zod, emitted into the committed `openapi.json` snapshot per ADR-0066): `POST …/documents/{fileId}/edit-session` (launch); `POST …/documents/{fileId}/checkout` + `…/checkin`; `POST …/documents/{fileId}/force-release`; `POST …/documents/{fileId}/reconcile`; the version-list + reconciliation-status reads. Snapshot + generated-client regeneration run for these.
- **WOPI callback surface** (token-guarded, §4, _not_ the cookie chokepoint): discovery, `CheckFileInfo`, `GetFile`, `PutFile`, `Lock`/`Unlock`/`RefreshLock`/`UnlockAndRelock`. These are declared in the contract as `authenticated:false` / token-guarded with a justified entry in the §3.5 conformance **`PUBLIC_ALLOW_LIST`** (analogous to the platform-admin-key exception), so the committed-snapshot obligation is met rather than silently bypassed.
- **Idempotency (ADR-0063 / `RouteMeta.idempotency`):** `checkout` / `checkin` / `force-release` / `reconcile` — **required** (client `Idempotency-Key`). The internally-triggered **version-cut** (from `PutFile`/session-close, with no client request) is idempotent by `(fileId, current_sha256)` — the same no-op-skip / ingest-dedup seam — a server-derived key, not the header.
- **Outbox topics (the contract):** `file.version_committed` (reused), `document.checked_out`, `document.checked_in`, `document.lock_released`, `file.tier_changed`, `document.reconciled`.
- **Audited mutations (mirroring 1·1; actor explicit):** `document.edit_session_launched`, `document.checked_out`, `document.checked_in`, `document.lock_force_released` (records **both** the authorized actor and the displaced holder), `file.version_committed`, `file.tier_changed`, `document.reconciled`. For **system-triggered cuts** (`PutFile`/session-close), the actor is the session-owning member resolved from the DO/token — **never null**.
- **The `DocumentSession` Durable Object** + the Collabora **Container** binding (new `wrangler` config, purpose-named per ADR-0075); the alarm-driven keep-alive + heartbeat; the conservative tiering sweep (cron) reusing the existing reconciliation cadence.

The editor UI shell rides the design-system slices (0·7a/0·7b).

## 12. Fitness functions & tests

- **Tenancy at use:** a valid firm-A edit token against a firm-B `WOPISrc` (or tampered `fileId`) yields 404 and touches no firm-B object; a checkout presigned URL cannot be edited to address another firm/file.
- **Capability:** a view-capability token cannot `PutFile`/`Lock` (write/mutate rejected server-side regardless of CheckFileInfo).
- **Isolation:** no code path shares one coolwsd across documents (source-scan, mirroring the pooling red-flag); a container has no R2/D1 creds and no egress beyond the host.
- **Untrusted check-in:** check-in bytes route the `files-ingest` consumer and cannot be opened by a container before clearing.
- **Ethical wall:** a walled-off-but-firm-admin member is 404 on force-release of a walled matter's document.
- **Read always:** reachable in every state (idle / coediting / checked_out) — e2e.
- **Versioning:** no-op skip on unchanged Save; explicit Save + session-close cut, autosave + join do not; timestamp 409 on stale `PutFile` against the DO-recorded value; divergent check-in produces a flagged conflicting copy and never overwrites; reconcile resolves the flag.
- **Tiering:** updates the meter in the same batch, never deletes, never tiers the live/latest version.
- **Contract:** the new session routes are in the committed snapshot; the WOPI routes are in the `PUBLIC_ALLOW_LIST`; the `documents:` namespace is in `RESOURCE_BY_PERMISSION_NAMESPACE`.
- **Load profile (accretion rule, ADR-0078/0083):** add measured ops — per-file version-row accretion at editing volume; the version-cut write batch (`CopyObject` + meter + audit + outbox); the conservative tiering sweep over superseded versions; the `storage_meter` rollup under growth; the DO SQLite read on the WOPI hot path — committed as new baselines via the fixtures measure harness.
