### Phase 1 — Core domain (firm + matters)

**Order decided 2026-06-10.** The white paper lists Directory → Locations → Matters; execution reorders it: the matter shell + File Manager have no hard Directory dependency (the party model is a designed seam until Directory lands) and going matters-first serves the owner's documents-finished-first spine (Phase 2 builds on the File Manager). Locations is too small to be a slice and is folded into 1·1 (matter numbering + letterhead reference it from day one). The Directory design surfaced a hidden prerequisite: its sensitive identifiers (SSN/DOB/financial) require the **`protected()` crypto module** (envelope encryption, HMAC blind index for conflicts matching) — so that becomes its own slice first. Design cycles run in this order, one ahead of the builds, as in Phase 0.

- **Slice 1·1 — Matters core + Locations + File Manager.** The matter shell (configurable numbering with optional location segment, matter types, Prospective → Open → Closed lifecycle), the Locations entity (addresses, jurisdiction, letterhead/remit-to, number prefix, staff assignment), and the File Manager (versioned per-firm R2 files, folders, the streaming store-mode ZIP64 bulk download with version pinning). **Client/party links are a designed seam** (role-on-the-link shape sketched in the spec, wired live in 1·3). The inbound upload-path decision (small-files-through-Worker now vs. the direct-to-R2 presigned/multipart ADR) is made in this slice's design, and the version-object metadata reserves the **delta-storage seam** (ADR-0077): a `storage_encoding` discriminator (`full` today) plus the rule that nothing outside the data-access layer assumes a version object is raw file bytes. Storage foundations build in-area (ADR-0078): **every object records a SHA-256 content hash from day one** (fixity, dup detection, upload short-circuit, scan-verdict caching, no-op version skip — retrofit means re-reading every stored byte) and the **per-firm storage-metering rollup** (bytes + object counts by class/prefix → Analytics Engine) that fires the platform's storage adopt-when triggers. Open research for this slice's design: a **derived-vs-original artifact class** (recomputable renditions — OCR text, conversions, previews — are caches and arguably should not inherit keep-forever tiering; ADR-0078 item 4). (White paper, _Matters and File Manager_ and _Locations_.)
- **Slice 1·2 — the `protected()` crypto module.** Envelope encryption per the white paper (_Encryption and key management_): root KEK as a Worker secret wrapping per-firm keys, HKDF purpose keys, the declarative `protected()` field type in the data-access layer (encrypt on write, role-gated + audited decrypt on read), and the HMAC **blind index** so conflicts can match encrypted identifiers without decrypting. Also retires the seams parked on it: TOTP-seed encryption (0·4), incident descriptions (0·6). Prerequisite for Directory.
- **Slice 1·3 — Directory.** The entity graph (Person/Organization, equal data depth, categories + custom fields), legal names done right (structured names, aliases/AKAs/former names, name-change history), typed edges (affiliations, relationships, representation, role assignments), typed identifiers on `protected()` fields, duplicate detection + merge/unmerge, temporal validity, soft-delete/archival — and **wiring the 1·1 matter↔party seam live** (client links, role-links). (White paper, _Directory_.)

### Hardening (seamed now, executed when upstream is ready)

- **Untrusted file handling (sandboxing + malware scanning)** — uploaded bytes (File Manager, _Client portal_, _Discovery_ ingest) are untrusted; a malicious file is inert at rest, so risk arises only on **process / serve / forward**. **Primary defenses are structural and built anyway** with conversion + preview, tracked in their feature homes — not deferred: **(1) sandbox-hardened processing** (no-egress `enableInternet=false`/allowlist, least-privilege-per-job, ephemeral Containers, resource caps — _Performance & concurrency model_) defeats server-side RCE in our native parsers (the only threat aimed at _us_); **(2) safe delivery** (separate cookieless sandbox origin + CSP + `<iframe sandbox>` + safe-rendition preview, never raw active formats — _Inline file preview_) defeats stored XSS. Per-firm isolation caps cross-tenant blast radius. **Malware scanning is the thinner, deferred layer** (mainly downstream-recipient protection + compliance/cyber-insurance), built as a **swappable port now, engine later** — _borrow outside expertise, never outside custody_ (commercial engine on our own compute yes; data-holding SaaS no, per ADR-0030/ADR-0038). Scan pipeline: pre-acceptance gates (size/type allow-list, magic-byte check, decompression-bomb guards) → quarantine-on-arrival (R2 event → Queue; not servable until cleared) → scan (verdict as metadata) → optional CDR rendition (original preserved for evidence) → re-scan sweep on signature updates → **quarantine, never auto-delete** (infected files are evidence; destruction blocked by holds). Engine options behind the port, by data custody: WAF content scanning (edge Layer-0 — detect-only, 50 MB cap, Enterprise, misses direct-to-R2/at-rest); commercial engine in a Cloudflare Container (Sophos/Bitdefender/MetaDefender — single engine fits ~12 GiB/instance); managed in our own cloud account (AWS GuardDuty / bucketAV-Sophos — solves the large-file cap but needs an off-Cloudflare ingest bucket); ClamAV + premium unofficial sigs + YARA (cheap baseline; needs a `cvdupdate` private mirror; falls back behind the ~2 GB cap). Files past the scannable cap get an explicit _unscanned_ policy; desktop (Tauri) local pre-scan is the parity accelerator. Its own ADR. (_Matters and File Manager_; tied to the inbound-upload backlog item above.)
- **Version-history delta storage** — store superseded document versions as binary deltas instead of full snapshots: re-pack the OOXML ZIP with _stored_ entries (deflate scrambles bytes on a one-word edit, defeating naive deltas), delta with **zstd `--patch-from`** against a keyframed base, verify a roundtrip content hash, swap the IA object — all as an async Queue/Container job at the existing supersede-to-IA hook, latest version always full (_Document versioning & storage tiering_; ADR-0077, designed-but-deferred). The seam is reserved in the slice 1·1 File Manager spec (`storage_encoding` on version metadata; version bytes hidden behind the data-access layer); the pipeline builds in Phase 2 once Collabora editing generates real version churn and the load-profile harness puts numbers on it (golden rule 10 — at IA's $0.01/GB-mo, full snapshots must reach ~100 GB/firm before costing $1/mo).
- **Telemetry analytics tier (Iceberg-on-R2)** — register the redacted Logpush-in-R2 logs as **R2 Data Catalog** Iceberg tables for zero-egress DuckDB/Spark/BI querying, with compaction + snapshot-expiration maintenance (_Observability and diagnostics_ → _Telemetry analytics tier_, ADR-0056 _Proposed_). Analytics Engine remains the MVP path; the seam sits on data already written. Adopt when a trigger binds — retention past ~92 days, exact/unsampled counts, rich joins / external engines, or cost-at-scale — and re-verify the open-beta limits (Parquet-only, ~2 GB/table/hr, orphan-file cleanup) at that point.
- **Post-quantum signature migration** — passkeys/WebAuthn + the PAdES e-signature seal → ML-DSA/SLH-DSA, and a PQC-capable external-KMS-rooted KEK (_Encryption and key management_, ADR-0046). Seamed today via algorithm-versioning; gated on upstream standards (FIPS 204/205/206, COSE, ETSI PAdES, CA support). Verify Cloudflare hybrid PQC TLS is on for every hop and log any plugin endpoint that won't negotiate it.
