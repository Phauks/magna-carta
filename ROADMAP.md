## UI roadmap — the deferred-surface build order

Every backend/headless capability that shipped ahead of its UI, in the order the UI stream builds them (agreed with the owner 2026-07-02). The design system (0·7a) is on `main`; this is the queue it unblocks. **In-commit discipline:** a slice that ships a backend capability without its UI adds its surface to a stage here; the line leaves when the UI lands — the same definition-of-done as ROADMAP/STATUS/CHANGELOG. Re-sequencing is a deliberate edit by the UI stream, not drift. (Per-slice stage detail lives in [`STATUS.md`](STATUS.md); design decisions in the register live with the design-system docs.)

**Ordering principle:** the frame first (everything renders inside it), then the session (every API call needs one), then the two archetype screens everything else copies (List, Detail), then maximum "humans can exercise built backends" per unit of work — the project's testing bottleneck. Craft threads (dark design pass, empty/loading/error states, NVDA passes, VRT baselines) run through every stage rather than being one.

**Stage 1 — the frame (slice 0·7b core; strictly ordered)**

- **Real App Shell in `apps/web`** — routes, the assembled chrome (Sidebar/TopBar/BrandMark parts from the design system; nav registry + permission filtering in the app), route-level View Transitions. No backend dependency.
- **Auth (slice 0·4 backend)** — login / 2FA / passkey-enrollment UI. Sequenced for plumbing, not ceremony: it gates real data on every later screen. Ships functional with a modest ceremonial edge; the written-live wordmark (anime.js's first consumer + its ADR) enriches it later without rework.

### Hardening (seamed now, executed when upstream is ready)

- **Untrusted file handling (sandboxing + malware scanning)** — uploaded bytes (File Manager, _Client portal_, _Discovery_ ingest) are untrusted; a malicious file is inert at rest, so risk arises only on **process / serve / forward**. **Primary defenses are structural and built anyway** with conversion + preview, tracked in their feature homes — not deferred: **(1) sandbox-hardened processing** (no-egress `enableInternet=false`/allowlist, least-privilege-per-job, ephemeral Containers, resource caps — _Performance & concurrency model_) defeats server-side RCE in our native parsers (the only threat aimed at _us_); **(2) safe delivery** (separate cookieless sandbox origin + CSP + `<iframe sandbox>` + safe-rendition preview, never raw active formats — _Inline file preview_) defeats stored XSS. Per-firm isolation caps cross-tenant blast radius. **Malware scanning is the thinner, deferred layer** (mainly downstream-recipient protection + compliance/cyber-insurance), built as a **swappable port now, engine later** — _borrow outside expertise, never outside custody_ (commercial engine on our own compute yes; data-holding SaaS no, per ADR-0030/ADR-0038). Scan pipeline: pre-acceptance gates (size/type allow-list, magic-byte check, decompression-bomb guards) → quarantine-on-arrival (R2 event → Queue; not servable until cleared) → scan (verdict as metadata) → optional CDR rendition (original preserved for evidence) → re-scan sweep on signature updates → **quarantine, never auto-delete** (infected files are evidence; destruction blocked by holds). Engine options behind the port, by data custody: WAF content scanning (edge Layer-0 — detect-only, 50 MB cap, Enterprise, misses direct-to-R2/at-rest); commercial engine in a Cloudflare Container (Sophos/Bitdefender/MetaDefender — single engine fits ~12 GiB/instance); managed in our own cloud account (AWS GuardDuty / bucketAV-Sophos — solves the large-file cap but needs an off-Cloudflare ingest bucket); ClamAV + premium unofficial sigs + YARA (cheap baseline; needs a `cvdupdate` private mirror; falls back behind the ~2 GB cap). Files past the scannable cap get an explicit _unscanned_ policy; desktop (Tauri) local pre-scan is the parity accelerator. Its own ADR — **engine research complete (owner, 2026-06-12; timeline home = slice 2·1)**: [`docs/research/upload-malware-scanning.md`](docs/research/upload-malware-scanning.md) adopts a self-hosted detection-only MVP — **ClamAV (socket-driven from Rust; freshclam/Talos signatures) + yara-x (pure-Rust; YARA-Forge-Core rules) + our own Rust structural heuristics (lopdf for PDF; cfb/zip/quick-xml for Office)** in a Container behind the port, freely-updated public rule feeds (no rule-writing by us), no data-holding SaaS, no CDR at launch (all CDR options eliminated — pdfium/Dangerzone destructive, DocBleach retired, purgo experimental), ~$35–50/mo all-in; ClamAV stays the one C component but isolated in its own process (socket, not FFI). Pipeline shape and the swappable port (launch verdict: explicit `unscanned`) build in slice 1·1 (ADR-0081); the engine itself builds in slice 2·1, where the engine ADR is written. (_Matters and File Manager_.)
- **Async bulk-download jobs** — the ADR-0027/ADR-0082 seam past the live-stream path: very large zip bundles switch to a build-to-R2-artifact job → signed URL, so a dropped connection doesn't waste the whole transfer and the download is retryable. **Research complete (owner, 2026-06-12)** — [`docs/research/async-bulk-download-jobs.md`](docs/research/async-bulk-download-jobs.md): all four knobs resolved — **threshold** (two config knobs `liveMaxFileCount`/`liveMaxTotalBytes`, now driven by retryability not the relaxed 10k-subrequest cap), **job lifecycle** (Durable-Object-coordinated, queue-consumer-Worker build streaming R2→R2 multipart, Container only as the outlier escalation — no standing infra), **artifact TTL/cleanup** (native R2 lifecycle rule on the `bundles/` prefix, ~7-day delete; DO-alarm belt), and **identical-bundle dedup** (per-firm manifest-hash content key `bundles/<hash>.zip`, the DO is the single-flight coordinator). Near-zero marginal cost (free R2 egress). The threshold ships as a config knob in slice 1·1; the **async build is claimed by slice 2·1 (owner, 2026-06-12)**, which already owns the Queue/Container/DO file-pipeline machinery. (_Matters and File Manager_; ADR-0082.)
- **Version-history delta storage** — store superseded document versions as binary deltas instead of full snapshots: re-pack the OOXML ZIP with _stored_ entries (deflate scrambles bytes on a one-word edit, defeating naive deltas), delta with **zstd `--patch-from`** against a keyframed base, verify a roundtrip content hash, swap the IA object — all as an async Queue/Container job at the existing supersede-to-IA hook, latest version always full (_Document versioning & storage tiering_; ADR-0077, designed-but-deferred). The seam is reserved in the slice 1·1 File Manager spec (`storage_encoding` on version metadata; version bytes hidden behind the data-access layer); the pipeline builds in Phase 2 once Collabora editing generates real version churn and the load-profile harness puts numbers on it (golden rule 10 — at IA's $0.01/GB-mo, full snapshots must reach ~100 GB/firm before costing $1/mo).
- **Telemetry analytics tier (Iceberg-on-R2)** — register the redacted Logpush-in-R2 logs as **R2 Data Catalog** Iceberg tables for zero-egress DuckDB/Spark/BI querying, with compaction + snapshot-expiration maintenance (_Observability and diagnostics_ → _Telemetry analytics tier_, ADR-0056 _Proposed_). Analytics Engine remains the MVP path; the seam sits on data already written. Adopt when a trigger binds — retention past ~92 days, exact/unsampled counts, rich joins / external engines, or cost-at-scale — and re-verify the open-beta limits (Parquet-only, ~2 GB/table/hr, orphan-file cleanup) at that point.
- **Post-quantum signature migration** — passkeys/WebAuthn + the PAdES e-signature seal → ML-DSA/SLH-DSA, and a PQC-capable external-KMS-rooted KEK (_Encryption and key management_, ADR-0046). Seamed today via algorithm-versioning; gated on upstream standards (FIPS 204/205/206, COSE, ETSI PAdES, CA support). Verify Cloudflare hybrid PQC TLS is on for every hop and log any plugin endpoint that won't negotiate it.
- **Root-key rotation + customer-managed keys (BYOK)** — the envelope key hierarchy (`ROOT_KEK` AES-KW-wraps a unique per-firm data key, which in turn encrypts that firm's `protected()` fields; _Encryption and key management_, ADR-0046) is seamed for two evolutions, neither built. **(1) `ROOT_KEK` rotation** — the ciphertext frame reserves `algo_version | key_version` bytes; rotation is a re-wrap sweep over the stored per-firm wrapped keys behind a two-KEK transition window. It is **cheap by design** — `ROOT_KEK` wraps only the firm keys, never the field ciphertexts, so rotating it re-wraps N firm keys with **zero data re-encryption**. Gated to **before the first real client onboards**, or sooner on a compromise/compliance trigger; until then a single `ROOT_KEK` secret (set per [`operations.md` §3](docs/conventions/operations.md), generate-once + backed up) is correct, and there is no production data under it yet. **(2) Customer-managed keys (BYOK)** — wrap a firm's per-firm key under the firm's own KMS/HSM instead of (or above) `ROOT_KEK`, giving the firm a cryptographic kill-switch (revoke → their data goes dark, even to us) **without** breaking server-side search/AI/conflicts/billing (the server still decrypts transiently to process). The **per-firm key is already the seam** — adopting BYOK touches one firm's wrapping, not a global migration — making this a future **enterprise tier**, not MVP. True zero-knowledge / end-to-end encryption is explicitly **out of scope**: it is incompatible with the platform's server-side processing; the only viable carve-out is a narrow, opt-in sealed-vault for fields that genuinely never need processing. Its own ADR when pursued. (_Encryption and key management_; ADR-0046.)
- **Branded per-firm subdomains + safe-delivery host model** — when firms get branded URLs (`<firm>.magnacarta.esq`), the tenancy boundary becomes the subdomain, which reshapes both the inline-preview delivery host and the session-cookie scope. Decided shape: **one neutral, shared, cookieless delivery host** (`files.magnacarta.esq` — users never navigate to it; it serves only signed-token subresources), embeddable by **any** firm app subdomain via `frame-ancestors https://*.<parent>` — not a single fixed `app.` host paired 1:1 with the files host. The wildcard does **not** weaken authorization: the signed, firm-scoped preview token names one object, so the embedding origin was never the gate and a firm only ever holds tokens for its own files. Session cookies stay **host-only** (Better Auth's default — `crossSubDomainCookies` must remain **off**) so a session never leaks to a sibling firm's subdomain or onto the files host (`__Host-` would be stronger, but the pinned better-auth emits `__Secure-` with no option to force it — a library-gap to revisit). Per-firm subdomains are served by a wildcard `*.<parent>` (Cloudflare for SaaS / custom hostnames — the same mechanism as the custom-hostname client-portal landing below). **Seamed now:** the preview header builder emits the wildcard `frame-ancestors` (`apps/worker/src/files/preview-headers.ts`), and a cookie-isolation fitness test pins the host-only invariant (`apps/worker/test/auth-cookie-isolation.test.ts`). **Remaining for when branded URLs are built:** provision the wildcard host, move the app to `<firm>.` subdomains, set `FILES_ORIGIN` to the real files host (it is the `files.example.com` placeholder today, so previews are inert until then), and bind `session.firmId` ↔ the requested subdomain server-side. (_Tenancy & data isolation_ / _Inline file preview_.)
- **Edge hardening (in-Worker)** — six request-handling improvements surfaced while triaging Cloudflare's snippet examples and deciding to skip Snippets as a surface (the skip + triage are recorded in [`docs/conventions/operations.md`](docs/conventions/operations.md) §8.5); all are app/build work, **not** dashboard config, and complement the existing app-level limiter (`apps/worker/src/chokepoint/rate-limiter.ts`) plus the deferred edge rate limiting + custom errors (operations §8.6). **(1) Security-header baseline — the one do-now gap:** no CSP / `X-Frame-Options` / `X-Content-Type-Options` / `Referrer-Policy` / `Permissions-Policy` exists in the Worker or SPA today; add a global header middleware in `apps/worker/src/app.ts` (extend Hono `secureHeaders()`; CSP for the Svelte SPA needs nonces/hashes), with HSTS set at the zone (operations §8.1). **(2) Deliberate CORS policy** (Hono `cors()` allowlist) — gated on the **Tauri desktop** client and the custom-hostname **client portal** landing (the web SPA is same-origin, so not needed yet). **(3) Webhook HMAC verification + outbound request signing** in `@magna-carta/integrations` (the HttpClient seam) — gated on the first signed integration (payments, EasyPost); nothing exists today beyond the analytics-pseudonymization HMAC. **(4) Maintenance-mode toggle** — an env/KV flag the Worker honors to serve a maintenance response; pairs with the deferred custom-errors work (operations §8.6). **(5) Mine `request.cf`** (`country`, `botManagement.score`, `tlsVersion`) for telemetry enrichment, geo/compliance signals, and bot-aware handling on sensitive routes. **(6) Honeypot / tarpit suspicious requests** — defense-in-depth, low priority (tarpitting holds the request open = Worker duration cost).
