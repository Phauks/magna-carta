### Hardening (seamed now, executed when upstream is ready)

- **Untrusted file handling (sandboxing + malware scanning)** — uploaded bytes (File Manager, _Client portal_, _Discovery_ ingest) are untrusted; a malicious file is inert at rest, so risk arises only on **process / serve / forward**. **Primary defenses are structural and built anyway** with conversion + preview, tracked in their feature homes — not deferred: **(1) sandbox-hardened processing** (no-egress `enableInternet=false`/allowlist, least-privilege-per-job, ephemeral Containers, resource caps — _Performance & concurrency model_) defeats server-side RCE in our native parsers (the only threat aimed at _us_); **(2) safe delivery** (separate cookieless sandbox origin + CSP + `<iframe sandbox>` + safe-rendition preview, never raw active formats — _Inline file preview_) defeats stored XSS. Per-firm isolation caps cross-tenant blast radius. **Malware scanning is the thinner, deferred layer** (mainly downstream-recipient protection + compliance/cyber-insurance), built as a **swappable port now, engine later** — _borrow outside expertise, never outside custody_ (commercial engine on our own compute yes; data-holding SaaS no, per ADR-0030/ADR-0038). Scan pipeline: pre-acceptance gates (size/type allow-list, magic-byte check, decompression-bomb guards) → quarantine-on-arrival (R2 event → Queue; not servable until cleared) → scan (verdict as metadata) → optional CDR rendition (original preserved for evidence) → re-scan sweep on signature updates → **quarantine, never auto-delete** (infected files are evidence; destruction blocked by holds). Engine options behind the port, by data custody: WAF content scanning (edge Layer-0 — detect-only, 50 MB cap, Enterprise, misses direct-to-R2/at-rest); commercial engine in a Cloudflare Container (Sophos/Bitdefender/MetaDefender — single engine fits ~12 GiB/instance); managed in our own cloud account (AWS GuardDuty / bucketAV-Sophos — solves the large-file cap but needs an off-Cloudflare ingest bucket); ClamAV + premium unofficial sigs + YARA (cheap baseline; needs a `cvdupdate` private mirror; falls back behind the ~2 GB cap). Files past the scannable cap get an explicit _unscanned_ policy; desktop (Tauri) local pre-scan is the parity accelerator. Its own ADR — **engine research complete (owner, 2026-06-12; timeline home = slice 2·1)**: [`docs/research/upload-malware-scanning.md`](docs/research/upload-malware-scanning.md) adopts a self-hosted detection-only MVP — **ClamAV (socket-driven from Rust; freshclam/Talos signatures) + yara-x (pure-Rust; YARA-Forge-Core rules) + our own Rust structural heuristics (lopdf for PDF; cfb/zip/quick-xml for Office)** in a Container behind the port, freely-updated public rule feeds (no rule-writing by us), no data-holding SaaS, no CDR at launch (all CDR options eliminated — pdfium/Dangerzone destructive, DocBleach retired, purgo experimental), ~$35–50/mo all-in; ClamAV stays the one C component but isolated in its own process (socket, not FFI). Pipeline shape and the swappable port (launch verdict: explicit `unscanned`) build in slice 1·1 (ADR-0081); the engine itself builds in slice 2·1, where the engine ADR is written. (_Matters and File Manager_.)
- **Async bulk-download jobs** — the ADR-0027/ADR-0082 seam past the live-stream path: very large zip bundles switch to a build-to-R2-artifact job → signed URL, so a dropped connection doesn't waste the whole transfer and the download is retryable. **Research complete (owner, 2026-06-12)** — [`docs/research/async-bulk-download-jobs.md`](docs/research/async-bulk-download-jobs.md): all four knobs resolved — **threshold** (two config knobs `liveMaxFileCount`/`liveMaxTotalBytes`, now driven by retryability not the relaxed 10k-subrequest cap), **job lifecycle** (Durable-Object-coordinated, queue-consumer-Worker build streaming R2→R2 multipart, Container only as the outlier escalation — no standing infra), **artifact TTL/cleanup** (native R2 lifecycle rule on the `bundles/` prefix, ~7-day delete; DO-alarm belt), and **identical-bundle dedup** (per-firm manifest-hash content key `bundles/<hash>.zip`, the DO is the single-flight coordinator). - **Root-key rotation + customer-managed keys (BYOK)** — the envelope key hierarchy (`ROOT_KEK` AES-KW-wraps a unique per-firm data key, which in turn encrypts that firm's `protected()` fields; _Encryption and key management_, ADR-0046) is seamed for two evolutions, neither built. **(1) `ROOT_KEK` rotation** — the ciphertext frame reserves `algo_version | key_version` bytes; rotation is a re-wrap sweep over the stored per-firm wrapped keys behind a two-KEK transition window. It is **cheap by design** — `ROOT_KEK` wraps only the firm keys, never the field ciphertexts, so rotating it re-wraps N firm keys with **zero data re-encryption**. Gated to **before the first real client onboards**, or sooner on a compromise/compliance trigger; until then a single `ROOT_KEK` secret (set per [`operations.md` §3](docs/conventions/operations.md), generate-once + backed up) is correct, and there is no production data under it yet. **(2) Customer-managed keys (BYOK)** — wrap a firm's per-firm key under the firm's own KMS/HSM instead of (or above) `ROOT_KEK`, giving the firm a cryptographic kill-switch (revoke → their data goes dark, even to us) **without** breaking server-side search/AI/conflicts/billing (the server still decrypts transiently to process). The **per-firm key is already the seam** — adopting BYOK touches one firm's wrapping, not a global migration — making this a future **enterprise tier**, not MVP. True zero-knowledge / end-to-end encryption is explicitly **out of scope**: it is incompatible with the platform's server-side processing; the only viable carve-out is a narrow, opt-in sealed-vault for fields that genuinely never need processing. Per-firm subdomains are served by a wildcard `*.<parent>` (Cloudflare for SaaS / custom hostnames — the same mechanism as the custom-hostname client-portal landing below). **Seamed now:** the preview header builder emits the wildcard `frame-ancestors` (`apps/worker/src/files/preview-headers.ts`), and a cookie-isolation fitness test pins the host-only invariant (`apps/worker/test/auth-cookie-isolation.test.ts`). **Remaining for when branded URLs are built:** provision the wildcard host, move the app to `<firm>.` subdomains, set `FILES_ORIGIN` to the real files host (it is the `files.example.com` placeholder today, so previews are inert until then), and bind `session.firmId` ↔ the requested subdomain server-side.
