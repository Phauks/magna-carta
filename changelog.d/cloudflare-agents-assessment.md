**Cloudflare Agents platform assessment (research).** [`docs/research/2026-08-04-cloudflare-agents-assessment.md`](docs/research/2026-08-04-cloudflare-agents-assessment.md) — what Cloudflare's Agents platform is (the pre-1.0 `agents` SDK, the experimental-preview Project Think, and the Agents Week 2026 surface), what community signal exists, and an honest per-candidate fit assessment against the Durable Objects / Queues / Workflows / `@magna-carta/inference` foundation already in place. Core finding: an Agent is a Durable Object with a harness on top, so the coordination half buys almost nothing here, while the SDK's default paths — direct provider calls via the AI SDK, and conversation history auto-persisted into the agent's own SQLite — would route privileged content around the accepted inference chokepoint and the firm-scoped data-access layer at once. Recommends adopting nothing, prototyping only a tightly fenced chat-transport shell on synthetic fixtures, deferring Project Think, and refusing the managed Agent Memory / AI Search stores and any agentic authority over conflicts, the ledger, or deadlines. Research only — no decision, no code.
