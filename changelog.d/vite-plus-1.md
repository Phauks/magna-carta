**The toolchain moves to Vite+ 1.5.0, and the Workers test pool to its renamed successor.** `vite-plus` 0.1.24 and the Vite 8.0.16 it brought carried GHSA-587h-7wmj-h5pm (HIGH, CVSS 7.5) and four lower advisories (GHSA-698v-4r3x-3vcv, GHSA-r825-w8mm-5pxw, GHSA-rq7h-c2jc-7f22, GHSA-9jrq-w75r-8gcw), fixed only from vite-plus 1.1. Vite+ 1.x runs upstream Vitest instead of the rebundled `@voidzero-dev/vite-plus-test`, so the catalog's `vitest` is now 5.1.0, the version vite-plus 1.5.0 depends on, and the `vitest` alias leaves the `overrides`. `@cloudflare/vitest-pool-workers` 0.23.0 peered only Vitest 4; its successor `@cloudflare/vitest-plugin` 1.6.0 keeps the same `cloudflareTest()` plugin and `cloudflare:test` module, so every worker's `package.json`, `vitest.config.ts` and `worker-env.d.ts` change only the package name. The design-system story tests import the Playwright provider from `@vitest/browser-playwright`, now a catalog pin kept equal to `vitest`, because upstream Vitest has no `vitest/browser-playwright` entry.

**One Vite in the tree, at last.** The `vite` override alone never reached a `vite` peer: the alias reports its own version (1.5.0), which no `^8` peer range accepts, so pnpm auto-installed upstream Vite for SvelteKit, the Svelte and Tailwind plugins, Storybook and Vitest — the Vite 8.0.16 the advisories named. The root `package.json` now declares `vite` as the same alias, so every peer resolves to it, and `peerDependencyRules.allowedVersions` silences the version warnings that leaves (`vite`, and Storybook's optional `vite-plus` peer, which still names only 0.1/0.2). The lockfile was resolved fresh to drop the stale peer resolutions; outside the toolchain the only version that moved is `@types/react` 19.2.17 to 19.3.0.

**Two overrides leave.** `zod` was there only to reach the 4.4.3 the old pool hard-pinned; the new plugin pins 4.6.6, past the 4.6.6 floor. `tinypool@2` pinned 2.1.2 under the formatter; oxfmt 0.76 and Vitest 5.1 both pin 2.2.0, and the override would now drag them back. Oxfmt 0.76 and oxlint 1.91 come with the move: the formatter now hugs a single arrow-function argument that carries a return-type annotation and indents a list item's continuation line that opens inside an inline code span, which reformats 58 files (8 source, 50 Markdown), and oxlint-tsgolint 7 reports more `no-unnecessary-type-assertion` and `consistent-function-scoping` warnings (none are errors).
