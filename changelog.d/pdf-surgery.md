**PDF text-preserving redaction — surgery mode for `redactDocument` in `@magna-carta/pdf`:** `RedactionOptions` gains an optional `mode` field (`"flatten"` | `"surgery"`, default `"flatten"`). Surgery mode excises only the glyphs whose centres fall within a redaction rectangle from the page content stream, leaving remaining text on that page as selectable PDF operators. The engine now resolves Core-14 standard-font metrics (Helvetica, Times, Courier, Symbol, ZapfDingbats and their variants) from built-in advance-width tables when no embedded `/Widths` array is present, lifting surgery coverage over standard-14-font documents. The engine falls back to rasterize-and-reassemble (`"flatten"`) for any page it cannot confirm clear: per-page fallback triggers for simple fonts that are not standard-14 and omit `/Widths`, non-Identity Type0 encodings, non-zero page rotation, inherited resource dictionaries, inline images, and redaction rectangles that overlap raster image XObjects. The per-page outcome gate (re-observing glyph positions via the hayro textpos device after the edit) ensures a surgered page is never less safe than a flattened page. `RedactionResult` gains `pagesSurgered` and `pagesFlattened` arrays (0-based page indices) alongside the existing `pagesRedacted`. Over-removal of an immediately neighbouring glyph is the only residual non-safety failure mode. Surgery now resolves inherited `/Resources` via the page parent chain: pages that declare `/Resources` on an ancestor `/Pages` node rather than the page dict itself are no longer forced to fall back to flatten. Surgery coverage over the 10-file corpus: surgered 3 / flattened 7 / errored 0 of 10. `crates/pdf-core` passes 80 tests. (`crates/pdf-core`, `packages/pdf`)
