**The document's opening wait is one centered panel over the frame, and the way back to the matter is a button on the editor's own bar.**

The staged wait sat above the frame, the "taking longer" sentence and its Retry arrived above that at fifteen seconds, and when the editor came up the panel went away and the frame moved up into its place: three reflows on a screen a member was staring at. The panel now sits over the frame, centered, with the frame beneath it at its final size from the start; the sentence, the Retry and a failure all appear inside the same panel, which grows downward only. Time is written out ("12 seconds so far"), never abbreviated.

With the editor the whole screen, the way back is a button the editor draws for us: **Matter**, on the editor's shortcuts bar, inserted through its message protocol and labelled with the matter it returns to. The editor's own Close is routed to the same exit. Both ask the editor to save first and leave when it says the save is done, or after three seconds if it does not; the editor saves on its own when the last view drops, so the wait protects the member's time, not their work.

Three corrections from the editor's own integration guide, now that it could be read: a save's answer carries `LastModifiedTime` as the JSON body the editor reads (an empty body was logged as invalid and left its change detection off); `CheckFileInfo` names the member (`UserFriendlyName`), so co-authors see a name rather than an unknown user with an identifier; and the frame allows full screen, which a slideshow needs. In the image, the kit's jail is set up by copying rather than by a bind-mount the container cannot make.
