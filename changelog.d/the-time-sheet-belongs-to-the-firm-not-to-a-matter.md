**The Time Sheet opens from the top bar and belongs to the firm.** The owner's design puts it there —
it lives in the top bar and opens over whatever the person is doing, so capture never forces
navigation — and the port made it a per-matter modal reachable only from a matter's Time tab, removing
the Matter column and recording that removal as a design decision. It was not one.

One component now serves two doors: the Time Keeper chip opens it with no matter assumed, and a
matter's Time tab opens the same sheet pre-filtered to that matter. The chip was the last disabled
control in the shell saying it waited on a surface that had already arrived.

**A row without a matter is legal, because that is how time is actually captured** — somebody records
what they did before deciding where it belongs. Such a row holds typing, runs the timer, carries a
client-minted provisional code, counts in the incomplete tally, and never falls out of view when the
date scope moves. It is simply never sent: the capture route requires a matter, so the row states what
it still needs and writes itself the moment a matter is picked. No failed request, no error a person
has to interpret.

Two adjacent honesty calls came with it. A run started before a matter is chosen cannot become an
entry, so its seconds land on the row and the row writes itself through capture rather than through
the timer. And the permanent matter-scoped entry number the design mints cannot be minted here — no
route serves one — so a written row names that gap and says which provisional code it was held under.

Setting a matter on a row that is already an entry is refused out loud, because nothing moves an entry
between matters yet.
