An error in the matter file manager used to say only that something went wrong, and its two buttons did nothing. It now leads with the fact that the record itself is unaffected — the first thing anyone needs to know — then names the request that failed, the status that came back, the time it happened, and the Error ID worth quoting.

Three first steps follow, each with the reason it is worth trying, so a person can tell a connection problem from a platform one before anyone else is involved. Retry re-runs the request. Report a Problem opens a real reporter rather than an inert button: it lists exactly what is sent, keeps the screenshot opt-in and unticked, and states plainly that no document, file name or matter content is included. The report goes to the firm's own pipeline, not an outside service.

The error view also scrolls inside its own pane. That ruling had been marked settled off a dialog fix, and the error view is a pane, not a dialog — the cap had never applied to it.

## Public

When something goes wrong in a matter's files, the screen now tells you what happened and what to try. It says up front that your record is unaffected, shows the time and an Error ID you can quote, and offers three things worth checking before you call anyone.

If you do want to report it, Report a Problem shows you exactly what will be sent before you send it — and none of your documents, file names or matter details are included. A screenshot is only attached if you tick the box.
