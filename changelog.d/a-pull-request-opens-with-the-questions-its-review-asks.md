**A pull request now opens with the questions its review asks.** `.github/pull_request_template.md` pre-fills every new pull request with the sections the conventions already require and previously left to memory: what and why, the Conventional Commits type, what reaches production at merge (migration, contract, binding), the documentation lanes with the exact fragment path each one takes, the local `pnpm test` result the 2026-09-03 ruling asks every description to state, and the golden rules a review most often catches late. The template links to `docs/conventions/documentation.md` and `documentation-style.md` for the standards rather than restating them, so it stays a layout and those files stay the home.
