**The fourth surface: a shipment opens in a record window over the register.** `/shipping/[id]` survives as its address and redirects into it, the same shape as a directory record's former address and for the same reason — a record opened in place needs no way back. The route is registered in `STANDING_EXEMPTIONS` as declining a back affordance, beside the directory's, because nothing ever renders there.

`RecordWindow` rather than the modal design's `reading` kind, settling **D4**: a shipment has a history and two acts, and one of them voids a bought label, which is destructive and about money. Tracking is asked for rather than fetched on open — the tracking route is a live carrier call, so a reader clicking through ten rows would otherwise be ten calls nobody asked for — and the tab states when it was last asked, because an event list with no timestamp beside it reads as current forever.

The label is fetched through the generated client and opened as an object URL rather than linked to by address: the contract's paths live in the client, and the bytes are behind the session anyway, so a blob the browser already holds beats a second authenticated navigation a pop-up blocker could lose. Which shipment is open comes from the URL rather than a local variable, so the browser's own back button closes the window — the gesture a reader reaches for whether or not the window offers one.

## Public

**Open any shipment from the list to see it in full** — where it is going, what it cost, which matter it belongs to, and its tracking history. It opens over the list, so closing it puts you back exactly where you were.

Ask the carrier where a parcel is with Check now, and the window tells you when it last asked rather than leaving you to guess how old the answer is. The label can be opened or printed from here, and a label you have not used yet can be voided.

Links to a shipment from anywhere else in the product land on it correctly.
