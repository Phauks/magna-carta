**AcroForm support for `@magna-carta/pdf` — `readForm`, `fillForm`, `flattenForm`:** enumerate interactive form fields, fill values by name, and flatten a form into permanent static page content. The four fillable field types are text, checkbox, radio, and choice (list/combo); push-button and signature fields are enumerated but read-only in this version. Field values are passed as a plain object mapping fully-qualified field names (dot-joined, as returned by `readForm`) to strings (for text/choice/radio) or booleans (for checkboxes). **Generated Helvetica appearances:** the engine writes a real PDF Form XObject appearance for every filled widget, so the rendered value is identical in every viewer without relying on viewer-honoured `/NeedAppearances`. Helvetica is a base-14 standard font; no font file is embedded. **Flatten bakes into content:** when `flatten: true` is set (or `flattenForm` is called), each widget's appearance is drawn into the page via a `Do` operator with a placement transform, page resources are merged non-destructively, widget annotations are removed, and the `/AcroForm` dictionary is dropped — after flattening, `readForm` returns an empty array. **Forms are not redaction.** Filling and flattening write and bake visible field values; they do not remove hidden content, metadata, or other surfaces — use `redactDocument`/`sanitizeDocument` for that. V1 boundaries: Helvetica base-14 appearances only (single-line, no rich text or multiline), no XFA, no digital-signature creation, no `/MK` border styling on generated appearances. Validated by 31 Rust unit tests in `crates/pdf-core` and 3 JS integration tests on the real IRS W-9 AcroForm fixture (fill + flatten round-trip verifies the form is dropped; fill without flatten verifies the form is retained). `(crates/pdf-core, packages/pdf)`
