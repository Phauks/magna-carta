**A newly provisioned firm's bucket accepts browser uploads.** The first production upload failed with "Nothing answered while sending the bytes to storage": the browser PUTs bytes straight to a presigned URL on the firm's own bucket, which is a cross-origin request, and the bucket carried no CORS policy — so the preflight was refused before a byte moved, and the app could only report that nothing answered. Provisioning had never configured CORS; the runbook step that applies it was written for the shared platform bucket, and a firm bucket minted by `firm-provisioner.ts` got neither. `firm-resource-provider.ts` now carries `configureBucketCors`, run unconditionally on every provisioning run that reaches the bucket step alongside the notifications and expiry rules, translating the rule set (now a module beside the code that reads it, `apps/api-worker/src/files/browser-upload-cors.ts`, replacing the checked-in JSON artifact, and naming the `workers.dev` serving origins too) into the REST API's shape and folding in the deployment's `APP_BASE_URL`; `pnpm run emit-r2-cors` prints it as the dashboard's JSON for the by-hand path. Buckets that existed before the step — the platform bucket and the one production firm — still take the policy by hand; the runbook's section 15 now says so, and names the read that tells whether a bucket has one.
