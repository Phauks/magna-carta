**The app Worker carries a `beta` Worker Preview on staging resources, and `docs/deploy-queue.md` carries the owner steps that stand it up.** `apps/api-worker/wrangler.jsonc` gains a `previews` block. A Worker Preview inherits no bindings from the top level, so each storage binding in it names a staging resource: the control-plane D1 `magna-carta-staging-platform-control`, the bucket `magna-carta-staging-platform-files`, a staging status namespace, thirteen `magna-carta-staging-*` producer queues and the `magna-carta-staging-telemetry` dataset. Durable Objects get a fresh namespace per preview. Service bindings reach production siblings, so only the stateless engines are bound; the bundle, edit and status Workers each hold a production binding of their own and are left out. The preview runs without the R2 S3 key pair or the firm provisioner token, so it selects the development adapters, and the control-plane schema is applied on its first request because previews never receive the cron. The D1 and KV identifiers and the beta URL read `SET-BEFORE-FIRST-PREVIEW` until the owner creates the resources. The deploy-queue entry covers creating them, setting preview secrets with `wrangler preview base-config secret put`, gating Workers Builds preview builds to the `beta` branch on `$WORKERS_CI_BRANCH`, and putting the preview behind Cloudflare Access.
