**Firm settings gain their working machinery — drafts, an engraved settings table, an append-only change ledger, and honest permissions.** Settings pages now run on a per-setting definitions registry that mirrors the backend's firm-setting definition shape (kind, options, default, sensitivity, confirm, audited), so the two converge instead of drifting. Every page shares one anatomy: settings render as an **engraved table** — category plates framed by rules with hairline-separated rows, a shared control column, and full-row hover — under a sticky **header band** whose commit rail keeps identical geometry across all three page postures and only changes contents: draft pages carry a permanent staged-count chip (a stable slot that never reflows; it opens a popover listing every staged change and jumps to its row), Cancel, and a Save that takes the gilt only when something is staged; instant pages state "Applies immediately"; read-only pages state "Managed by the firm". A staged row is marked by a full-height gilt bar in a permanent marker gutter with the old value struck through beside the control — the ledger's own strike-and-re-enter grammar — plus an in-row Revert; consequential settings (like turning off retainer floor alerts) get one confirmation per save summarizing the whole batch. Values a member cannot edit render as engraved facts — never greyed dead controls — restricted settings are simply absent rather than locked boxes advertising secrets, and each read-only row reveals its own **Request a change** composer, pre-scoped with the setting's current value and addressed to chosen recipients from the administrators who hold that setting's permission area (filing rides the access-request rails when firm accounts arrive). Every change lands in a per-page **change history** — an append-only ledger in a right-side pull-out where Restore re-applies an old value as a new entry rather than rewriting history (staging on draft pages, applying immediately on instant ones) — and saved values plus the trail sync live across browser tabs. The settings navigation now reads as three levels: identity-plated bands (the member's own settings under their avatar; firm settings under the firm mark with the ledger's double rule of authority), muted group headings, and page rows — with a quiet "view" tag marking firm pages the member can read but not edit. A new CI fitness check enforces the mode-purity invariant: a page never mixes instant-apply and staged controls, read-only sections register no editable settings, and every firm section declares which permission area edits it.
