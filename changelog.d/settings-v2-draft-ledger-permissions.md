**Firm settings gain their working machinery: drafts, a save posture, an append-only change ledger, and honest permissions.** Settings pages now run on a per-setting definitions registry that mirrors the backend's firm-setting definition shape (kind, options, default, sensitivity, confirm, audited), so the two converge instead of drifting. Two demonstration firm pages show every posture live: **Settings · Billing** stages edits through a page draft — the save cluster sits in the page's header band from first paint (rested legend, waking to a staged count with the gilt Save), each staged row shows its old → new values with a one-step Reset to default, and consequential settings (like turning off retainer floor alerts) get one confirmation per save summarizing the whole batch. **Settings · Firm profile** shows the other side of permissions: values a member cannot edit render as engraved facts under one quiet "Managed by your firm administrators" line — never greyed dead controls — restricted settings are simply absent rather than locked boxes advertising secrets, and a **Request a change** composer assembles a paste-ready request (filing rides the access-request rails when firm accounts arrive). Every change lands in a per-page **change history** — an append-only ledger in a right-side pull-out, where Restore re-applies an old value as a new staged entry rather than rewriting history — and saved values plus the trail sync live across browser tabs. A new CI fitness check enforces the mode-purity invariant: a page never mixes instant-apply and staged controls, read-only sections register no editable settings, and every firm section declares which permission area edits it.
