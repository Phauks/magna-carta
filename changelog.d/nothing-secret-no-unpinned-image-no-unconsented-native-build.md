**`lint:secrets`, `lint:containers` and `lint:native-builds` — the supply-chain family this repository had none of.**

There was **no secret scan of any kind**, on a platform that holds firm credentials, the root key that wraps every per-firm data key, and privileged client documents. A credential is compromised the moment it is pushed and stays compromised in the object database after the commit that removes it, so the only cheap moment to catch one is before it lands. Eleven rules over 7,111 tracked files, in-house for the same reason the license gate is: a hosted scanner is handed, by construction, exactly the bytes it is looking for. Findings never print the value. The tree is clean — and `apps/api-worker/.dev.vars` passes because the scan **decodes** its values and finds the placeholder inside, not because its path is allowlisted, so the file stays under the rule forever. The scan does not skip its own directory either: every pattern is written so its own source cannot satisfy it.

The container gate holds the Dockerfile properties that matter for images built here — an explicit tag, never `latest`; no `ADD` from a URL; no disabled certificate verification, in ten spellings; no credential baked into a layer. Two properties are ratchets rather than bans, with the measurement that made them so: **no** base image is digest-pinned (five distinct bases, each recorded with its reason, keyed by image so a new container reusing a known base needs no edit), and **1 of 11** runtime images drops privileges. What it leaves to review is stated rather than implied — whether a pinned hash is the right hash, and the sandbox properties that live in the Containers configuration rather than in a Dockerfile.

The native-build gate gives golden rule 14 a mechanism instead of a habit, across four surfaces: the `onlyBuiltDependencies` grants, the build scripts pnpm has blocked, the platform binaries in the lockfile, and every `-sys`/`cc`/`cmake`/`bindgen` crate in fifteen `Cargo.lock` files. It does not fail on what is already here — a gate that does gets switched off — it fails on what is **new**, and prints everything that is not memory-safe on every run with its language and its consumer. It refuses to pass when it reads nothing: a consent gate that silently scans an empty set is the one failure mode it must not have.

What that surfacing shows is worth reading: clamd is the one consented C engine, and beside it sit `onig_sys` (a C regex engine, in the OCR container's job path), `ort-sys` and `vectorscan-rs-sys` — sandboxed, but with no ruling on record the way clamd has. `openssl-sys` reaches three workspaces only through `ureq`'s `native-tls` default feature, which is a default rather than a decision. And `sharp` — libvips, the one C library the npm graph installs — is not ours: it arrives under miniflare, and so under wrangler and the Workers test pool every worker package carries.
