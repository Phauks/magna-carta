**A transferred record remembers where it came from.** The per-firm database gains `transfer_run` (one run of a record transfer: the source system, the operator's label, who started it, and how it ended) and `source_record_link` (one row tying a record in the source system to the record here that it became). A new package, `@magna-carta/record-transfer`, holds the statement builders and the short list of tables a link may name. Nothing writes to either table yet: this is the foundation the LEAP transfer is built on, and the first piece of it. Design: `docs/specs/2026-11-10-record-transfer-framework-design.md`. It also gains `transfer_source_file`, the facts about each file a run was given, and a reader for delimited text that turns such a file into numbered rows without changing a value. A source file is kept whole in object storage and none of its content is copied into the database. It can now turn a row of such a file into a Directory person or organization: the operator states which column holds which part, a value that cannot be used (an email that is not an address, a date in an unreadable form) is left out and reported with its column, and each record is written through the Directory's own code together with its link, so a second run of the same file creates nothing. A row can also become a matter: it keeps the number the firm already quotes, its opening and closing dates come from the source, its client and parties are linked to the Directory records they became, and it waits, unwritten, while any of those has not yet arrived. A transferred matter requests no conflicts check and sends no notification. One pass over a file now does all of this in order and returns a report that accounts for every row: created, already arrived, rejected with its reason and line, or waiting for another record, with a sample of the records it made for checking by eye.
