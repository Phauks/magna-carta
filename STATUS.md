# Slice Status

Per-slice progress across the build pipeline — the **stage-status home**. [`ROADMAP.md`](ROADMAP.md) owns the narrative scope and ordering; this page tracks _where each slice sits in the pipeline_. Update a cell the moment a slice changes stage (same in-commit discipline as ROADMAP/CHANGELOG).

## Stages

- **Research** — a pre-design research doc in [`docs/research/`](docs/research/) for an under-specified slice (the open subsystems get one before their design cycle). `[-]` where a slice went straight to design.
- **Spec** — a design doc in [`docs/specs/`](docs/specs/).
- **Plan** — an implementation plan in [`docs/specs/`](docs/specs/).
- **Built** — implemented (TDD). **In this workflow the 7-angle adversarial review runs _during_ build**, so Built means implemented-and-reviewed — review is not a separate column.
- **Load profile** — the slice extended the volume harness in-area (the accretion rule, ADR-0078/ADR-0083): its data joined the active profile and its **volume-shaped** operations (cost depends on data shape) joined the measured set. Default-bound for any slice touching per-firm data; `[-]` only where a slice adds no per-firm data surface — justify in Notes. Phase 0 rows are `[-]` (platform/UI slices that predate the rule).
- **Tested** — the separate, independent verification pass run against the _landed_ slice (the dedicated testing pass), distinct from the in-build review.

**Markers:** `[x]` complete · `[~]` in progress · `[ ]` not started · `[-]` not applicable.

**Model attribution.** An untagged completed cell was built and verified by **Fable 5** — the baseline for everything landed to date. When another model does the work, suffix the marker with the full model name and version (e.g. `[x] Opus 4.8`), never an abbreviation — capability shifts between point releases, so the exact version is the fact worth keeping. Append `↻` when the cell still awaits an independent **Fable 5** pass (`[x] Opus 4.8 ↻`); drop it back to a plain `[x]` once Fable 5 has re-confirmed. This is primarily a **Tested**-column signal: Opus-verified work is re-tested on Fable 5 once it is available again. (Model-split rationale lives with the build workflow, not here.)

A trailing **`*`** marks work completed under **Opus during the Fable-access gap** — the same awaited-Fable-pass obligation as `↻`, arising from the gap period rather than a normal Opus build. It is the scan signal for "where do I need to retest with Fable," and clears to a plain `[x]` once Fable re-confirms.
