# Editor worker (`magna-carta-edit`) — CLAUDE.md

**Purpose.** The standalone in-app document editor worker: it owns `DocumentEditorContainer`, one isolated Collabora Online (coolwsd) container per open document, and fronts every request the browser makes to it — the editor page, its assets, and the WebSocket the document rides — from the cookieless content domain. Boundary: this worker routes, proxies and reports; it authorizes nothing, holds no firm data, and never reaches storage. The WOPI host coolwsd calls back to is the app worker's (`apps/api-worker/src/editing/`), reached over a service binding by outbound interception.

**White paper:** _Documents & automation_ / _Delivery model_ — design and rationale live there; do not restate.
**Spec:** [`docs/specs/2026-06-18-slice-2-2-editing-versioning-storage-tiering-design.md`](../../docs/specs/2026-06-18-slice-2-2-editing-versioning-storage-tiering-design.md). **Decisions:** the pending ADRs `collabora-editing-host-topology`, `container-subsystems-extract-to-dedicated-workers`.

## Key files / entry points

- `src/index.ts` — the `ExportedHandler` and the `Bindings` shape. The fetch pipeline in order: the build-identity probe, the document label off the Host, the platform's stylesheet, then under the diagnostics boundary the container's status read and the container fetch with the three rewrites on the way out.
- `src/document-editor-container.ts` — the `Container` class: one coolwsd on 9980, `enableInternet = false`, `sleepAfter`, and `outboundByHost`, which intercepts coolwsd's calls to `WOPI_HOST` and forwards them over `APP_WORKER`. The handler is registered by assignment in a static block, never as a static field (Gotchas).
- `src/document-routing.ts` — `documentKeyFromHost` (the Host's first label, validated against `DOCUMENT_KEY_PATTERN` before it can name a container) and `forwardWopiCallback`. Pure; importable by the node test pool.
- `src/embedding-policy.ts` — adds the app origins to the `frame-ancestors` coolwsd sends, and hands a WebSocket upgrade back untouched. Pure.
- `src/editor-branding.ts` — switches off the editor page's logo field on the way out (the editor hides its logo when that field reads `none`; this image offers no setting for it). Pure; the runtime rewriter is injected.
- `src/editor-stylesheet.ts` — the platform's stylesheet on the editor's origin (served at `/magna-carta/editor.css`, linked into the page's head on the way out): where the host's back button sits on the editor's bar and how its icon is coloured in the dark theme. The editor's page allows styles from its own origin only, which this worker is. Pure; the runtime rewriter is injected.
- `src/editor-about.ts` — the platform's build (this worker's baked-in build identity, which is the deploy's) appended to the editor's About dialog on the way out, after the editor's own version rows. Pure; the runtime rewriter is injected.
- `src/container-phases.ts` — what the editor's container has been doing, for the screen waiting on it: the phase list (`requested`, `started`, `listening`, `served`, `stopped`, `error`) kept in the container object's storage by `DocumentEditorContainer`'s `fetch` override and lifecycle hooks, and the read at `/magna-carta/status` on a document's origin that the app worker's progress route fetches over `EDIT_SERVICE`. The platform gives no sight of coolwsd's own output, so between `started` and `listening` is the boot, shown as exactly that: a gap. Pure; the object reads and writes it.
- `src/diagnostics.ts` — the error boundary: a throw becomes a 500 with `X-MC-Error-Id` and one `error.captured`; an upgrade the container declines is recorded as `operation.failed` naming the status. Pure.
- `wrangler.jsonc` — the wildcard route on the content domain, the container, the Durable Object, the `APP_WORKER` service binding, the `TELEMETRY` dataset.
- `../../containers/collabora/Dockerfile` — the image and the whole of coolwsd's configuration.

## Local conventions

- **Everything testable is pure and lives outside the Container class.** `document-routing.ts`, `embedding-policy.ts` and `diagnostics.ts` import nothing from `cloudflare:workers`, so the suite runs in the default node pool against fakes; coolwsd cannot run locally. Keep new behaviour in a pure module the entrypoint calls, not inline in `fetch`. One test imports the class anyway — `test/document-editor-container.test.ts`, which runs the library's real `ContainerProxy` dispatch to prove the WOPI handler is registered where that proxy reads — and the suite pays for it once, in `vitest.config.ts`: the library is inlined and `cloudflare:workers` is answered by the two-class stub in `test/stubs/`. Nothing else should need the class.
- **coolwsd is configured through `extra_params` and nothing else.** Every setting in the Dockerfile is a `--o:<xmlpath>=<value>` override the image's entrypoint expands onto coolwsd's command line. Not the image's other environment variables (`aliasgroupN`, `username`, `dictionaries`): those are read by coolwsd itself only when the entrypoint passes `--use-env-vars`, and the one this worker needed was read wrongly (Gotchas). One channel, proven in production, so a setting that fails to take effect has one place to be wrong.

## Invariants that apply here

- **This worker is never the gate.** The WOPI access token, re-verified by the app worker on every callback, is the only thing that authorizes a document; a well-formed document label for a document the caller may not read gets them nothing. The label check exists to keep a multi-gigabyte container from booting for an invented Host, not to authorize.
- **Redact by default, and the credential is in every URL.** The browser carries the access token as `?access_token=…` on the page, every asset and the socket, so nothing here logs a URL: the route in an event is the pathname, and the scrubber in `@magna-carta/telemetry` recognises the token's own shapes as the backstop. Golden rule 4 is met by `diagnostics.ts`; a new path that answers the browser goes through it.
- **One container per document, never pooled.** The container is keyed by the document label, which is stable so co-editors converge and opaque so the Host leaks no file id. Untrusted document bytes have no general egress: `enableInternet` stays false and the only reachable host is the intercepted one.
- **An upgrade is handed back, not rebuilt.** The runtime refuses to construct a 101, and a reconstruction drops the `webSocket` the upgrade carries; either breaks every editing session. `embedding-policy.ts` checks for the upgrade before it reads a single header, and nothing added to the response path may reorder that.

## Dependencies & contracts

- **Three literals in three files must agree on the WOPI host:** `WOPI_HOST` in `src/document-editor-container.ts`, `WOPI_HOST` in `apps/api-worker/src/editing/edit-session-route.ts`, and the `storage.wopi.alias_groups` host in the Dockerfile. Change one and change all three in the same commit — a mismatch is either blocked egress or "Unauthorized WOPI host".
- **The document label shape is a contract with the launch:** `DOCUMENT_KEY_PATTERN` here refuses anything but the 52 lowercase hex characters `deriveDocumentKey` mints in the app worker. Same-commit rule.
- Calls: the app worker's `/wopi/files/*` host over `APP_WORKER` (the container's intercepted callbacks). Called by: the browser, on `*.magnacartausercontent.com`; and the app worker's build-identity aggregate, which probes the version route over `EDIT_SERVICE`.
- Writes: the shared `magna-carta-production-telemetry` dataset, beside the WOPI host's events. Nothing else — no R2, no D1, no secrets.

## Gotchas

- **The editor appends a host's buttons after its own, and shows the icon exactly as given.** `Insert_Button` on the tabbed interface lands the button last on the shortcuts bar (`insertBefore` is honoured only by the editor's classic toolbar), and a data: URL icon drawn in black stays black in the editor's dark theme, where the editor's own icons are separate light drawings. Both are corrected by `src/editor-stylesheet.ts` rather than by the message: the bar's row is laid out as a flex line so the host's cell can be ordered first, and the icon is inverted under `html[data-theme='dark']`, the editor's own device for images it cannot redraw. The bar also draws no words for any button (`Control.NotebookbarBuilder.js` sets `noLabelsForUnoButtons`, and the text becomes the `data-cooltip` tooltip), so the matter's number the host sends as the label is drawn beside the arrow by a `::after` rule reading that attribute, cut to `BACK_LABEL_CHARACTERS` with an ellipsis; the editor's own tooltip shows the whole number on hover. The selectors key on `integrator-shortcut`, the class the editor puts on every host button; a rule that stops matching leaves the button where the editor put it.
- **"Unauthorized WOPI host" in the editor is coolwsd's allow-list, and three log lines decide it.** The message renders only after the WebSocket is up and the document load has begun, so it is never the frame and never the socket. In the container's log (the dashboard, this worker's container instance): `Adding trusted WOPI host: [wopi.magna-carta.internal]` at startup means the allow-list took; `Admins did not set the alias_groups mode to 'groups'` means a group was defined under the wrong mode and was discarded; `No acceptable WOPI hosts found matching the target host [...]` is the refusal itself. coolwsd falls back to resolving the host over DNS when the name does not match, which `wopi.magna-carta.internal` can never do by design.
- **The allow-list is the three `storage.wopi.alias_groups` overrides, and the mode must be spelled `storage.wopi.alias_groups[@mode]=groups`.** The image's `aliasgroup1` variable was set, the socket connected, and the host was still refused: that route reads the variable only under `--use-env-vars`, and writes its mode switch to `alias_groups[@mode]` without the `storage.wopi.` prefix the parser reads (upstream `wsd/COOLWSD.cpp` `initializeEnvOptions` against `wsd/HostUtil.cpp` `parseAliases`), leaving a group under the default mode `first`, which the parser refuses outright. The `[0]` in the keys is a bash glob class when the entrypoint expands `${extra_params}` unquoted; it stays literal because nothing in that working directory can match.
- **The editor's welcome dialog is off in the image (`welcome.enable=false`), and it has to be.** The dialog remembers the version it showed in the browser's storage for the editor's ORIGIN, and every document here is its own origin, so it opened on every document a member opened for the first time. Help › What's New still opens it. Telling members the editor changed is the platform's job: the version probe can carry coolwsd's version and the app can say so once per member, which is the follow-up, not a dialog over the document.
- **`security.capabilities` and `mount_jail_tree` are both at the image's defaults (true) as of 2026-09-19, and the server audit is off (`disable_server_audit=true`) as of 2026-09-20.** The first two proved the runtime jails the kit and bind-mounts its files after all (the audit reported both clean). The one line the audit still raised is the hardware warning, which coolwsd sets whenever the kernel shows it fewer than four threads: `standard-4` cleared it and felt no different, so the owner kept `standard-1` and accepted the line, and the audit is off because that line counts as an error and would otherwise put the "Check warnings of your server" snackbar over every open for every member (IsAdminUser is true for all). To diagnose the editor again, take `disable_server_audit` out of `extra_params` for a deploy. The Dockerfile's notes carry each setting's reasoning and revert. These lines exist so that a commit touching the Dockerfile also touches this directory (the next gotcha says why).
- **A Dockerfile-only change may not deploy.** The Workers Builds project for this worker watches `apps/edit-worker/*`; the image lives at `containers/collabora/`. A commit that touches only the Dockerfile can leave the running container on the old image with no build triggered. Until the watch path also names `containers/collabora/*` (a dashboard setting — `docs/conventions/operations.md`), touch something under this directory in the same commit, or trigger the build by hand, and confirm the container rebuilt before reading a symptom as the new image's.
- **`outboundByHost` is assigned in a static block, and a static field silently breaks it.** `Container` declares `outboundByHost` as a static accessor pair whose setter files the handlers in a module-level registry keyed by class name, and that registry is what the library's `ContainerProxy` reads for an intercepted request. Under the class-field semantics this repository compiles to (ES2022), `static outboundByHost = { … }` — the shape the library's README shows — defines an own property that shadows the setter, which never runs. The library then half-works: the host is intercepted (that path reads the property) and the proxy finds no handler (that path reads the registry) and answers 520. In the container log that is `WOPI::CheckFileInfo returned 520 (Unknown) Server Error` followed by `CheckFileInfo failed … State::Fail`; it is the library refusing, not the app worker, which was never reached. `test/document-editor-container.test.ts` holds the registration against the library's own dispatch.
- **The socket's failure is invisible to the browser.** Every failed handshake reads "closed before the connection is established" whatever the server answered, so a container answering 502 and this worker throwing were indistinguishable from outside until `diagnostics.ts` began recording the container's actual status. Read the Error ID and that status from Workers Logs before reasoning from the browser's sentence.
- **`collabora/code:latest` is unpinned, and its source is the `distro/collabora/co-XX.YY` branches of `CollaboraOnline/online`, not `main`** (which holds only CI and packaging). When the image's behaviour needs reading rather than guessing, that branch is the reference; the Dockerfile's own note about pinning a tested digest stands.
- **No local Docker.** `wrangler deploy --dry-run` insists on building the image; pass `--containers-rollout=none` to validate the Worker bundle and its bindings without it. The repo's `build` script does not, because Workers Builds has Docker.
- **The first open of a document is a cold start of a multi-gigabyte image**, and the screen framing it says so for as long as it takes (`apps/web/src/lib/documents/office-document-editor.svelte`). `min_instances` pre-warming is the lever if that wait proves unacceptable; the worker deliberately keeps no warm cron.
