# @magna-carta/status-worker — CLAUDE.md

**Purpose.** A minimal, read-only, unauthenticated Cloudflare Worker that serves the public service-status feed. It reads the shared `STATUS_KV` namespace, merges the three stored documents, and serves them — nothing else. Its entire reason to exist is fate-isolation: it must keep answering "is something out of service?" even when the application Worker, control-plane D1, or a per-firm database is the thing that is down.

**White paper:** _Product updates_ — [`docs/Magna-Carta-White-Paper.md`](../../docs/Magna-Carta-White-Paper.md). **Specs:** [`docs/specs/2026-07-02-service-status-design.md`](../../docs/specs/2026-07-02-service-status-design.md), [`docs/specs/2026-07-09-status-page-history-and-upstream-advisory-design.md`](../../docs/specs/2026-07-09-status-page-history-and-upstream-advisory-design.md).

## Key files / entry points

- `src/index.ts` — the Worker's routes: `GET /api/status.json` (the machine-readable feed), `GET /` (the public status page), `GET /__version` (this worker's own build identity, a read about this worker itself — served `no-store` so a fresh deploy is never misreported from the edge cache), and the two immutable same-origin `/assets` routes (the content-hashed stylesheet and the bundled Atkinson woff2 — the page loads nothing from anywhere else). The feed and the page read `STATUS_KV`, parse the three stored documents (`status:derived`, `status:authored`, `status:history`), and call `mergeSnapshot()` from `@magna-carta/status` with `audience: "public"`.
- `src/render-status-page.ts` — the pure page renderer (snapshot -> HTML string). The page is server-rendered and COMPLETE with zero JavaScript (a meta refresh keeps it current); the inline scripts are progressive enhancement only (countdown, scheme toggle, text-size ladder, the subscribe panel). **Every snapshot-sourced string is HTML-escaped at the sink** — operator and upstream text is untrusted; keep that property for any new interpolation. `src/page-styles.ts` (stylesheet + hashed asset path) and `src/country-dial-codes.ts` (dial codes + the unit-tested phone formatter injected verbatim into the page script) support it.
- `wrangler.jsonc` — the binding set. Read this file before adding anything to it; see "Invariants" below.
- `../worker/src/routes/platform/platform-status.ts` — the sibling write side (a different worker, a different app): the operator-gated endpoints that populate `status:authored`. The cron in `../worker/src/status/derived-snapshot.ts` populates `status:derived` and appends to `status:history`. This worker never writes any of the three keys.
- `../../packages/status/src/` — the shared, pure package both this worker and `apps/api-worker` import: the snapshot schema, the provider registry/adapter, health derivation, the uptime history (`history.ts`), and `mergeSnapshot()`. Any change to merge semantics or the snapshot shape belongs there, not here.

## Local conventions

- This worker serves only the routes above (the feed, the page, and the page's own two assets) and takes no request body. If a task asks for another endpoint here, ask whether it is actually a read that serves this page (belongs here) or a write (belongs in `apps/api-worker`) before adding it.
- Every response path returns `200` or a `4xx` for a malformed request path — never a `5xx`. A KV read failure or a parse failure falls back to `fallbackResponse()` in `src/index.ts`, not a thrown error. Keep new code inside the existing `try`/`catch` shape in `fetch`.
- **Every response carries an explicit `Cache-Control`.** This worker has Workers Cache enabled (`"cache": { "enabled": true }`), and with a cache in front, a response with _no_ directive is cached anyway under RFC 9111 heuristic freshness — a `200` for two hours. So a new route either opts in (`SNAPSHOT_CACHE`, 30s + a stale-while-revalidate window) or opts out (`NEVER_CACHE`, `no-store`). The fallback, the `404`, and the `405` all opt out: a stand-in for a failure must never outlive the failure. Tests in `test/status-worker.test.ts` hold this.

## Invariants that apply here

- **Caching is safe here and nowhere else in this repo.** The edge cache keys on entrypoint + path + query + worker version — not the host, not the `Cookie` header. Every response this worker serves is byte-identical for every reader (no session, no cookie, no per-firm content), so that key fully determines the body. `apps/api-worker` resolves the firm from a session cookie, so caching its default entrypoint would serve one firm's `/api/v1` reply to the next firm requesting the same path; a fitness guard there rejects the `cache` key outright. Do not copy this config across. Reasoning: [`docs/conventions/security.md`](../../docs/conventions/security.md) (response cache-control). Two consequences worth knowing: **purge is scoped to the worker that issues it**, and every writer of this data lives in `apps/api-worker`, so nothing can purge these entries — a published incident becomes visible when the 30-second window lapses (accepted; the responses carry `Cache-Tag`s so a purge route on _this_ worker remains possible later). And `cross_version_cache` stays off, so each deploy starts cold and no superseded version's page can be served.
- **This worker must never gain an app, D1, or per-firm binding.** Its fate-isolation from the application Worker is the entire point of its existence — every other binding this worker could plausibly want (a D1 handle, an R2 bucket, a service binding into `apps/api-worker`) reintroduces exactly the coupling this design exists to avoid. The one binding it may hold is `STATUS_KV` (read-only in practice — this worker never writes to it). Before adding any binding to `wrangler.jsonc`, check whether it is `STATUS_KV`; if it is anything else, stop and reconsider the design instead of wiring it in.
- Reads never leak operator identity: this worker always calls `mergeSnapshot(..., { audience: "public" })`, never `"internal"`. If a future internal view is ever added here (rather than reusing the same public feed from the SPA, which is the current design), it must not default to public audience by accident.
- **An upstream provider's status never sets this platform's verdict.** `overall` is the worst of our own components and our own active events; a troubled provider raises `upstreamAdvisory` on the snapshot, which the page renders as its own quiet surface — never a colored band. A Cloudflare incident is not a Magna Carta outage, and if it becomes one, our own probes are what say so. Do not reintroduce provider status into the rollup.
- **A provider's severity is read from the components we depend on, not its whole-page rollup.** A Statuspage `status.indicator` covers every component the provider publishes, and Cloudflare publishes each edge location as one — several dozen are re-routed at any moment, so that field reads "minor" almost permanently while every service is healthy. `serviceComponentGroups` in `../../packages/status/src/provider-registry.ts` names the groups that matter per provider; the severity is the worst of those components plus any unresolved incident touching them. A scope matching nothing falls back to the page indicator, never to operational — the failure mode of a status page is always the false green.
- **The page never invents a green.** A day with no uptime samples renders as a no-data tick, a component with nothing countable reads "No data" rather than 100%, and an imperfect record is floored at 99.99% rather than rounded up. Any new surface that summarizes health inherits this rule: absence of evidence is not evidence of health.
- **Data encoded in a graphic is also stated in text.** The uptime ticks are `aria-hidden` — ninety announcements per component would be unusable — so the record they carry is written out beside them in an `.offscreen` paragraph, as run-length phrases covering every day in the window (`describeHistoryRuns`). A `title` attribute is a sighted-hover convenience, never the only place a fact lives. Any new graphic that encodes state owes the same text.

## Dependencies & contracts

- Depends on `@magna-carta/status` for the schema, parsing (`parseDerived`/`parseAuthored`/`parseHistory`), and `mergeSnapshot`, plus `@magna-carta/build-identity` for the shared `GET /__version` read the app Worker's version aggregate probes. The second is a deliberate, bounded exception to "nothing else": a pure leaf package (no bindings, no app code, no other dependency), so it adds no coupling that could take this page down with the application. No shared app code from `apps/api-worker` — that part is unchanged and stays so.
- Nothing depends on this worker at **runtime**; it is not imported by, and does not import, `apps/api-worker`. Two arms-length couplings exist and are acceptable because a status-worker outage degrades them, never the reverse: the app Worker probes `/__version` over its `STATUS_SERVICE` service binding (a failed probe reads as "Unreachable" in the version overlay), and — because a service binding must name a worker that exists — the app Worker's **deploy** now requires `magna-carta-status` to exist on the account. Deleting this worker means removing that binding in the same change.

## Gotchas

- **This is a separate deployable with its own Workers Build — it is deliberately not part of `build-all`** (`vp run build-all` in the repo root `vite.config.ts` is scoped to `@magna-carta/api-worker` only, the same posture as `apps/scan-worker`/`apps/bundle-worker`/`apps/convert-worker`). Building or deploying it is its own step; do not assume it rides along with the main app's deploy.
- `apps/api-worker` and this worker share exactly one KV namespace and nothing else. If a change here seems to need data that only `apps/api-worker` has, that is a sign the data belongs in `STATUS_KV` (written by the cron or the operator routes), not a signal to add a binding.
- The `wrangler.jsonc` `STATUS_KV` id binds the real `Magna_Carta_Status` namespace and MUST stay identical to the `STATUS_KV` id in `apps/api-worker/wrangler.jsonc` — both this worker (read side) and `apps/api-worker` (cron/operator write side) bind the one shared namespace. Changing it in one place without the other silently splits the read and write sides.
