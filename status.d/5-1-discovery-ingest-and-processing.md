**Sub-slice 5·1·1 built — the Rust discovery core, the sub-slice with the most unknowns and no Cloudflare, database, or worker in it.** `crates/discovery-core` on the engine-host seam: I/O-free, threadless, dual-target (native + `wasm32`), with a seven-code fixed error set whose own test proves no file content can reach an error payload. **Identification reads bytes and cannot read a name** — `identify` has no parameter a file name could arrive through, so a production's wrong names cannot route anything; comparing the two is a separate call whose answer is reported and never acted on, and a spreadsheet renamed to a picture still identifies as a spreadsheet. A ZIP is refined into the package it actually is (word-processing, workbook, presentation, OpenDocument, or a plain archive) and an OLE2 into the document it actually is (legacy Word/Excel/PowerPoint, an Outlook message, or an encrypted package) from entry names alone, with no decompression. **Normalization is the determinism boundary** — line endings, canonical composition, exotic spacing, and invisible characters all settle before anything derived, and everything derived is derived from its output; **the passage chunker moved out of `packages/search/src/extraction.ts` byte-for-byte**, carrying that suite's own corpus with the expected values copied rather than recomputed, because web and desktop feeding one index must agree about what a document says. Committed cross-target vectors run natively and under `wasm-pack`. Native extractors for text (with charset detection), OOXML (including shared-string resolution, so a workbook yields its words and not its indexes), OpenDocument, RTF, email over `crates/email-core`, and **PDF text layers over `crates/pdf-core` — the born-digital PDF that the shipped extraction port records as unextractable now extracts its real text and is never sent to recognition**. Archives enumerate without decompressing and expand under five guards checked before a byte is retained (depth, total bytes, ratio, entry count, and unconditional path-traversal rejection), with an encrypted entry reported rather than failing its siblings and a too-deep nested archive recorded rather than opened. Hosted by `containers/discovery` + `apps/discovery-worker` on the file-repair container pattern: `enableInternet` false, no `r2` feature, an engine failure a 422 carrying only the stable code. **No C-backed feature on any path**, asserted by a test that reads the crate's own manifest, and a hostile-input sweep runs every fixture through truncation, bit-flips, and absurd declared lengths against every entry point. The custodian-vocabulary gate ships early, scoped to the discovery trees, self-testing so it cannot silently stop biting.

**Sub-slice 5·1·2 built — the review-set model, the object every deferred discovery feature is a function over.** `packages/discovery` plus six per-firm tables in one migration (`20260806T080000_discovery-5-1-2`, journal idx 43). **A review document is a pointer and never a copy**: it names a `file_version` or an `email_message` the firm already holds, so the internal lanes move no bytes, re-read none, and reuse the hash computed at ingest and the scan verdict already recorded — and it pins the VERSION, so a file that gains a new version does not silently change a corpus already certified. **The vocabulary is mechanical**: `recordCustodian` / `record_custodian` / "record custodian", two words everywhere, with the shipped gate now biting on this package's own prose; record custodians are review-set-scoped because the same name in two matters is not assertably the same person. **The transcript control is a required field with no default in either direction** — every load declares `transcript_scope`, the column is `NOT NULL` with no default, an omission is refused, and `include` is refused BY NAME until the lane that reaches transcripts exists, because silently dropping it would produce a corpus that does not match its declaration and honouring it in name would produce a manifest claiming a sweep that never happened. **Three state machines are triggers, not conventions**: a review set moves open → locked → closed and a reopen aborts at the database; a load moves declared → loading → processing → complete, fails only before completing, and is reversed only once complete; a document leaves a terminal processing state only by an explicit reset to `pending`, so it can never flip between `processed` and `excepted`. **The reconciliation is a row CHECK** — a load cannot reach `complete` while loaded ≠ processed + excepted. **The ceiling is refused at declaration** with the count and the ceiling in the message. **Discovery is its own permission namespace** (`discovery:read` / `:manageReviewSets` / `:load`), which IS the access rule: a member holding every `matters:*` and `files:*` grant on the matter reaches no review set on it, proven by a route test. The `DiscoveryLoadCoordinator` holds its cursor in durable storage and nothing on the instance, so an eviction mid-fan-out resumes where the load actually got to; email enters as a family; a quarantined version is refused by name rather than skipped.

Settled by the build and recorded: the per-review-set access LIST the design recommended is named for the review surface rather than built (a list nothing renders is a list nothing enforces); the occurrence columns are `primary_review_document_id` + `duplicate_review_document_id`; and the platform-wide widening of the custodian-vocabulary gate that the tool's own comment scheduled for this slice is refused as written and the comment corrected — the shipped Custodian register legitimately owns the bare word as its subsystem name, its package specifier, and its route.

Not built here and named: processing — the queue lane, the composite extraction port, deduplication and occurrences, the exception table and the manifest (5·1·3) — and corpus indexing, the review-document list read, and the load profile (5·1·4). No user-facing surface exists yet, which is why UI is not applicable rather than deferred; the load profile is likewise 5·1·4's, which is why it stays `todo` while the model it measures is built.

**Sub-slice 5·1·3 part-built — the processing lane and the composite extraction port, which is the wire between the two halves that had already shipped.** `DISCOVERY_PROCESS` is its own queue with its own dead-letter queue at concurrency 4, apart from every ingest lane, because a load at the ceiling is a quarter of a million documents and the alternative is a firm's interactive uploads queued behind an opposing party's production. Dispatch is a keyset-paged walk off the load coordinator's durable cursor — resumable across an eviction or a deploy, safe to run twice because it selects only what is still `pending` — and it starts only once allocation is complete, so the reconciliation a load completes against is never counted against a corpus that is still growing. **The extraction port is composite for real now**: the pure-Rust engine reads natively (PDF text layers, OOXML, OpenDocument, RTF, email, plain text — identified from the bytes, never the file name), recognition is asked only about pages the engine reports as pixels, and a 1997 binary office file goes through the consented office container so the CONVERSION can be read by the memory-safe engine — the parser that touches an opposing party's bytes stays pure Rust even for a format no pure-Rust parser exists for, and the identified format on the record stays the legacy one. When the engine service is unbound the shipped in-Worker PDF reader plus recognition still runs, unchanged.

**Every extraction records its ROUTE**, which is the fact the corpus could not previously state and the reason the born-digital-PDF defect was invisible until somebody read the code: `review_document.extraction_route` names the engines in the order they ran, `pages_recognized` counts how many pages are a machine's reading of a picture rather than the author's characters, and the per-page provenance goes to the R2 sidecar. **A disposition and a diagnosis are two fields**: the port keeps its three reasons (park, terminal, retry) because the pipeline does three things, and gains a separate `code` carrying the engine's own stable string, mapped to the closed exception vocabulary by a table proved TOTAL against the port's own export rather than a copy. A refusal code the router does not recognize is treated as transient rather than filed under the nearest name — an unnamed reason means the engine and the worker are at different versions, and inventing a sentence for a report nobody checked is worse than retrying. **A document an undeployed engine has not read is `pending` with `processing_deferred_reason` on the row, not `excepted`**: the two terminal states stay two, and neither of them means "we have not got to it". Bulk stays out of the database — text and sidecar to R2, pointers on the row — and a quarantined version is refused from the version's recorded status without a parser ever being handed the bytes.

**Measured rather than asserted**, at the standard 25,000-document review-set volume on a migrated node-sqlite per-firm database (machine-relative, this box): the mid-walk dispatch page 0.231 ms median / 0.321 ms p95; the whole-load reconciliation tally 3.266 / 3.327; the exception report's counts-by-code 0.157 / 0.186; the parked-document count 0.468 / 0.494; the per-document claim-and-process write pair 0.101 / 0.333. Every volume-shaped read walks an index and the dispatch walk sorts from one — the reconciliation is allowlisted as a whole-load aggregate, which is what it is. **The database after 25,000 review documents and their pointed-at file rows is 44 MiB**, which extrapolates to roughly 440 MiB at the 250,000 ceiling — the arithmetic the ceiling was derived from, now re-derived against a measurement.

Also settled: the conversion registry gains `doc`/`xls`/`ppt` as sources and `xlsx`/`pptx` as targets with office edges onward to PDF, which is what routing a legacy binary through the one home for conversion actually requires and which makes those files convertible in the file-converter tool too; two new object classes for the derived text and sidecar; and a firm with no provisioned bucket parks its dispatch by name rather than failing the load that committed correctly.

Not built here and named: deduplication and occurrence rows, container families over the guarded archive expansion the engine already has, and the manifest and exception report written at load completion — the rest of 5·1·3. The discovery volume in the SHARED load profile is deliberately not added: the corpus is an order of magnitude larger than everything else in a firm's database and folding it into the shared generator would change every other domain's baseline identity for a table none of them read, so the processing measurements seed their own volume on the email-filing precedent and the shared volume lands with the review-document list read in 5·1·4.

**Sub-slice 5·1·3 finished — deduplication with occurrence rows, container families, and the two record artifacts a firm hands to another party.**

**The exception report is the piece the slice was worth doing for.** A production is a claim — _we produced everything we could read_ — and without a document the claim is an assertion. The report names every item the claim excludes and gives the reason for each, from the closed vocabulary in which every code is a different sentence to a court: `encrypted` and `password-protected` stay apart because a password can be asked for and a key cannot, and `no-text-extracted` is on the list precisely so a document that yields nothing is listed rather than indexed as empty. It is written per load in a machine-readable and a printable form, alongside a manifest of what arrived, and **only once the load reconciles** — and reconciliation is checked twice, once against the counters the consumer advanced relatively and once by counting the rows themselves, because a report reconciled against the number it was drawn from would reconcile with anything.

**Both artifacts are REPRODUCIBLE, and that is a property of the generator rather than a habit.** The renderers are pure — no binding, no bucket, no database, and no clock. The knowledge instant is an argument, and it is the load row's `updated_at`: the moment its last counter moved, which is the moment the corpus stopped moving for that load. Nothing advances it afterwards, so a second run reads the same instant and renders the same header; taking `now` would make every rebuild a different document, which is the difference between a record and a snapshot. Every set arrives keyset-ordered by identifier, nothing is derived from the environment, and the keys are derived so a retry overwrites its own object with the same bytes. A test renders twice and compares; a source scan fails the module on a clock. The manifest is streamed into R2 in fixed multipart parts rather than assembled in memory, because a load at the ceiling is a quarter of a million document entries.

**Deduplication decides what a reviewer never sees, so it is built to be inspectable.** The identity is the content hash the ingest gate already recorded, or the email record model's own dedup key for a message — **never the near-duplicate fingerprint on the same row**, which collides by design and would be suppressing a document from review on a heuristic; clustering over it is the review slice's job and it shows documents rather than hiding them. A document with no recorded hash gets no group at all rather than a group of one. Primacy is taken by ONE guarded statement (`WHERE NOT EXISTS` a holder) and held by a partial unique index, so a group can never have two primaries; a copy that finds a holder that has not finished parks and throws, and the queue brings it back one redelivery later because dispatch walks in identifier order. **The duplicate row survives** with its own custodian, its own load and its own terminal state, pointing at the primary's text object rather than a second copy of it, and inheriting the primary's named codes on its own row when the primary is one nothing could read — so the custodian who held an encrypted document is counted as having held one. An occurrence row makes every suppressed copy reachable from the copy a reviewer opens, and "which custodians held this document" is one indexed read.

**A container family is a chain-of-custody claim.** An archive is expanded by the engine under its five existing guards — nothing here second-guesses them — and every entry re-enters the ordinary ingest gate by the same path an email attachment takes: presigned session, magic-byte sniff, content hash, malware scan. There is no discovery bypass and no second way to put bytes in a firm's bucket. Entries are sorted by path before they are numbered, so a re-processing gives the same entry the same family sequence; the archive becomes the family head, `processed` with **no text object** (an empty text object for a container would assert it holds no words, which is the assertion the exception vocabulary exists to avoid) and an entry listing in its sidecar. Entries the engine described rather than opened become one exception per KIND carrying a count and a kind and **never a path** — a path inside an opposing party's production is free text somebody writes a name into. Expansion is one level per document, absolutely and not by counting: the engine already recursed to its own nesting ceiling, so a child that is itself a container is one it declined to open and it says so.

**Found and fixed:** a document waiting on the scan gate parked and was acked, so nothing would ever look again — it now re-reads the row and throws so the queue redelivers, which is what a container's children need since their bytes cross the gate after their message exists. A `quarantined` verdict is deliberately never re-read: the two failure directions are not symmetrical.

Also settled: the extraction facts gain the digest set the engine already computed in the same pass, so MD5 and SHA-1 reach the row (SHA-256 stays the ingest gate's value — two authorities on whether two documents are the same document is one too many), and a legacy binary keeps the digests of the bytes that arrived rather than of the conversion made to read them; the exception row gains its load so the report walks its own index; the lane's message becomes a two-kind union with the absent `kind` still reading as a document, so messages in flight across a deploy still route; and the record artifacts carry a `review-load-record` object class, stamped apart from the derived text and sidecars so a collection rule cannot delete the evidence and keep the cache.

**Three deviations from the design, recorded rather than silently taken:** the manifest carries three digests rather than five (the shipped row has three columns, and no load-file specification asks for SHA-384 or SHA-512); engine VERSION pinning is replaced by the extraction routes the corpus itself observed, because no engine reports a version over its service binding today and inventing one would be worse than omitting it; and an exception row may sit on a document whose terminal state is `processed`, which is what a container with encrypted entries actually is — the report renders the state beside every reason rather than an advisory-code list being invented.

Not built here and named: the review-document index enqueue into the review-set corpus, opt-in semantic indexing, the review-document list read, and the discovery volume in the shared load profile — all 5·1·4. No review surface; the user guide for the exception report is authored ahead of the screens, as the review-set guide already is.
