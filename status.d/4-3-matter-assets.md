Slice 4·3·1 built: the register core, on the design's recommended defaults for every owner flag. **Eight per-firm tables** — the asset row anchored `NOT NULL` to one matter, the per-firm type catalog under a closed ten-value platform class, the real-property and financial-account attribute tables, the append-only valuation history, interests, the document link, and the sealed identifier — plus two permissions, thirteen seeded catalog entries, the firm's starting interest-label list, and **seventeen routes**. An asset row is **one matter's assertion**: there is deliberately no cross-matter thing identity, because the same house in a divorce and in an estate has different dates, values, encumbrances, and privilege, and a shared row would have to reconcile them. **Two fields make a row** (a class and a description) — the deliberate inversion of Custodian's mandatory owner link, because here the catastrophe is a register nobody fills in — and a valuation and the class attributes ride the create call, with a bounded bulk route in the first slice rather than deferred. **A valuation is appended, never updated and never deleted, and no current-value column exists on any table**: enforced by the custody ledger's three `RAISE(ABORT)` triggers (update, delete, and the replace guard that catches an `INSERT OR REPLACE`), by a source scan over the package, and by a `PRAGMA`-walking test that no asset table carries an undated value column. A correction is a compensating row naming the row it corrects, which supersedes it in every read while both stay on the record. The **as-of read returns amount, date, and basis as one object** so a value cannot be rendered without the date it speaks to, and **a date before an asset's first valuation resolves to nothing** rather than to the earliest figure — proven as a table, alongside exactly-on, between-two, and corrected-row-never-resolves. **The class is frozen at creation** and the patch schema accepts the field so a caller naming it gets an explainable refusal rather than a silent strip. **Documents are many-to-many** and deliberately diverge from `custody_scan`'s unique file index — one brokerage statement lists four accounts — and no byte reaches an asset route: the File Manager's presigned-upload and quarantine chokepoint is the only ingest, and a file filed under another matter is refused. **Identifiers split by what they are**: a parcel number is public record and stays a plaintext searchable column, while a full account, policy, certificate, or tax number is a registered protected column reachable only through the existing `readProtected` chokepoint — permission-gated, audited before any plaintext, with every list, detail, and report projecting the four-character suffix on a row shape that carries no field a full value could ride on, and a named refusal rather than a blank when the decrypt permission is absent. **No credential is storable anywhere**: a password, passphrase, seed or recovery phrase, private key, personal identification number, or safe combination is refused BY NAME before anything is sealed, with its own problem type whose message names the custody register as the correct home. The class registry carries the firearm handling notice now, standing and non-jurisdictional, guarded by a test asserting it names no jurisdiction, cites no statute, and carries no numeral; nothing branches on it.

Deliberately not built and named as seams: the six remaining attribute tables and their classes (declared in the registry and refused by name with "arrives in 4·3·2"), encumbrances and net equity (`matter_asset_valuation.encumbrance_id` lands now because adding it later means rebuilding a table whose triggers have to be dropped to do it), the grouped estate schedule, the custody item link coming into use, the asset merge subjects and the one new assembly source, the firm's own fields on an asset, carry-forward from a prior matter, the parcel and valuation integration adapters, and portal visibility. The load-profile asset corpus and the as-of schedule measurement are the next thing after 4·3·2.

Slices 4·3·2 and 4·3·3 built (reconciled against the plan: the protected identifier and the firearm handling notice landed EARLY in 4·3·1, so 4·3·2's remainder was the attribute tables, encumbrances, and the schedule). **Seven new per-firm tables** — the six remaining one-to-one attribute tables and `matter_asset_encumbrance` — plus one additive index on the valuation history and twenty-six seeded catalog entries, taking the register to **every one of its ten classes**. The line between a public-record identifier and a credential-adjacent secret now has its sharpest cases on both sides: a vehicle identification number, a plate, and a firearm serial are plaintext and indexed because searching by them is the point, while `matter_asset_digital_asset` has **no column a credential could ride on at all** and the write path refuses one by name. A firearm's `regulated_category` is free text a person asserted and is read by nothing — no code classifies an item, determines a recipient, or produces a deadline. **An encumbrance's balance is a valuation row naming it**, so one append-only table, one trigger set, one as-of query shape, and net equity as one read with a sign flip — and the write path refuses a balance naming a charge on a different asset, because that makes the equity of two assets wrong with neither looking wrong. **Equity is computed and never stored, and withheld rather than approximated**: an unrecorded balance makes it unavailable rather than nil (which would overstate exactly the assets a firm must be careful about) and a mixed-currency pair nets to nothing at all; negative equity is reported as negative, because a house worth less than its mortgage is the ordinary condition of many estates. **The schedule** groups by class as of a required, never-defaulted date, subtotals per class per currency, states the unvalued count rather than hiding it, keeps `undetermined` as its own group, and withholds a group's equity subtotal when one balance in it is unstated — five batched reads for a whole matter, never one per asset. **The custody link comes into use**: set and cleared through the patch route against an item the write path proves exists, with the asset detail composing location, status, and hold state by READING Custodian at request time and storing none of it; a source scan in both directions holds the boundary, refusing any mention of `declared_value_*` in the package and any write into a custody table. **Eleven merge subjects on ONE new source**, collection-only by construction: no `assetClass` subject declares a scalar (an estate with two houses would make every scalar an absence naming the count), `value` and `valueAsOf` are declared and set together or not at all, `accountSuffix` is the facet and the full number has no key, and a manifest naming all eleven issues exactly the one read a manifest naming one issues — the a-subject-costs-nothing property, holding on the first outside subsystem to join the catalogue.

Still not built after 4·3·3: `custom_field.target` widening to `matterAsset` (deferred deliberately — it is the custom-fields engine's migration and wants coordinating with the Custodian `custodyPacket` widening so both values land in one), the starter schedule template in the document-automation starter content, the load-profile asset corpus and the as-of schedule measurement, carry-forward from a prior matter, the parcel and valuation integration adapters, and portal visibility.
