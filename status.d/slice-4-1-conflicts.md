No-scorer evidence-tier engine; typed source registry + firm floor; three append-only log tables. Firm personnel resolved as a source, not a Directory node type. Deepening slice 1 adds the reporting posture: one derived per-matter read, an honest zero-hit report, and a vocabulary fitness function — the platform reports what it searched and never concludes. Slice 2 makes the check fire when the corpus moves: one outbox row on each producing write path, the `conflicts_recheck_request` ledger (partial unique index on the open rows, immutable cause, one-way satisfaction, never deleted), separate request and run consumers, a cron drain plus a scheduled re-scan, and `conflicts.hit.surfaced` carrying counts only. The automated path cannot dispose of anything, and two source scans prove it. Slice 3 makes the graph half of search depth real: traversal is budgeted per edge class rather than by one integer (corporate family transitive at no hop cost; control, family and representation one hop each by default), bounded by a per-run closure cap, and both are firm settings recorded verbatim on the check row. Reaching the cap stops the walk and the check records that it was TRUNCATED with the frontier it did not reach — a truncated expansion is never reported as a completed one, the depth analogue of `unavailable` never reading as searched and clean. Degree-based hub suppression is refused and the refusal is held by a test; expired edges are traversed with the expiry on the path step. The N+1 goes in the same change: one subject-facts read per node table over the closure, one batched edge read per traversal round, each blocking channel once over the closure — gated by an equivalence test proving the batched matcher returns exactly the per-entity matcher's hit set over a real corpus. A follow-on pass adds the SECOND bound the traversal slice's measurement asked for: a corpus sweep with the closure pinned shows candidates rising linearly with the Directory (about six tenths of the organization corpus per organization subject, a tenth of the person corpus per person subject, ~99% of it trigram overlap with no other signal), so `candidateCap` now bounds what a run WRITES beside the cap on how far it walks — strongest evidence kept, a co-party surfacing never refused, the refusal recorded per evidence tier and stated in the report, and the bound applied outside both matchers so the equivalence proof stays a proof about the whole answer. Slice 4 closes the ORGANIZATION half of matching depth: two derived keys beside the frozen normalization (`normalized_match_key` at tier 2 for one name spelled two ways, `normalized_match_key_bare` at tier 3 for the same name under a different legal form), and the nickname catalogue shipped empty so every check records the dimension as one it could not search. The keys are computed inside `insertNameStatement` so none of the eight name-writing paths can omit them, filled for existing corpora by a resumable budgeted sweep on the daily cron with no stored cursor, and audited by a fitness probe. The PERSON half — Beider-Morse for cross-origin surnames — was built and then removed on measurement: the only maintained pure-TypeScript encoder (MIT, zero runtime dependencies, so golden rule 14 never applied) compiles its rule tables in 20,377 ms inside workerd against 16 ms in Node, which is past the Workers CPU limit on both the write and the read path, and a lazy dynamic import is worse because Workers forbid runtime module loading. The recall it would buy is measured and recorded (seven cross-origin pairs in thirty that Double Metaphone structurally cannot reach), and the follow-on carries that number as its flip condition. The design's claim that the encoder was additive rows on `directory_name_phonetic_code` is also false and is corrected in the schema: that table's primary key is (name_id, scheme), so it holds one code per name per scheme and cannot hold a variable set. Name-role breadth becomes an explicit firm setting recorded verbatim on the check row beside the name keys compared and the phonetic schemes that ran, shipping the design's recommended default (current, former, maiden, alias) so a married-name change is found at the default band and answering owner flag F1 is a settings edit rather than a release. The load-profile smoke test asserts each new channel actually found something against the real corpus, because a channel that finds nothing reads as coverage and is worse than no channel at all.
