# @magna-carta/custom-fields — CLAUDE.md

**Purpose.** The firm's typed extra-attributes engine — a typed entity-attribute-value (EAV) store that lets a firm define its own fields on matter types, entity (directory contact) categories, and matter-asset classes, set temporal values on individual records, retype a field without data loss, and govern a field's lifecycle (archive, hard-delete, compliance purge). Validates in memory and composes statements into `@magna-carta/data-access`'s effect batch; holds no D1 binding and performs no I/O of its own. The reference, picklist, and merge integrations reach into matters and the directory, but no business query crosses firms — every read and write rides the firm-scoped per-firm database the route hands in.

**White paper:** _Core domain_ — [`docs/Magna-Carta-White-Paper.md`](../../docs/Magna-Carta-White-Paper.md). (Design and rationale live there; do not restate.)

## Key files / entry points

- `src/types.ts` — `CUSTOM_FIELD_KINDS` (the twelve kinds), `CUSTOM_FIELD_TARGETS` + `CustomFieldTarget` (`matter` | `entity` | `matterAsset` — the three record axes), `CustomFieldError` + its `CustomFieldErrorCode` union (the single source the route maps to RFC 9457 problems by code).
- `src/custom-field-service.ts` — define / rename / set-required / reorder / archive / unarchive / hard-delete a field. `defineCustomField` enforces the per-scope and per-firm field caps; `hardDeleteCustomField` refuses (`field-in-use`) when any value rows exist, **or when a registered document template binds the field as a merge field** — the binding shows as the key `custom.<handle>` inside a stored `document_template_version` field manifest, and the table is named by string (this package imports no other domain package, the same discipline `@magna-carta/directory` follows for `custom_field_value`). Both arms route the administrator to Archive, where a bound field resolves as a reported absence rather than leaving templates naming a handle nobody can look up. The manifest scan is deliberate: it runs on a rare administrative action, never on a read or write path, and the alternative — a bindings table maintained alongside every registration — is a second copy of a fact the manifest already states, with its own way of going stale.
- `src/picklist-option-service.ts` — create / rename / reorder / archive / hard-delete a picklist option (option-level mirror of the field lifecycle; `option-in-use` guards the hard-delete).
- `src/custom-field-value-service.ts` — `setCustomFieldValue` / `clearCustomFieldValue` (append-and-flip), and `CustomFieldValueInput` (the tagged value union threaded through values, Convert, and the route). `setCustomFieldValue` reads the field's definition up front and enforces it (kind agreement, archived refusal, picklist membership, whole minor units, the per-value text ceiling); `columnsFor` validates a reference handle before any write.
- `src/number-scale.ts` — `effectiveNumberScale` (what a field's stored integers mean) plus the exact decimal↔integer helpers every scaling path shares. THE home of the scale rule; the route imports it so the boundary and the domain cannot drift.
- `src/coercion.ts` — `classifyCoercion` (pure: clean / needs-rule / parked) + `coerceWithRule`; the per-value classifier Convert preview and apply both run. Both take the minor-unit exponents of the two sides — a numeric coercion cannot be classified without stating what its digits mean.
- `src/convert.ts` — `previewConvert` (counts, no write) and `applyConvert` (non-destructive retype: every original row flips to history, clean values gain a coerced current row, parked values are left cleared). `CONVERT_INLINE_VALUE_LIMIT` is the inline-vs-Queue threshold.
- `src/reads.ts` — `resolveCustomField` (handle → definition, active/archived/absent), `readCurrentValues` (a record's current values), `readCustomFieldValuesForScope` (every ACTIVE field a `(target, attachment_id)` scope offers, left-joined to one record's current value — one read whatever the field count, and the read the asset detail composes), `readValueHistory` (one field on one record, oldest first).
- `src/purge.ts` — `purgeCustomField`, the compliance-erasure seam (refuses with `purge-not-yet-enabled` until the executing pass is built).
- `src/limits.ts` — `MAX_FIELDS_PER_SCOPE` / `MAX_FIELDS_PER_FIRM` / `MAX_OPTIONS_PER_FIELD` (load-profile-calibrated caps), `MAX_VALUE_TEXT_LENGTH` (the per-value anti-bloat ceiling), `MAX_NUMBER_SCALE` (the widest declarable minor-unit exponent).
- `src/audit.ts` — `customFieldAuditStatement` (the shared write-options type + audit-row builder every write path emits).
- `src/run-custom-field-effect.ts` — `runCustomFieldEffect` (the top-level idempotent executor; `CustomFieldWriteOptions`; `CustomFieldIdempotencyConflictError`).
- `src/*-statements.ts` — the SQL statement builders for the atomic batch (field, value, option).
- `src/fitness.ts` — `assertCustomFieldFitness` + per-invariant probe queries.

Schema home: `packages/database/drizzle/per-firm/0013_custom-fields.sql` (the `custom_field`, `picklist_option`, `custom_field_value` tables, the one-value CHECK, and the one-current partial unique index). HTTP surface: `apps/api-worker/src/http/routes/firm/custom-fields.ts`.

## Local conventions

- **The target vocabulary has ONE home and no CHECK behind it.** `CUSTOM_FIELD_TARGETS` in `src/types.ts` is it; the drizzle column's `enum`, the define-field request schema, and every scoped read derive from it, and `test/schema-name-sync.test.ts` pins the column's `enumValues` to the constant. Widening it takes **no migration** — `custom_field.target` is a bare `text NOT NULL` and drizzle's `enum` option emits no SQL — so nothing at the database refuses an unrecognised target and the only thing standing between a firm and a field that can never be used is the set of readers that filter on it. Add a target and walk the readers: the merge catalogue's `target = 'matter'` filter (`@magna-carta/document-assembly/src/custom-field-statements.ts`), `readCustomFieldValuesForScope`, and whatever composes the new axis's detail.
- **`attachment_id` means a different thing on each target and is validated on none.** A matter type, a directory category, an asset class. The engine has never known what is on the other side of that handle, and it must not learn — checking would mean importing the three domain packages that import this one.
- **Handle identity, never name.** A value binds to a field by its `customField_` handle, not its name — so renaming a field never breaks a stored value. Resolve and read paths key on the id; only the display name changes on a rename.
- **Append-and-flip value history.** A value is never edited in place. `setCustomFieldValue` flips the prior current row to history (`is_current = 0`, `valid_to = now`) and inserts a new current row in the same batch; `clearCustomFieldValue` flips the current row to history and inserts nothing. A field's full history endures, so Convert and clear are reversible and nothing the user entered is lost.
- **Currency/number scaling happens at the route, not in the service.** `value_number` stores an integer in minor units. The route (`valueInputForWrite` in `apps/api-worker/src/http/routes/firm/custom-fields.ts`) scales the inbound decimal by 10^scale before it reaches the value service, using this package's `effectiveNumberScale` so both ends read a field's scale the same way (a currency field with no explicit `number_scale` falls back to the money minor-unit scale). The domain package only ever sees and stores the already-scaled integer — do not re-scale here; `setCustomFieldValue` **validates** what arrives (a fractional value is `value-not-a-scaled-integer`) and never multiplies it.
- **What a stored integer means is `kind` + `number_scale`, and every kind boundary has to say so.** The same `500` is five hundred on a number field and $5.00 on a currency field. Convert therefore re-expresses values at the target kind's scale (`conversionScale` in `convert.ts` feeds `classifyCoercion`), and a re-expression that cannot be made exactly **parks** rather than rounds. All the arithmetic is integer-and-string (decimal-point moves in `number-scale.ts`) — never a float multiply, in either direction.
- **A retype does not rewrite `number_scale`.** The column records what the admin declared; the effective scale is derived from it under the current kind. Pinning the computed exponent onto the column would leave a field retyped currency → number → currency declaring a scale of zero — a money field that can no longer hold cents.
- **The merge `archive-to-history` collision rule lives in `@magna-carta/directory`, not here.** When two contacts merge, the directory's `mergeEntities` repoints both kinds of custom-field reference: a value that POINTS AT the subordinate (`value_reference_id` → master) and a value OWNED BY the subordinate (`target_row_id` → master). The owned-value repoint uses `onCollision: "archive-to-history"` — if the master already holds a current value of the same field, the subordinate's value is moved onto the master and flipped to history (field-level survivorship) rather than discarded. That logic is in `packages/directory/src/merge.ts`'s `REPOINT_TARGETS`; this package owns only the table shape it operates on.

## Invariants that apply here

- **Exactly one value column is non-null.** `custom_field_value` carries a CHECK that exactly one of `value_text` / `value_number` / `value_date` / `value_option_id` / `value_reference_id` is set. `columnsFor` / `columnsFromCoerced` build the row by populating one column over an all-null base — never widen this to a free-form map.
- **One current value per (record, field).** The partial unique index `(target_row_id, field_id) WHERE is_current = 1` enforces a single live value. Every write that adds a current row must flip the prior one first (`flipCurrentValueStatement`), or the insert collides.
- **No floats in stored values.** `value_number` is an `integer` column holding minor units; the decimal-to-integer scaling is the route's job (see Local conventions). The service and statements never store a fractional number — `setCustomFieldValue` refuses one, and every coercion produces its integer by moving a decimal point, never by multiplying.
- **A value write is checked against its field's definition.** `setCustomFieldValue` reads the field before composing anything and refuses what the definition rules out: `unknown-field` (no such field → 404), `field-archived`, `value-kind-mismatch` (the value shape, the reference kind, or a checkbox that is neither 0 nor 1), `value-not-a-scaled-integer`, `value-text-too-long`, `unknown-picklist-option` (absent or another field's), `picklist-option-archived`. Never add a write path that skips this read.
- **Reference handle validation.** A `contact-reference` value must carry a `directoryPerson_`/`directoryOrganization_` handle and a `matter-reference` a `matter_` handle; `columnsFor` throws `reference-kind-handle-mismatch` (→ 422 at the route) before any write when the handle does not match the declared kind.
- **All writes compose the atomic batch and emit an audit row.** Every mutation goes through `runCustomFieldEffect` (idempotent) and pushes a `customFieldAuditStatement` into the same batch — never raw D1 outside a statement builder, never a write without its audit row.
- **Firm-scoped data access.** The route hands the service the firm-scoped per-firm database; no query in this package crosses firms.

## Dependencies & contracts

- Depends on: `@magna-carta/data-access` (effect batches, idempotency, audit statements), `@magna-carta/database` (the per-firm `0012` schema), `@magna-carta/identifiers`, `@magna-carta/money` (the minor-unit scale the currency default mirrors).
- Pure and synchronous per operation: produces statements for the caller to run; holds no D1 binding and performs no I/O of its own.
- Callers: `apps/api-worker/src/http/routes/firm/custom-fields.ts` is the only caller of the services and `runCustomFieldEffect` — it owns threading `env`, the actor, the clock, the crypto random source, and the idempotency context, and maps `CustomFieldError.code` to problems. `packages/directory/src/merge.ts` reads and repoints `custom_field_value` rows directly during a contact merge (the only cross-package writer of this table).

## Gotchas

- **The Convert confirmed-rule path is a forward seam.** `classifyCoercion` returns `needs-rule` for values that need an admin-confirmed coercion (a magnitude suffix, or a text-to-picklist option creation), and `coerceWithRule` can resolve them — but `applyConvert` does not yet thread a confirmed rule, so today a `needs-rule` value is treated like a parked value (its original moves to history, no new current row). Wiring the confirmed-rule UI + apply path is the slice that builds the Convert review screen.
- **Bulk Convert offload is a forward seam.** `applyConvert` runs inline in one effect batch and now **refuses** (`convert-too-many-values`) a field holding more than `CONVERT_INLINE_VALUE_LIMIT` (500) current values, rather than composing a batch of tens of thousands of statements. That ceiling is where the Queue-driven background pass (which also sets `converting = 1`) takes over once it is built; the preview stays a plain read and still answers above the limit. Re-derive the limit against the load profile, never raise it on a guess.
- **The concurrent-write window during a Convert is still open.** `converting` is never set, so a value written between the load and the commit can be clobbered or survive in the old kind's column. Closing it is part of the same background-pass work.
- **Reference kinds are not convertible, in either direction.** Preview and apply both refuse `reference-kind-not-convertible` before loading a value, so the answer does not depend on how many values the field holds.
- **D1 has no interactive transactions.** Everything an operation needs must be read before composing the batch (the field definition reads in `convert.ts` and `custom-field-value-service.ts` happen up front); never plan logic "between" statements.
- **`required` is advisory at the data layer.** Setting a field required does not block a value-less record write in this package — form-level required enforcement is the UI's job; the column records the intent.
